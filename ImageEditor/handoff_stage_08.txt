================================================================================
1. RESUMO DA ETAPA
================================================================================

Esta etapa implementou o sistema completo de exportacao e importacao de
projetos utilizando arquivos JSON.

O usuario pode exportar o estado completo do editor (imagem de fundo, zoom,
pan, stamps, configuracoes de slots, keybinds e historico) para um arquivo
.json e posteriormente importa-lo para restaurar integralmente o projeto.

Foi criado o ProjectPersistenceManager, um novo manager responsavel por
orquestrar todo o fluxo de exportacao e importacao.

Managers existentes foram expandidos com metodos de serializacao e
restauracao (serialize/restore).

================================================================================
2. FUNCIONALIDADES IMPLEMENTADAS
================================================================================

2.1. Exportacao de Projeto

  - Botao "Export (.json)" na secao "Project" das Configuracoes.
  - Gera um arquivo JSON com nome no formato: project_YYYY-MM-DD_HH-mm-ss.json
  - O JSON e baixado automaticamente via download.
  - Inclui: canvasState, keybindSettings, stampSlotConfigurations, stamps,
    historyState.

2.2. Importacao de Projeto

  - Botao "Import (.json)" na secao "Project" das Configuracoes.
  - Abre seletor de arquivos aceitando apenas .json.
  - Valida a estrutura do JSON antes de importar.
  - Exibe confirmacao: "Importing a project will replace the current
    session. Continue?"
  - Em caso de cancelamento: nenhuma alteracao ocorre.
  - Em caso de JSON invalido: notificacao amigavel, projeto atual nao
    alterado, nenhuma excecao nao tratada.

2.3. ProjectPersistenceManager (NOVO)

  Responsabilidades:
  - exportProject(): gera snapshot completo e faz download.
  - importProject(): aciona seletor de arquivos.
  - validateProject(): valida versao e sanitiza dados.
  - buildProjectSnapshot(): constroi o snapshot completo do estado.
  - restoreProjectSnapshot(): restaura estado a partir de snapshot.
  - validateVersion(): verifica compatibilidade de versao.
  - sanitizeImportedData(): corrige dados invalidos.
  - migrateProjectVersion(): permite migracao futura entre versoes.

4. ALTERACOES ARQUITETURAIS
================================================================================

4.1. ImageStampManager (MODIFICADO)

  NOVOS METODOS:
  - serializeAllStamps(): Retorna array com deep copies de todos os stamps.
  - deserializeAllStamps(data): Valida array de stamps, filtra entradas
    invalidas (id, worldX, worldY obrigatorios).
  - restoreAllStamps(stampsData): Limpa stamps atuais, recalcula nextZIndex
    baseado no maior zIndex dos dados, recria todos os stamps preservando
    IDs originais.

4.2. StampSettingsManager (MODIFICADO)

  NOVOS METODOS:
  - serializeSettings(): Retorna deep copy de todas as configuracoes de
    slots.
  - restoreSettings(settings): Limpa slots atuais, restaura configuracoes
    dos dados, mescla com defaults (getDefaultSlotConfig) para garantir
    campos obrigatorios.

4.3. HistoryManager (MODIFICADO)

  NOVOS METODOS:
  - serializeHistory(): Serializa undoStack e redoStack. Para entradas do
    tipo 'command', chama command.serialize() que retorna objeto JSON com
    __cmdType identificando o tipo do comando.
  - restoreHistory(data, imageStampManager): Limpa historico, itera sobre
    dados e reconstroi entradas. Para comandos, usa CMD_MAP para
    identificar a classe e chamar deserialize().

4.4. KeybindManager (MODIFICADO)

  NOVOS METODOS:
  - serializeKeybinds(): Retorna deep copy das keybinds.
  - restoreKeybinds(data): Mescla dados com defaults e restaura.

4.5. Stamp Commands (MODIFICADOS)

  Todos os 4 comandos (AddStampCommand, RemoveStampCommand, MoveStampCommand,
  ReplaceSlotStampsCommand) ganharam:
  - serialize(): Retorna objeto JSON plano com __cmdType identificador.
  - static deserialize(data, manager): Reconstrói o comando a partir dos
    dados serializados, associando ao manager informado.

  FORMATO DE SERIALIZACAO:
  - AddStampCommand: { __cmdType, stampData, stampId, stampSnapshot }
  - RemoveStampCommand: { __cmdType, stampId, removedSnapshot }
  - MoveStampCommand: { __cmdType, stampId, oldX, oldY, newX, newY }
  - ReplaceSlotStampsCommand: { __cmdType, slot, oldStampsSnapshots, newConfig }

4.6. ProjectPersistenceManager (NOVO)

  Adicionado apos StampPersistenceAdapter. Classe completa com:
  - CURRENT_VERSION = 1 (constante)
  - Gerenciamento de versao, sanitizacao e migracao
  - Fluxo completo export/import com validacao e confirmacao
  - Restauracao assincrona (imagem carregada via Image onload)

5. FLUXO COMPLETO DE EXPORTACAO
================================================================================

  1. Usuario clica em "Export (.json)" nas Configuracoes > Project.
  2. ProjectPersistenceManager.exportProject() e chamado.
  3. buildProjectSnapshot() constroi o snapshot completo:
     a. Obtem imageData do canvas layer-background via toDataURL('image/png')
        (try/catch para evitar erros CORS/Security).
     b. Chama serializeKeybinds(), serializeSettings(), serializeAllStamps(),
        serializeHistory() de cada manager.
     c. Inclui version (1), exportedAt (ISO date), canvasState completo.
  4. JSON.stringify(snapshot, null, 2) gera o JSON formatado.
  5. Blob e criado, link temporario <a> gerado e clicado para download.
  6. Nome do arquivo: project_YYYY-MM-DD_HH-mm-ss.json.
  7. URL.createObjectURL e revogada apos clique.
  8. Notificacao "Project exported: project_....json" exibida.

================================================================================
6. FLUXO COMPLETO DE IMPORTACAO
================================================================================

  1. Usuario clica em "Import (.json)" nas Configuracoes > Project.
  2. importProject() aciona o file input hidden (#json-import-input).
  3. Usuario seleciona arquivo .json.
  4. _handleImportFile() e chamado:
     a. Verifica extensao .json.
     b. FileReader le o arquivo como texto.
     c. JSON.parse() converte para objeto.
     d. _executeImport(data) e chamado.
  5. validateProject(data):
     a. validateVersion(): verifica se version existe e nao e superior.
     b. sanitizeImportedData(): verifica campos obrigatorios, corrige IDs
        duplicados, coordenadas invalidas, keybinds conflitantes.
     c. Retorna { valid, sanitized, warnings/error }.
  6. Se invalido: notificacao de erro, retorna sem alterar projeto.
  7. confirm() nativo: "Importing a project will replace the current
     session. Continue?".
  8. Se cancelado: retorna sem alterar nada.
  9. Se confirmado: _restoreProject(importData):
     a. clear() do HistoryManager.
     b. clear() do ImageStampManager (remove DOM elements + limpa lista).
     c. Reseta EditorState.canvas (image, dimensions, etc.).
     d. layerManager.clearAll() + resize(1,1).
     e. Restaura scale e offset do canvasState.
     f. Se imageData existe:
        - Cria Image(), carrega data URL.
        - onload: drawImage, resize layers, atualiza estado.
        - onerror: continua sem fundo.
     g. Chama _finishRestore().
  10. _finishRestore():
      a. keybindManager.restoreKeybinds()
      b. stampSettingsManager.restoreSettings()
      c. imageStampManager.restoreAllStamps()
      d. historyManager.restoreHistory()
      e. settingsManager.renderImageSlots()
      f. settingsManager.renderKeybinds()
      g. app.updateUI()
      h. cursorManager.refresh()
      i. Emite IMAGE_LOADED event
  11. Notificacao "Project imported successfully".
  12. Qualquer erro durante o processo e capturado e exibido como
      notificacao, sem lancar excecoes nao tratadas.

================================================================================
7. VALIDACOES IMPLEMENTADAS
================================================================================

7.1. validateVersion()

  - Verifica se data existe e version e do tipo number.
  - Se version > CURRENT_VERSION (1): erro "Project version is newer".
  - Se version for 1: aceito.

7.2. sanitizeImportedData()

  - canvasState: se ausente/invalido, cria padrao com valores zero.
  - stampSlotConfigurations: se ausente, cria objeto vazio {}.
  - stamps: se nao for array, cria array vazio [].
  - keybindSettings: se ausente, cria objeto vazio {}.
  - historyState: se ausente, cria { undoStack: [], redoStack: [] }.
  - Stamps:
    - IDs ausentes ou nao-string: gerado novo UUID.
    - IDs duplicados: gerado novo UUID.
    - worldX/Y invalidos (NaN): resetado para 0.
    - width/height invalidos (NaN, <=0): resetado para 100.
    - zIndex invalido (NaN): resetado para 1.
    - src ausente: '' (string vazia).
    - slot invalido: 1.
  - Slot configurations:
    - Keybind ausente: usa numero do slot como string.
    - Keybind conflitante (duplicado entre slots): substituido pelo
      numero do slot.

7.3. Correcoes Automaticas

  - IDs duplicados sao substituidos.
  - Coordenadas invalidas sao zeroadas.
  - Keybinds conflitantes sao reatribuidos.
  - Campos ausentes sao preenchidos com defaults.

7.4. Casos Irrecuperaveis

  - JSON mal formatado (SyntaxError): notificacao "Invalid JSON file".
  - Versao futura (version > 1): notificacao "Project version is newer".
  - Arquivo nao .json: notificacao "Please select a .json file".

8. COMPORTAMENTO DO HISTORICO APOS IMPORTACAO
================================================================================

  - Apos importar, o usuario pode usar Ctrl+Z e Ctrl+Y normalmente.
  - O historico importado inclui strokes (pencil, eraser) e comandos
    (AddStampCommand, RemoveStampCommand, MoveStampCommand,
    ReplaceSlotStampsCommand).
  - Comandos sao reconstruidos com a instancia do ImageStampManager atual.
  - Stamp IDs sao preservados durante a restauracao, garantindo que comandos
    no historico referenciem stamps corretos.
  - O nextZIndex e recalculado: max(zIndex dos stamps restaurados) + 1.

================================================================================
9. CUIDADOS IMPORTANTES RELACIONADOS AOS GIFS
================================================================================

  - GIFs sao armazenados como data URIs no src dos stamps.
  - Durante exportacao: data URIs sao incluidos diretamente no JSON.
  - Durante importacao: stamps sao recriados com os mesmos data URIs.
  - O elemento <img> gerado pelo navegador anima GIFs nativamente.
  - Efeitos (blink, wobble, fadeIn, fadeOut) sao restaurados via
    appearEffect, disappearEffect, imageEffect e effectSettings.
  - posicionamento (worldX, worldY) e zIndex sao preservados.

17. CUIDADOS PARA EVITAR REGRESSOES
================================================================================

  1. Sempre verificar se os metodos serialize() dos comandos estao
     implementados e retornam __cmdType. Se faltar __cmdType, o comando
     nao sera reconstruido durante a importacao.

  2. restoreAllStamps() deve ser chamado ANTES de restoreHistory() para
     garantir que os stamp IDs existam quando os comandos forem
     reconstruidos.

  3. restoreHistory() limpa o historico existente ANTES de preencher com
     os dados importados.

  4. _restoreProject() e o ponto de entrada unico para restauracao.
     Nunca chamar _finishRestore() diretamente (a imagem precisa ser
     carregada primeiro).

  5. A imagem de fundo e carregada de forma assincrona (img.onload).
     Durante o carregamento, o estado do canvas fica vazio. Nao adicionar
     logica que dependa da imagem entre _restoreProject e _finishRestore.

  6. Se imageData for null (exportacao sem imagem), _finishRestore e
     chamado diretamente sem carregamento assincrono.

  7. sanitizeImportedData() modifica o objeto data in-place. Nao reutilizar
     o objeto original apos sanitizacao se precisar dos dados originais.

  8. O metodo deserializeAllStamps() nao e usado internamente (a validacao
     e feita inline em sanitizeImportedData). Foi mantido para uso futuro.

  9. A exportacao pode falhar silenciosamente (sem notificacao) se o canvas
     estiver sujo (tainted) por imagem cross-origin. O try/catch captura o
     erro e imageData fica null.

  10. Se o usuario clicar em "Import" e selecionar um arquivo nao-JSON,
      o filtro accept=".json" do input file ja filtra no nivel do SO, mas
      a verificacao em _handleImportFile serve como fallback.

20. PROBLEMAS COMUNS QUE DEVEM SER EVITADOS
================================================================================

  1. NAO usar JSON.parse(JSON.stringify()) em objetos que contenham
     referencias circulares ou funcoes. Todas as estruturas serializadas
     sao dados planos.

  2. NAO esquecer que stamps restaurados precisam preservar seus IDs
     originais para que comandos no historico funcionem.

  3. NAO chamar restoreHistory() antes de restoreAllStamps(). Os comandos
     no historico referenciam stamps por ID.

  4. NAO modificar o objeto data durante sanitizacao se precisar dos
     dados originais para debug (a sanitizacao modifica in-place).

  5. NAO assumir que toDataURL() sempre funciona. Usar try/catch e tratar
     imageData: null como caso valido.

  6. Cuidado com o carregamento assincrono da imagem de fundo durante
     importacao. _finishRestore so deve ser chamado apos o onload.

  7. A confirmacao de import usa confirm() que e bloqueante. Nao chamar
     de dentro de loops ou callbacks animados.

  8. Nao confundir serializacao de comandos com execucao. restoreHistory()
     NAO executa os comandos, apenas os restaura nas pilhas.

  9. Ao adicionar novos comandos no futuro, implementar serialize() e
     static deserialize() e adicionar ao CMD_MAP em restoreHistory().

  10. O metodo _handleImportFile tem underscore (privado por convencao)
      mas e chamado pelo event handler do DOM. Isso e intencional.
