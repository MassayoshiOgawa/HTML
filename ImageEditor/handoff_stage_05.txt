1. RESUMO DA ETAPA
================================================================================

Esta etapa implementou dois modos de interacao com stamps permanentes:

1. DELETE MODE: ativado ao segurar a tecla X (ou keybind configurada).
   Enquanto ativo, clicar com o botao esquerdo sobre um stamp o remove.

2. MOVE MODE: ativado ao segurar a tecla V (ou keybind configurada).
   Enquanto ativo, clicar e arrastar um stamp o reposiciona.

Ambos os modos usam hit testing por coordenadas do mundo (world coordinates),
respeitando zoom, pan, z-index, e o tamanho real de cada stamp.

Todas as funcionalidades existentes (lapis, borracha, caneta que some, zoom,
pan, historico, keybinds, slots, preview, insercao de stamps) continuam
funcionando exatamente como antes.

  - Desativado ao soltar a tecla X

  - Ao soltar o botao do mouse, a movimentacao e finalizada
  - Ao soltar a tecla V durante um arrasto, o arrasto e finalizado

2.3. SISTEMA DE HIT TESTING

  - Implementado no ImageStampManager
  - Converte coordenadas de tela para coordenadas do mundo
  - Verifica se o ponto esta dentro do bounding box de cada stamp
  - Retorna o stamp com maior z-index entre os que contem o ponto
  - Considera: posicao real (worldX/worldY), tamanho (width/height),
    zoom (via conversao de coordenadas), pan (via conversao),
    z-index (itera do maior para o menor)

2.4. KEYBINDS CONFIGURAVEIS

  - "Delete Stamp Mode" com valor padrao "x"
  - "Move Stamp Mode" com valor padrao "v"
  - Configuraveis no modal de teclas (Settings > Atalhos de Teclado)
  - Persistidas no localStorage via chave "image-editor-keybinds"

3.4. ImageStampManager (EXPANDIDO)

  - 4 novos metodos:
    hitTest(worldX, worldY)
      Retorna o stamp com maior zIndex na posicao worldX/worldY,
      ou null se nenhum stamp for encontrado. A bounding box e
      calculada como: left = worldX - width/2, right = worldX + width/2,
      top = worldY - height/2, bottom = worldY + height/2.

    findTopMostAtPosition(worldX, worldY)
      Alias para hitTest().

    moveStamp(id, worldX, worldY)
      Atualiza worldX/worldY no estado (fonte da verdade),
      chama updateStampPosition() para sincronizar o DOM,
      emite STAMP_MODIFIED.

    updateStampPosition(id)
      Sincroniza o elemento <img> no DOM com as coordenadas
      do estado. Usa left/top em world coordinates.

3.5. App (MODIFICADO)

  - 10 novos metodos privados:
    _keyMatchesKeybind(e, keybind)
      Verifica se o evento de teclado corresponde a uma keybind
      (considerando modificadores ctrl/alt/shift e o local).
      Ignora e.repeat e e.location === 3 (num pad).

    _handleModeKeyDown(e)
      Verifica se a tecla pressionada corresponde a delete-stamp-mode
      ou move-stamp-mode. Se sim, ativa o modo correspondente,
      desativa o outro modo, atualiza indicador e cursor.
      Ignora INPUT/TEXTAREA. Retorna true se consumiu o evento.

    _handleModeKeyUp(e)
      Verifica se a tecla solta corresponde ao delete-stamp-mode
      ou move-stamp-mode. Se sim, desativa o modo.
      Se havia um arrasto em andamento (move mode), finaliza.
      Ignora INPUT/TEXTAREA. Retorna true se consumiu o evento.

    _handleStampModeMouseDown(e)
      Se delete mode ativo: faz hit test, se achar stamp, remove.
      Se move mode ativo: faz hit test, se achar stamp, inicia
      arrasto (calcula offset, marca draggingStampId, aplica
      highlight visual).
      Apenas botao esquerdo (button 0).

    _handleStampModeMouseMove(e)
      Se draggingStampId estiver definido, calcula nova posicao
      em world coordinates (subtraindo o offset de arrasto)
      e chama moveStamp().

    _handleStampModeMouseUp(e)
      Se draggingStampId estiver definido, finaliza o arrasto.

    _finalizeStampDrag()
      Remove highlight visual, emite STAMP_MODIFIED, limpa estado
      de arrasto (draggingStampId, dragOffsetWorldX/Y).

    _highlightStamp(stampId, highlight)
      Aplica outline (2px solid var(--accent)) e drop-shadow no
      elemento <img> do stamp quando highlight=true.
      Remove quando highlight=false.

    _updateModeIndicator()
      Mostra/esconde o elemento #stamp-mode-indicator com texto
      e cor apropriados para cada modo.

    _updateModeCursor()
      Alterna o cursor do canvas-area entre crosshair (delete),
      move (move mode), ou normal (nenhum modo).
      Esconde o custom cursor do CursorManager durante os modos.

3.6. _bindEvents (MODIFICADO)

  - document.addEventListener('keydown', ...):
    Antes de chamar keybindManager.handleKeyDown, chama
    _handleModeKeyDown. Se retornar true, previne default e
    nao chama keybindManager.

  - document.addEventListener('keyup', ...):
    Adicionado listener para _handleModeKeyUp.

  - canvas-area mousedown:
    Antes de chamar toolManager.handleMouseDown, chama
    _handleStampModeMouseDown. Se retornar true, nao chama
    toolManager.

  - canvas-area mousemove:
    Se delete ou move mode ativo, pula cursorManager.move().
    Antes de chamar toolManager.handleMouseMove, chama
    _handleStampModeMouseMove. Se retornar true (arrasto
    ativo), nao chama toolManager.

  - canvas-area mouseleave:
    Se modo ativo, nao esconde o cursor (pois o custom
    cursor ja esta desativado).

  - canvas-area mouseenter:
    Se modo ativo, nao reposiciona o cursor.

  - document mouseup:
    Antes de chamar toolManager.handleMouseUp, chama
    _handleStampModeMouseUp. Se retornar true, nao chama
    toolManager.

9. COMPORTAMENTO ESPECIFICO DOS MODOS
================================================================================

9.1. DELETE MODE

  - Entrada: pressionar tecla configurada (padrao X)
  - Saida: soltar tecla
  - Enquanto ativo, cursor crosshair
  - Click esquerdo em stamp: remove o stamp com maior zIndex
  - Click em area sem stamp: NAO remove nada
  - Click nao interfere com ferramentas (lapis, borracha, etc.)
  - Click com botao direito: NAO remove nada

9.2. MOVE MODE

  - Entrada: pressionar tecla configurada (padrao V)
  - Saida: soltar tecla
  - Enquanto ativo, cursor move
  - Click esquerdo em stamp + arrastar: move o stamp
  - Stamp selecionado: outline azul + drop-shadow
  - Enquanto arrastado, stamp segue o cursor perfeitamente
  - Usa world coordinates (NUNCA coordenadas de tela)
  - Respeita zoom e pan (via getCanvasCoords)
  - Arrasto finalizado ao soltar o mouse OU soltar a tecla V

9.3. PRIORIDADE DE Z-INDEX

  - Ambos os modos selecionam o stamp com maior zIndex
  - hitTest() itera do ultimo para o primeiro elemento da lista
    (a lista e ordenada por zIndex ascendente via getAll())
  - Exemplo:
    Stamp A zIndex 1
    Stamp B zIndex 3
    Stamp C zIndex 5
    Click em sobreposicao -> seleciona Stamp C

9.4. MUTUAL EXCLUSION

  - Delete mode e Move mode sao mutuamente exclusivos
  - Ativar um modo desativa automaticamente o outro
  - Nao e possivel estar em ambos os modos simultaneamente

14. DESCRICAO DA ETAPA 6 (PROXIMA)
================================================================================

A Etapa 6 devera implementar a integracao completa com UNDO/REDO para
operacoes de stamps, e refinamentos no sistema de interacao.

14.1. FUNCIONALIDADES ESPERADAS

  - Undo/Redo para Delete de stamps:
    * Quando um stamp e removido (via Delete Mode), a operacao deve
      ser registrada no HistoryManager
    * Ctrl+Z deve restaurar o stamp removido
    * Ctrl+Y deve refazer a remocao
    * Utilizar RemoveStampCommand (ja existe no codigo)

  - Undo/Redo para Move de stamps:
    * Quando um stamp e movido (via Move Mode), a operacao deve
      ser registrada no HistoryManager
    * Ctrl+Z deve retornar o stamp a posicao original
    * Ctrl+Y deve refazer o movimento
    * Utilizar MoveStampCommand (ja existe no codigo)
    * Capturar posicao original ANTES do inicio do arrasto

  - Refinamentos de experiencia:
    * Animacao suave de retorno ao desfazer movimento
    * Feedback visual ao desfazer/refazer (piscar o stamp)
    * Prevenir estado inconsistente (stamp removido mas DOM presente)

14.2. INTEGRACAO COM SISTEMAS EXISTENTES

  - App._handleStampModeMouseDown(): ao inves de chamar
    imageStampManager.removeStamp() diretamente, criar e executar
    um RemoveStampCommand via historyManager.

  - App._handleStampModeMouseDown(): ao iniciar arrasto, salvar
    a posicao original (stamp.worldX, stamp.worldY) para uso
    pelo MoveStampCommand.

  - App._finalizeStampDrag(): ao finalizar arrasto, criar e executar
    um MoveStampCommand com oldX/oldY (posicoes originais) e
    newX/newY (posicoes finais).

  - HistoryManager.push(): atualmente aceita strokes do canvas.
    Precisa ser expandido para aceitar Command objects.

  - Alternativa: implementar um StampHistoryManager separado que
    gerencia uma pilha de StampCommand.

14.3. ARQUITETURA EXISTENTE QUE DEVE SER REUTILIZADA

  - RemoveStampCommand (linha ~1975):
    constructor(imageStampManager, stampId)
    execute(): remove stamp, salva referencia em _removed

  - MoveStampCommand (linha ~2005):

14.4. OBSERVACOES IMPORTANTES PARA O PROXIMO DESENVOLVEDOR

  O HistoryManager atual gerencia strokes como objetos simples
  (arrays de pontos). Para integrar Undo/Redo com stamps, o
  HistoryManager precisa ser expandido para aceitar Command objects.

  Sugestoes de implementacao:

  1. Criar um array separado EditorState.history.commandStack
     para comandos de stamp (para nao misturar com strokes).

  2. Ou modificar HistoryManager.push() para detectar se o
     argumento e um Command ou um stroke, e tratar adequadamente.

  3. Ou criar um StampCommandHistory gerenciado pelo
     ImageStampManager.

  A abordagem recomendada:
  - Adicionar EditorState.history.commandUndoStack e
    EditorState.history.commandRedoStack
  - HistoryManager ganha metodos pushCommand(command),
    undoCommand(), redoCommand()
  - App.executeAction('undo') verifica se ha comandos para
    desfazer, e se sim, chama undoCommand() ao inves de undo()
  - O estado dos botoes undo/redo considera ambas as pilhas

  Cuidados:
  - Nao quebrar o undo/redo existente de strokes
  - Nao permitir estado inconsistente (stamp removido do estado
    mas ainda no DOM)
  - Garantir que o DOM seja sincronizado apos cada undo/redo
    (ImageStampManager.renderAll() pode ser usado para
    reconstruir o DOM a partir do estado)
  - Testar exaustivamente: inserir stamp, mover, deletar,
    desfazer varias vezes, refazer
