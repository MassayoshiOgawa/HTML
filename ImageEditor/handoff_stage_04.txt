Esta etapa implementou a insercao permanente das imagens configuradas nos
slots 1 a 9 dentro do canvas do editor.

Ao pressionar e segurar a keybind de um slot com a ferramenta Mao ativa
e o botao esquerdo do mouse pressionado, o preview da imagem aparece

editor como um StampEntity independente.

zoom, pan, historico, keybinds, configuracao dos slots, preview dos
slots) continuam funcionando exatamente como antes.

2. FUNCIONALIDADES IMPLEMENTADAS

2.1. INSERCAO PERMANENTE DE STAMPS

  - A insercao permanente ocorre quando TODAS as condicoes abaixo sao
    satisfeitas:
    * Ferramenta Mao (hand) esta ativa
    * Botao esquerdo do mouse esta pressionado
    * Uma keybind de slot (1-9) esta pressionada
    * Um preview valido esta sendo exibido (imagem configurada no slot)

  - Fluxo completo:
    1. Usuario ativa a ferramenta Mao (tecla H ou clique na toolbar)
    2. Usuario pressiona o botao esquerdo do mouse
    3. Usuario pressiona e segura a keybind de um slot (1-9)
    4. O preview da imagem aparece seguindo o cursor
    5. Usuario posiciona a imagem na posicao desejada
    6. Usuario solta a keybind
    7. O preview desaparece (com ou sem fade out, conforme configurado)
    8. Uma copia permanente do stamp e criada no canvas

  - A insercao acontece no momento em que a tecla e solta (keyup),
    antes do preview ser desativado.

2.2. IMAGE STAMP MANAGER EXPANDIDO

  - O ImageStampManager existente foi expandido com metodos de renderizacao
    DOM e gerenciamento de elementos HTML.

  - Novos metodos adicionados:

    addStamp(stampData)
      - Chama add() internamente (cria entidade no estado)
      - Renderiza o elemento <img> correspondente no DOM
      - Retorna o StampEntity criado

    removeStamp(id)
      - Chama remove() internamente (remove do estado)
      - Remove o elemento <img> do DOM
      - Retorna o StampEntity removido (ou null)

    getStampById(id)
      - Alias para getById(id)

    getStampsBySlot(slot)
      - Alias para getBySlot(slot)

    getAllStamps()
      - Alias para getAll()

    getTopMostStamp()
      - Retorna o stamp com maior zIndex (ultimo inserido)
      - Retorna null se nao houver stamps

    calculateNextZIndex()
      - Retorna o proximo zIndex a ser usado
      - Nao incrementa o contador

    renderStamp(stamp)
      - Renderiza um StampEntity especifico no DOM
      - Utilizado para renderizacao individual

    destroyStamp(id)
      - Remove o elemento <img> do DOM sem remover do estado
      - Utilizado para gerenciamento fino de DOM

    renderAll()
      - Remove todos os elementos <img> do DOM
      - Re-renderiza todos os stamps a partir do estado
      - Utilizado para reconstrucao completa do DOM

    setLayer(layerEl)
      - Define o elemento DOM que servira como container
      - Deve ser chamado durante a inicializacao (App.init())

    _renderStampElement(stamp)
      - Metodo privado que cria o elemento <img>
      - Configura src, posicao (left/top em world coords),
        dimensoes (width/height), zIndex, pointer-events
      - Adiciona ao _layer e registra no Map _stampElements

    _destroyStampElement(id)
      - Metodo privado que remove o elemento <img> do DOM
      - Remove do Map _stampElements

  - O metodo clear() foi modificado para tambem destruir todos os
    elementos DOM antes de limpar o estado.

  - A geracao de ID foi alterada de uuid() para crypto.randomUUID()
    com fallback para uuid().

2.3. STAMPENTITY - ESTRUTURA FINAL

  Cada StampEntity e um objeto JavaScript com a seguinte estrutura:

    {
      id: string (UUID via crypto.randomUUID),
      slot: number (1-9, slot de origem),
      src: string (URL ou data URI da imagem),
      sourceType: string ('url' | 'datauri'),
      worldX: number (coordenada X no espaco do mundo),
      worldY: number (coordenada Y no espaco do mundo),
      width: number (largura em pixels no espaco do mundo),
      height: number (altura em pixels no espaco do mundo),
      zIndex: number (ordem de sobreposicao, auto-incrementado),
      appearEffect: string | null ('fadeIn' ou null),
      appearSettings: object | null,
      disappearEffect: string | null ('fadeOut' ou null),
      disappearSettings: object | null,
      imageEffect: string | null ('blink' | 'wobble' | null),
      imageEffectSettings: object | null,
      createdAt: number (timestamp de criacao),
    }

  A fonte da verdade e o estado JavaScript (EditorState.stamps.list).
  O elemento <img> no DOM e uma representacao derivada.

  Cada StampEntity tem um elemento <img> correspondente no DOM,
  registrado no Map _stampElements (id -> HTMLImageElement).

2.4. SISTEMA DE Z-INDEX

  - Cada novo stamp recebe um zIndex igual ao valor atual de
    EditorState.stamps.nextZIndex, que e entao incrementado.

  - O stamp inserido mais recentemente tem o maior zIndex.

  - Exemplo:
    Stamp A -> zIndex 1
    Stamp B -> zIndex 2
    Stamp C -> zIndex 3

  - zIndex e aplicado via CSS (style.zIndex) no elemento <img>.

2.5. SISTEMA DE COORDENADAS DO MUNDO (WORLD COORDINATES)

  - A posicao de cada stamp e armazenada em coordenadas do mundo
    (worldX, worldY), que representam o centro da imagem.

  - A conversao de coordenadas de tela para mundo:

    worldX = (clientX - rect.left - offsetX) / scale
    worldY = (clientY - rect.top - offsetY) / scale

    Onde:
      clientX, clientY = posicao do cursor na tela
      rect = getBoundingClientRect() do canvas-area
      offsetX, offsetY = pan offset do canvas
      scale = zoom scale do canvas

  - A renderizacao no DOM aplica:
    left = worldX - width/2
    top = worldY - height/2

  - Como os elementos <img> estao dentro de #canvas-container (que
    possui transform: translate + scale), as coordenadas do mundo
    sao automaticamente mapeadas para a tela pelo navegador.

2.6. COMPORTAMENTO DOS GIFS PERMANENTES

  - GIFs animados permanecem animados apos insercao permanente.
  - Como os stamps sao elementos <img> nativos (nao canvas),
    a animacao nativa do GIF e preservada pelo navegador.
  - Continuam animados durante zoom e pan (pois o elemento <img>
    nunca e interrompido).
  - Funciona tanto para uploads (data URI) quanto para links (URL).

2.7. VALIDACAO DE LIMITE ESPACIAL

  - O centro do stamp deve estar dentro do canvas-container.
  - A verificacao e feita comparando as coordenadas de tela do
    cursor contra o bounding client rect do canvas-container.
  - Se o cursor estiver fora, a insercao e cancelada (nenhum
    erro, apenas nao insere).
  - Stamps podem ultrapassar os limites da imagem principal,
    desde que o centro esteja dentro do canvas-container.

2.8. REACAO AO ZOOM E PAN

  - Todos os stamps reagem ao zoom e pan automaticamente:
    * Ampliam junto com a imagem principal (devido ao scale do
      canvas-container)
    * Reduzem junto com a imagem principal
    * Acompanham deslocamentos do pan (devido ao translate do
      canvas-container)
    * Mantem proporcoes corretas
    * Mantem alinhamento perfeito com a imagem principal

  - Nenhum codigo adicional e necessario para zoom/pan porque os
    elementos <img> estao dentro de #canvas-container, que tem
    a transformacao CSS aplicada.

2.9. TRACKING DO MOUSE

  - O StampPreviewManager agora monitora o estado do botao
    esquerdo do mouse:
    * _mouseButtonDown: boolean (true quando botao esquerdo
      esta pressionado)
    * _onMouseDown(e): define _mouseButtonDown = true (apenas
      botao 0)
    * _onMouseUp(e): define _mouseButtonDown = false (apenas
      botao 0)

  - Eventos mousedown sao escutados no canvas-area
  - Eventos mouseup sao escutados no document (para capturar
    soltura fora do canvas)

9. COMPORTAMENTO ESPECIFICO DA INSERCAO
================================================================================

9.1. ORDEM DE EXECUCAO EM KEYUP

  Quando a tecla do slot e solta:
    1. _heldSlots.delete(slot)
    2. if (_activeSlot === slot):
       a. _tryInsertStamp(slot) -> verifica condicoes -> _insertStamp(slot)
       b. _deactivatePreview(false) -> inicia fade out (se configurado)
          ou remove preview imediatamente

  A insercao acontece ANTES do preview ser removido. Isso significa
  que o stamp permanente aparece no DOM enquanto o preview ainda esta
  visivel (durante o fade out, se configurado).

9.2. PREVIEW DURANTE FADE OUT

  - Se o slot possui efeito de desaparecimento "Fade Out", o preview
    permanece visivel durante o fade out (opacity: 1 -> 0).
  - O stamp permanente e criado na mesma posicao.
  - O stamp fica atras do preview (z-index 5 vs z-index 10).
  - Quando o fade out termina e o preview e removido, o stamp
    permanece visivel.

9.3. CANCELAMENTO DE INSERCAO

  A insercao e cancelada silenciosamente (sem notificacao) quando:
  - Nenhum preview ativo
  - Mouse nao esta pressionado
  - Ferramenta ativa nao e a Mao
  - Cursor esta fora do canvas-container
