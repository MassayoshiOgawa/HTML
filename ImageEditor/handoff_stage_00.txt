1. RESUMO DA ETAPA
================================================================================

Esta etapa estabeleceu a fundacao arquitetural do Image Editor. O foco foi
exclusivamente estrutural: criar uma base solida, consistente e preparada para
crescimento futuro. Nenhuma funcionalidade avancada (image stamps, save/load,
autosave, GIFs, etc.) foi implementada.

As principais entregas foram:
- Sistema de DEBUG_MODE e asserts
- Utilitarios (clamp, debounce, throttle, lerp, uuid)
- EventBus para desacoplamento de managers
- Classe Command (padrao de comando)
- Eventos padronizados (namespace:evento)
- Sistema de coordenadas (Screen Space vs World Space)
- EditorState com estado organizado em namespaces
- InputManager centralizado
- CanvasManager unificado (zoom, pan, transformacoes)
- Atualizacao dos managers existentes para usar EventBus

================================================================================
2. ESTRUTURA DO EDITORSTATE
================================================================================

O estado global da aplicacao esta em:

  const EditorState = { ... };

Organizado nos seguintes namespaces:

  EditorState.canvas
    - scale (number): fator de zoom (0.1 a 10)
    - offsetX (number): deslocamento X do canvas em pixels
    - offsetY (number): deslocamento Y do canvas em pixels
    - image (HTMLImageElement|null): imagem carregada
    - imageUrl (string|null): URL do objeto (ObjectURL)
    - imageName (string): nome do arquivo
    - imageWidth (number): largura natural da imagem
    - imageHeight (number): altura natural da imagem

  EditorState.tools
    - activeToolName (string): nome da ferramenta ativa ('pencil', 'eraser', etc.)
    - isDrawing (boolean): se o usuario esta desenhando no momento
    - currentStroke (object|null): tracado atual sendo desenhado
    - isPanning (boolean): se esta em modo pan (mao)
    - panStart (object|null): ponto de inicio do pan
    - panOffsetStart (object|null): offset inicial do pan
    - fadingStrokes (array): tracos da caneta que some
    - currentFadingStroke (object|null): traco fade atual
    - fadingLoopId (number|null): ID do requestAnimationFrame

  EditorState.history
    - undoStack (array): pilha de comandos para desfazer
    - redoStack (array): pilha de comandos para refazer
    - maxHistory (number): limite maximo do historico (50)

  EditorState.settings
    - keybinds (object): mapa de atalhos (acao -> combinacao)
    - defaultKeybinds (object): atalhos padrao

  EditorState.ui
    - isOptionsOpen (boolean): painel de opcoes aberto/fechado

  EditorState.stamps
    - (vazio, preparado para uso futuro)

  EditorState.input
    - (vazio, gerenciado pelo InputManager)

4. RESPONSABILIDADES DE CADA MANAGER
================================================================================

EventBus
  - Desacoplar comunicacao entre managers
  - Metodos: on(event, cb), off(event, cb), emit(event, data), once(event, cb)
  - Usa Set para listeners (evita duplicatas)
  - Eventos sao prefixados por namespace (ex: 'history:changed')

NotificationManager
  - Exibir toasts/notificacoes na interface
  - Tipos: info, success, error, warning
  - Temporizador automatico de remocao

KeybindManager
  - Registrar, validar e persistir atalhos de teclado
  - Persistencia via localStorage (chave: 'image-editor-keybinds')
  - Captura de novas combinacoes (startCapture/stopCapture)
  - Emite 'keybind:changed' no EventBus ao alterar atalhos

HistoryManager
  - Gerenciar undo/redo usando pilhas
  - Push de strokes para undoStack
  - Limite de 50 entradas (maxHistory)
  - Emite 'history:changed' no EventBus

CanvasManager
  - Controlar zoom (setScale, zoomIn, zoomOut, setZoom100, fitToScreen)
  - Controlar pan (via manipulacao direta de EditorState.canvas.offsetX/Y)
  - Aplicar transformacoes CSS no canvas-container
  - Emite 'canvas:transformed' no EventBus
  - Usa clamp() para limitar escala entre 0.1 e 10

LayerManager
  - Gerenciar camadas de canvas (background, permanent, temp, fading)
  - Redimensionar todos os canvases
  - Limpar camadas individuais ou todas

ToolManager
  - Registrar e ativar ferramentas
  - Gerenciar ferramenta ativa
  - Emite 'tool:activated' no EventBus

UIManager
  - Atualizar painel de opcoes da ferramenta ativa
  - Atualizar barra de status
  - Gerenciar toggle do painel de opcoes

SettingsManager
  - Abrir/fechar modal de configuracoes
  - Renderizar lista de atalhos
  - Integracao com KeybindManager para alteracao de atalhos

InputManager
  - Centralizar eventos de teclado e mouse
  - Rastrear estado de teclas pressionadas (isKeyDown)
  - Rastrear estado de botoes do mouse (isMouseDown)
  - Rastrear posicao do mouse (getMousePosition, getMouseClient)
  - Emitir eventos no EventBus (input:keydown, input:keyup, etc.)
  - Impedir duplicacao de listeners (bind/unbind)

================================================================================
5. FUNCIONAMENTO DO EVENTBUS
================================================================================

O EventBus e um sistema pub-sub interno. Todos os managers que precisam
comunicar mudancas o fazem atraves do EventBus, sem referencias diretas.

Eventos padronizados (const EVENTS):

  NOME DA CONSTANTE       STRING DO EVENTO
  ------------------------------------------------------------------
  HISTORY_CHANGED         'history:changed'
  SETTINGS_UPDATED        'settings:updated'
  CANVAS_TRANSFORMED      'canvas:transformed'
  KEYBIND_CHANGED         'keybind:changed'
  INPUT_KEYDOWN           'input:keydown'
  INPUT_KEYUP             'input:keyup'
  INPUT_MOUSEDOWN         'input:mousedown'
  INPUT_MOUSEMOVE         'input:mousemove'
  INPUT_MOUSEUP           'input:mouseup'
  TOOL_ACTIVATED          'tool:activated'
  IMAGE_LOADED            'image:loaded'

Exemplo de uso:
  this.eventBus.emit(EVENTS.CANVAS_TRANSFORMED, { scale: 2 });
  this.eventBus.on(EVENTS.CANVAS_TRANSFORMED, (data) => { ... });

================================================================================
6. FUNCIONAMENTO DO INPUTMANAGER
================================================================================

O InputManager e criado no App.constructor() e ativado no App.init():

  this.inputManager = new InputManager(this.eventBus);
  // ...
  this.inputManager.bind(DOM['canvas-area']);

Ao ser ativado (bind), ele registra listeners em document para:
  - keydown: atualiza this.keys e emite input:keydown
  - keyup: atualiza this.keys e emite input:keyup
  - mousedown: atualiza this.buttons e emite input:mousedown
  - mousemove: atualiza this.mouse e emite input:mousemove
  - mouseup: atualiza this.buttons e emite input:mouseup

E em window para:
  - blur: limpa todos os estados de teclas/botoes

API publica:
  - isKeyDown(key): boolean
  - isMouseDown(button): boolean
  - getMousePosition(): { x, y } (relativo ao target)
  - getMouseClient(): { clientX, clientY }
  - bind(target): ativa listeners
  - unbind(): remove listeners

================================================================================
7. FUNCIONAMENTO DO HISTORYMANAGER
================================================================================

O HistoryManager gerencia duas pilhas:

  EditorState.history.undoStack - armazena strokes para desfazer
  EditorState.history.redoStack - armazena strokes para refazer

Metodos:
  push(stroke): adiciona stroke ao undoStack, limpa redoStack,
                respeita maxHistory (shift se exceder)
  undo(): move do undoStack para redoStack, renderiza canvas
  redo(): move do redoStack para undoStack, renderiza canvas
  clear(): limpa ambas as pilhas

Cada operacao emite 'history:changed' no EventBus.

================================================================================
8. SISTEMA DE COORDENADAS
================================================================================

Dois sistemas de coordenadas sao definidos:

SCREEN SPACE
  - Coordenadas relativas a tela (viewport)
  - Usadas para eventos de mouse (clientX, clientY)
  - Convertidas via: screenToWorld(clientX, clientY)

WORLD SPACE
  - Coordenadas logicas do editor (posicao na imagem)
  - Usadas para armazenar strokes e dados persistentes
  - Regra: TODO dado persistente deve usar WORLD SPACE

Funcoes de conversao:
  screenToWorld(clientX, clientY) -> { x, y }
    Leva em conta o zoom (scale) e pan (offsetX/Y) do canvas.

  worldToScreen(worldX, worldY) -> { x, y }
    Converte coordenadas logicas para posicao na tela.

A funcao getCanvasCoords(clientX, clientY) e um alias para screenToWorld,
mantida para compatibilidade com as ferramentas de desenho.

================================================================================

  Constantes de classe -> UPPER_SNAKE   (ex: EVENTS.HISTORY_CHANGED)
  Elementos DOM        -> prefixo DOM   (ex: DOM['canvas-area'])
  Eventos              -> namespace:evento (ex: 'history:changed')
  Propriedades/Metodos privados -> prefixo _ (ex: this._applyTransform)

10. UTILITARIOS IMPLEMENTADOS
================================================================================

  clamp(value, min, max)
    - Limita um valor entre minimo e maximo

  debounce(fn, ms)
    - Retorna funcao com atraso de execucao

  throttle(fn, ms)
    - Retorna funcao com limitacao de taxa de chamada

  lerp(a, b, t)
    - Interpolacao linear entre a e b

  uuid()
    - Gera UUID v4 aleatorio

  assert(condition, message)
    - Lanca erro se condicao falsa (apenas em DEBUG_MODE)

  debug.log / debug.warn / debug.error
    - Logging condicional (so imprime se DEBUG_MODE = true)

13. PONTOS CRITICOS QUE DEVEM SER PRESERVADOS
================================================================================

1. TODO estado persistente deve usar WORLD SPACE (screenToWorld), NUNCA
   screen space. Isto e fundamental para consistencia com zoom/pan.

2. Somente o CanvasManager pode alterar zoom, pan e transformacoes CSS
   do canvas-container. NUNCA manipule DOM.transform diretamente.

3. O estado (EditorState) e a unica fonte da verdade. O DOM jamais deve
   tornar-se fonte da verdade.

4. Managers sao inicializados no App.constructor() e recebem eventBus
   via parametro do construtor. A ordem de inicializacao no constructor
   deve ser mantida.

5. Nao duplicar listeners de evento. O InputManager usa bind/unbind com
   flag _bound para garantir registro unico.

6. CursorManager e criado no init() (nao no constructor) porque depende
   de DOM['canvas-area'] que so existe apos initDOM().

7. HandTool faz pan diretamente via EditorState.canvas.offsetX/Y e
   chama app.updateTransform(). Isso e aceitavel, mas idealmente deveria
   passar pelo CanvasManager.

8. A funcao getCanvasCoords e mantida para compatibilidade com as
   ferramentas de desenho, mas internamente delega para screenToWorld.

================================================================================

  UIManager depende de: App (toolManager, cursorManager)
