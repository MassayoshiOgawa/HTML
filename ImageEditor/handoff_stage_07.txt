1. RESUMO DA ETAPA
================================================================================

Esta etapa implementou o sistema de substituicao em massa (Replace Existing
Stamps) que permite ao usuario alterar as configuracoes de um slot e aplicar
essas mudancas a todos os stamps ja existentes daquele slot.

O sistema utiliza a opcao "Replace Existing Stamps" que ja existia na
interface como toggle, mas que agora possui comportamento funcional completo.

Quando o toggle esta ativo para um slot e o usuario modifica uma propriedade
relevante (imagem, tamanho, efeitos, etc.), uma confirmacao e solicitada. Se
confirmada, todos os stamps do slot sao atualizados com os novos valores em
uma unica operacao atomica desfazivel via Undo/Redo.

================================================================================
2. FUNCIONALIDADES IMPLEMENTADAS
================================================================================

2.1. Substituicao em Massa via Confirmacao

  - Cada slot possui seu proprio toggle "Replace Existing Stamps"
    independente.
  - Quando ativo, alteracoes em propriedades relevantes disparam uma
    confirmacao.
  - Se confirmado: todos os stamps do slot sao atualizados com os novos
    valores, toggle e desativado.
  - Se cancelado: nenhum stamp e alterado, toggle permanece ativado.
  - Se nao existirem stamps para o slot: toggle e desativado silenciosamente,
    nenhuma entrada no historico e criada.

2.2. Propriedades que Disparam Confirmacao

  As seguintes alteracoes disparam confirmacao quando o toggle esta ativo:
  - Upload de nova imagem (slot-file-input)
  - Aplicacao de link de imagem (_slotApplyLink)
  - Alteracao do tamanho (size slider, evento change)
  - Alteracao do efeito de surgimento (appearEffect select)
  - Alteracao da duracao do fade-in (appearDuration slider)
  - Alteracao do efeito de desaparecimento (disappearEffect select)
  - Alteracao da duracao do fade-out (disappearDuration slider)
  - Alteracao do efeito continuo (imageEffect select - blink/wobble)
  - Alteracao das configuracoes de blink (blinkSpeed, blinkVisibleTime,
    blinkInvisibleTime)
  - Alteracao da intensidade do wobble (wobbleIntensity)

2.3. ReplaceSlotStampsCommand (NOVO)

  Novo comando que substitui o antigo ReplaceStampCommand.

  Responsabilidades:
  - Armazena slot afetado, snapshots anteriores, nova configuracao.
  - execute(): aplica nova configuracao a todos os stamps do slot via
    _applyConfig(), chama syncAllElements() para atualizar DOM.
  - undo(): restaura cada stamp ao snapshot original via Object.assign().
  - redo(): chama execute() novamente.

  Caracteristicas:
  - Gera APENAS UMA entrada no historico, independentemente do numero de
    stamps (1 stamp ou 100 stamps = 1 entrada).
  - Nao destroi e recria stamps - atualiza in-place.
  - Preserva ID, worldX, worldY, zIndex de cada stamp.

2.4. ImageStampManager.updateStampElement() (NOVO)

  Atualiza o elemento DOM <img> de um stamp especifico para refletir os
  dados atuais (src, posicao, dimensoes, zIndex).

2.5. ImageStampManager.syncAllElements() (NOVO)

  Itera sobre todos os stamps em EditorState.stamps.list e chama
  updateStampElement() para cada um, sincronizando todo o DOM com o estado.

3. FLUXO COMPLETO DA SUBSTITUICAO
================================================================================

  1. Usuario abre Configuracoes e expande um slot (ex: Slot 1).
  2. Usuario ativa o toggle "Replace Existing Stamps".
  3. Usuario altera uma propriedade relevante (ex: troca a imagem via upload).
  4. A configuracao do slot e salva normalmente via setSlot().
  5. Imediatamente apos, _checkSlotReplaceConfirmation() e chamada.
  6. Esta funcao verifica:
     a. config.replaceExisting e true? (senao, retorna)
     b. Existem stamps para este slot? (senao, desativa toggle, retorna)
     c. config.source e valido? (senao, notifica warning, retorna)
  7. Se todas as condicoes sao satisfeitas, confirm() nativo e exibido:
     "This will update all existing stamps created using Slot X. Continue?"
  8. Se usuario confirmar:
     a. Snapshots profundos de todos os stamps do slot sao salvos.
     b. ReplaceSlotStampsCommand e criado e executado via
        HistoryManager.pushCommand().
     c. config.replaceExisting = false e salvado via setSlot().
     d. renderImageSlots() e chamado para atualizar interface.
     e. Notificacao "Slot X stamps updated" e exibida.
  9. Se usuario cancelar:
     a. Nenhuma acao adicional. Toggle permanece ativo.

10. COMPORTAMENTO DO REPLACE SLOT STAMPS COMMAND
================================================================================

10.1. execute()

  1. Obtem todos os stamps do slot via this._manager.getBySlot(this._slot).
  2. Para cada stamp, chama _applyConfig(stamp) que atualiza:
     - src, sourceType, appearEffect, appearSettings, disappearEffect,
       disappearSettings, imageEffect, imageEffectSettings, height, width
  3. Chama this._manager.syncAllElements() para atualizar todos os elementos
     DOM <img> com os novos dados.
  4. Nota: height = containerHeight * (sizePercent/100). width = height
     (sem calculo de aspect ratio por limitacao sincrona).

10.2. undo()

  1. Itera sobre this._oldStampsSnapshots.
  2. Para cada snapshot, obtem o stamp atual por ID.
  3. Se existir, aplica Object.assign(stamp, snapshot) para restaurar.
  4. Chama syncAllElements() para atualizar DOM.

10.3. redo()

  Chama execute() diretamente.

10.4. _applyConfig(stamp)

  Metodo privado que aplica a nova configuracao a um stamp individual.
  Configura todas as propriedades baseadas no slot config. A altura e
  recalculada com base no sizePercent e na altura atual do canvas-area.

12. CUIDADOS IMPORTANTES RELACIONADOS AO UNDO/REDO
================================================================================

  1. ReplaceSlotStampsCommand gera UMA unica entrada no historico,
     independente de quantos stamps foram atualizados.

  2. O snapshot salvo em this._oldStampsSnapshots contem deep copies
     completos de cada stamp antes da alteracao.

  3. Ao desfazer (undo()), os stamps sao restaurados via Object.assign().
     Como o ID do stamp nao muda, o elemento DOM correspondente e
     encontrado e atualizado via syncAllElements().

  4. Ao refazer (redo()), execute() e chamado novamente, reaplicando a
     configuracao a todos os stamps do slot.

  5. O toggle "Replace Existing Stamps" NAO e restaurado pelo Undo.
     Apos a confirmacao, config.replaceExisting = false e salvo.
     Undo/Redo nao afeta o estado do toggle (que e gerenciado pelo
     StampSettingsManager, nao pelo comando).

  6. Se o usuario fizer Undo apos a substituicao, os stamps voltam ao
     estado anterior, mas o toggle permanece desativado. Isso e
     intencional (conforme especificacao).

14. CUIDADOS PARA EVITAR REGRESSOES
================================================================================

  1. _checkSlotReplaceConfirmation so dispara se config.replaceExisting for
     true. Alteracoes sem o toggle ativo nao sao afetadas.

  2. replaceExisting e uma propriedade do slot, independente por slot.
     A alteracao no Slot 1 nunca afeta o Slot 2.

  3. A substituicao nunca recria stamps. Ela sempre atualiza in-place
     (modifica o objeto stamp em EditorState.stamps.list e depois
     sincroniza o DOM).

  4. syncAllElements() atualiza todos os stamps no DOM. Se houver muitos
     stamps, isso pode ser custoso, mas evita inconsistencia.

  5. O comando usa deep copies (JSON.parse(JSON.stringify())) para snapshots.
     Nao ha risco de referencia compartilhada.

  6. A funcao _checkSlotReplaceConfirmation e chamada APOS a configuracao
     ja ter sido salva. Se o usuario cancelar, a configuracao permanece
     alterada (os proximos stamps usarao a nova config), mas os stamps
     existentes nao sao modificados.

  7. O callback de change do size slider dispara confirmacao. O callback
     de input (arrasto continuo) nao dispara confirmacao, apenas salva a
     configuracao.

  8. Apos confirmacao, renderImageSlots() e chamado para atualizar o
     checkbox do toggle na interface. Isso recria todo o DOM dos slots.

  9. O metodo _slotApplyLink carrega a imagem primeiro (onload), depois
     salva config e entao chama _checkSlotReplaceConfirmation. Isso
     garante que a imagem esteja valida antes de qualquer acao.

  10. upload e link sao tratados como "imagem/GIF". Alterar source sempre
      dispara confirmacao se toggle estiver ativo.

  11. A notificacao de "Slot nao possui imagem" aparece APENAS se o toggle
      estiver ativo e config.source for null/undefined. Isso evita
      notificacoes indesejadas durante configuracao normal.

  12. O metodo _checkSlotReplaceConfirmation faz return ao inves de
      continuar se config.replaceExisting for false. Isso significa que e
      seguro chama-lo apos qualquer alteracao.

17. PROBLEMAS COMUNS QUE DEVEM SER EVITADOS
================================================================================

  1. NAO confundir o comportamento de substituicao em massa com insercao
     de novos stamps. A substituicao ocorre quando configuracao e alterada,
     nao quando um novo stamp e inserido.

  2. NAO usar removeStamp/addStamp para substituicao. Sempre atualizar
     in-place para preservar ID, zIndex e referencias DOM.

  3. NAO esquecer de chamar syncAllElements() apos qualquer alteracao em
     massa. O estado do EditorState e o DOM devem estar sempre em sync.

  4. NAO disparar confirmacao para alteracoes que nao sao relevantes
     (ex: alterar keybind do slot nao deve disparar confirmacao).

  5. NAO permitir que Undo/Redo reative o toggle. O toggle e gerenciado
     pelo StampSettingsManager, nao pelos comandos.

  6. NAO deep-copiar o this._newConfig sem JSON.parse(JSON.stringify()).
     Referencias a effectSettings podem ser compartilhadas.

  7. Cuidado ao chamar _checkSlotReplaceConfirmation de dentro de loops
     ou handlers que modificam config. A funcao pode modificar config
     (desativar replaceExisting) e chamar renderImageSlots().

  8. _checkSlotReplaceConfirmation usa confirm() que e bloqueante. Nao
     chama-lo de dentro de um requestAnimationFrame ou callback assincrono.
