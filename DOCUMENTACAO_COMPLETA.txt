===== CAPA E VISÃO GERAL DO PROJETO =====

Nome do Projeto:    DeutschMeister
Tipo:               Aplicação Web Single-Page (SPA), HTML + CSS + JS vanilla
Arquivo Fonte:      deutsch-meister.html (~3088 linhas)
Objetivo:           Ensinar alemão do nível A1 (iniciante) ao B1 (intermediário)
                    seguindo o padrão CEFR (Quadro Europeu Comum de Referência).
                    Totalmente offline, progresso salvo em localStorage.
Tecnologias:        HTML5, CSS3 (variáveis CSS, flexbox, grid), JavaScript ES6+
                    Sem frameworks ou bibliotecas externas.
Navegadores:        Chrome, Firefox, Edge, Safari (modernos)
Licença:            DeutschMeister © 2026 — Projeto educacional gratuito

Features principais:
  - 20 capítulos com teoria, exercícios interativos e mini testes
  - Treinador de conjugação verbal com 50+ verbos
  - Glossário pesquisável com 190+ palavras
  - Sistema de progresso com salvamento automático (localStorage)
  - Internacionalização (Português / English)
  - Modo escuro (dark mode)
  - Exportação/importação de progresso
  - Sidebar de navegação com busca de capítulos
  - Sistema de anotações pessoais
  - "Base Fundamental" com 7 seções de pré-conhecimento
  - Código de desbloqueio (cheat code) para acesso completo

  const VOCAB_UNIQUE = Object.values(

  );

2.3 OBJETO EX (EXERCÍCIOS EM PORTUGUÊS)

Estrutura: EX[chapterId] = array de exercícios

Cada exercício é um objeto com os seguintes campos:
  {
    q:       string,          // pergunta (enunciado)
    qPt:     string (opc),    // pergunta em português (para ordenação)
    qEn:     string (opc),    // pergunta em inglês (para ordenação)
    a:       number|string,   // resposta: índice (m) ou string (t)
    alts:    string[] (opc),  // respostas alternativas aceitas
    opts:    string[] (opc),  // opções de múltipla escolha
    h:       string|string[], // dica(s) — pode ser string única ou array
    t:       string,          // tipo: 'm' (múltipla) | 't' (texto) | 'o' (ordenação)
    w:       string[] (opc),  // banco de palavras (ordenação)
    correct: string[] (opc),  // ordem correta das palavras
    explain: string (opc),    // explicação rica em HTML
    meanings: object (opc)    // significados das palavras no banco
  }

Tipos de exercício (campo t):
  'm' = múltipla escolha (Multiple choice)
        - Usa campo opts (array de opções) e a (índice da correta)
        - Renderizado como botões clicáveis

  't' = texto (Text input)
        - Usa campo a (resposta esperada) e alts (alternativas aceitas)
        - Renderizado como input text + botão verificar
        - Comparação flexível via isSimilar() com normalização

  'o' = ordenação (Ordering / word bank)
        - Usa campo w (todas as palavras disponíveis), correct (ordem correta)
        - Renderizado como word tiles + slot container
        - Palavras são embaralhadas aleatoriamente a cada renderização

Número de exercícios por capítulo (EX):

2.4 OBJETO EX_EN (EXERCÍCIOS EM INGLÊS)

Estrutura idêntica a EX, mas com perguntas, dicas e opções em inglês.
Nem todos os capítulos têm versão em inglês de todos os exercícios.
Os exercícios de ordenação (tipo 'o') podem ter menos entradas em EX_EN,
pois a tradução pode simplificar. A função getEx(chId) seleciona EX_EN
se state.lang === 'en' e o capítulo existir em EX_EN; caso contrário,
retorna EX[chId] como fallback.

2.5 OBJETO TH / THEORY (TEORIA EM PORTUGUÊS)

Estrutura: TH[chapterId] = string HTML completa

Cada entrada contém a teoria completa do capítulo em português,
formatada com classes CSS do sistema:
  - <h3>, <h4> para títulos
  - <table> para tabelas (artigos, conjugações, preposições)
  - <div class="example"> para exemplos com destaque
  - <div class="note"> para notas e observações importantes
  - <span class="de"> e <span class="pt"> para pares de tradução
  - <strong> para ênfase
  - <p> para parágrafos

O HTML da teoria é injetado diretamente no DOM dentro de div.theory-box.

2.6 OBJETO TH_EN (TEORIA EM INGLÊS)

Estrutura idêntica a TH mas em inglês.
Função getTh(chId) seleciona TH_EN se state.lang === 'en', senão TH.

2.7 OBJETO REVIEW / REVIEW_EN (REVISÕES POR CAPÍTULO)

Estrutura: REVIEW[chapterId] = string HTML (<li>...</li>)
Cada entrada contém de 2 a 5 itens de revisão resumindo o capítulo.
Usa getReviewContent(id) que retorna REVIEW_EN se state.lang === 'en'.

2.8 OBJETO LANG (INTERNACIONALIZAÇÃO)

Estrutura: LANG = { pt: {...}, en: {...} }

Contém ~90 pares chave-valor em pt e en. As chaves seguem o padrão:
  categoria.subcategoria  (ex: 'nav.settings', 'exercises.check')

Categorias de chaves:
  nav.*           — Navegação (menu, settings)
  sidebar.*       — Sidebar (title, search)
  settings.*      — Painel de configurações
  cover.*         — Capa/hero
  intro.*         — Seção de introdução
  toc.*           — Sumário (TOC)
  glossary.*      — Glossário
  notes.*         — Anotações
  conclusion.*    — Tela de conclusão
  footer          — Rodapé
  exercises.*     — Exercícios (labels, botões, feedback)
  minitest.*      — Mini testes
  chapter.*       — Capítulos (locked, review, theory)
  toast.*         — Notificações toast
  reset.confirm   — Confirmação de reset

Função _t(key):
  - Busca LANG[state.lang][key]
  - Se não encontrado, fallback para LANG.pt[key]
  - Se não encontrado, retorna a própria key

2.9 OBJETO STATE (ESTADO GLOBAL DA APLICAÇÃO)

Estrutura:
  state = {
    completed:  {},       // { chapterId: true } — capítulos concluídos
    progress:   {},       // { chapterId: { exercisesDone: n, exerciseTotal: m, testPassed: bool } }
    favorites:  [],       // Array de strings (palavras em alemão favoritas)
    notes:      '',       // String com anotações pessoais
    darkMode:   false,    // Modo escuro ativo
    adaptive:   true,     // Dificuldade adaptativa (toggle, não implementado ativamente)
    lang:       'pt'      // Idioma atual ('pt' | 'en')
  }

Persistência:
  - loadState(): carrega de localStorage['deutschmeister_state']
  - saveState(): salva em localStorage['deutschmeister_state']
  - Ambos usam try/catch para segurança (storage pode estar cheio ou indisponível)

2.10 OBJETO VERB_DB (BANCO DE CONJUGAÇÃO VERBAL)

Estrutura de cada verbo:
  {
    infinitive:  string,       // nome da chave e também campo interno
    conj:        string[6],    // [ich, du, er/sie/es, wir, ihr, sie/Sie]
    type:        string,       // 'regular'|'irregular'|'modal'|'separable'|'inseparable'|'mixed'|'auxiliary'
    pattern:     string,       // descrição do padrão (ex: 'standard -en', 'e→i (strong)')
    meaning:     {pt, en},     // significado
    chapters:    number[],     // capítulos onde aparece (ex: [5, 9])

===== 3. BASE FUNDAMENTAL (PRÉ-CAPÍTULOS) =====

A seção #base-fundamental contém 7 subseções teóricas que introduzem
conceitos essenciais ANTES do primeiro capítulo. O conteúdo é hardcoded
em português (NÃO é internacionalizado) diretamente no HTML.

As 7 seções são renderizadas como div.theory-box dentro da section.

3.1 SEÇÃO 1: PRONÚNCIA ALEMÃ — OS SONS QUE ENGANAM BRASILEIROS

Conteúdo:
  - Tabela com 13 sons problemáticos:
    ch (após i/e/ä/ö/ü): "rr" suave (ich)
    ch (após a/o/u): gutural (Buch)
    r: vibrante na garganta (rot)
    ü: boca de "u" mas som de "i" (grün)
    ö: boca de "ô" mas som de "ê" (schön)
    ä: som aberto "é" (Mädchen)
    ei: pronuncia-se "ai" (mein)
    ie: pronuncia-se "i" longo (Liebe)
    eu/äu: pronuncia-se "ói" (Europa, Häuser)
    sch: sempre "x" (Schule)
    W: sempre "v" (Wasser)
    V: geralmente "f" (Vogel)
    ß: sempre "ss" (Straße)
  - Nota com erros comuns de brasileiros (W como "u", V como "v", ei como "êi", ie como "ai")
  - Curiosidade sobre a suavidade do alemão

3.2 SEÇÃO 2: COMO DETECTAR VERBOS — O NÚCLEO DA FRASE

Conteúdo:
  - Infinitivos: -en (machen, gehen), -ern (ändern), -eln (lächeln)
  - Verbos conjugados (ich gehe, du lernst, er wohnt)
  - Verbos separáveis: aufstehen → Ich stehe ... auf
                     einkaufen → Wir kaufen ... ein
  - Dica essencial: "caçar o verbo" na posição 2 e no final

3.3 SEÇÃO 3: ESTRUTURA DAS FRASES — A REGRA DE OURO

Conteúdo:
  - REGRA: O verbo conjugado SEMPRE ocupa a 2ª posição (orações principais)
  - Frases declarativas: [1: Sujeito] [2: Verbo] [3+: Complementos]
  - Inversão: [1: Heute] [2: lerne] [3: ich]
  - Perguntas Sim/Não: verbo na posição 1
  - W-Fragen: W + verbo + sujeito
  - Subordinadas: verbo vai para o FINAL (weil, dass)
  - Tabela resumo: Declarativa(2ª), Sim/Não(1ª), W-Frage(2ª após W), Subordinada(Final)
  - Nota: português é SVO, alemão tem verbo "dançante"

3.4 SEÇÃO 4: ARTIGOS E GÊNEROS — O PESADELO QUE TEM SOLUÇÃO

Conteúdo:
  - Tabela dos 3 gêneros: der (masc), die (fem), das (neutro) com exemplos
  - Regra de ouro: NUNCA aprenda substantivos sozinhos, sempre COM artigo
  - Padrões de terminação:
    Masculino: -er, -el, -en, -ling, -ismus, -ant
    Feminino:  -e, -ung, -heit, -keit, -schaft, -ion, -tät, -ik
    Neutro:    -chen, -lein, -um, -ment, -tum, -nis
  - Curiosidade: Mädchen é neutro (das), não feminino (sufixo -chen sempre neutro)

3.5 SEÇÃO 5: CASOS GRAMATICAIS — DE FORMA SIMPLES

Conteúdo:
  - Tabela dos 3 casos principais:
    Nominativ: Sujeito (quem faz), pergunta Wer?
    Akkusativ: Objeto direto (quem recebe), pergunta Wen?
    Dativ:     Objeto indireto (para quem), pergunta Wem?
  - Exemplo: Der Mann sieht den Hund
    der Mann = Nominativ (sujeito)
    den Hund = Akkusativ (objeto direto)
    der → den (única mudança visível: artigo masculino no acusativo)
  - Nota tranquilizadora: não precisa decorar tudo agora

3.6 SEÇÃO 6: VOCABULÁRIO ESSENCIAL — SUAS PRIMEIRAS PALAVRAS

Conteúdo:
  - Tabela com 20 palavras/frases essenciais:
    Hallo, Tschüss, Bitte, Danke, Ja/Nein, Ich, sein, haben, gehen,
    kommen, machen, sprechen, und/oder/aber, Wie?/Wo?/Was?/Wer?
  - Exemplo de diálogo simples: Hallo! Ich heiße [nome]. Wie geht es Ihnen?

Short EN:   Present

4.9 CAPÍTULO 9: DAS PERFEKT (A2)

Nome:       Das Perfekt
Nível:      A2 — Básico
Objetivo:   Passado com haben/sein e Partizip II
Short PT:   Perfekt
Short EN:   Perfekt

Teoria (TH[9] / TH_EN[9]):

  - Verbos em -ieren NÃO recebem ge- (studieren → studiert)
  - Regra haben vs. sein:
    haben: verbos transitivos, reflexivos, modais

Revisão (3 itens):
  - Perfekt = haben/sein + Partizip II
  - Partizip regular: ge- + radical + -t; irregular: ge- + radical(mod) + -en
  - Movimento/mudança de estado: sein; demais: haben

4.11 CAPÍTULO 11: DER DATIV (A2)

Revisão (3 itens):
  - Dativo: der→dem, die→der, das→dem, Plural→den + -n
  - Verbos com dativo: danken, helfen, gefallen, gehören
  - Pessoa (DAT) + Coisa (AKK)

4.12 CAPÍTULO 12: MODALVERBEN (A2)

Nome:       Modalverben
Nível:      A2 — Básico
Objetivo:   Verbos modais: können, müssen, dürfen, sollen, wollen, mögen
Short PT:   Modais
Short EN:   Modals

Teoria (TH[12] / TH_EN[12]):

4.13 CAPÍTULO 13: PRÄPOSITIONEN (A2)

Nome:       Präpositionen
Nível:      A2 — Básico

Short PT:   Preposições
Short EN:   Prepositions

Revisão (3 itens):

4.14 CAPÍTULO 14: TRENNBARE VERBEN (A2)

Nome:       Trennbare Verben
Nível:      A2 — Básico
Objetivo:   Verbos separáveis no presente e Perfekt
Short PT:   Separáveis
Short EN:   Separable

Teoria (TH[14] / TH_EN[14]):

Revisão (3 itens):
  - Prefixos: an-, auf-, aus-, ein-, mit-, etc.

  - Perfekt: prefixo + ge- + radical (aufgestanden)

===== 5. SISTEMA DE EXERCÍCIOS =====

5.1 TIPOS DE EXERCÍCIO

O sistema suporta 3 tipos de exercício, identificados pelo campo 't':

  'm' (múltipla escolha / multiple choice):
    - O usuário clica em um botão entre várias opções
    - Resposta correta: ex.a (índice no array ex.opts)
    - Após clique, todos os botões são desabilitados
    - Botão correto fica verde (.correct)
    - Botão errado fica vermelho (.wrong)
    - Demais ficam com opacity 0.5

  't' (texto / text input):
    - O usuário digita a resposta em um campo <input type="text">
    - Comparação flexível via isSimilar(): normalização + array de alternativas
    - Campo fica verde (.correct) ou vermelho (.wrong)
    - Se a distância Levenshtein <= 2, mostra "Quase lá!"
    - Aceita alternativas listadas em ex.alts

  'o' (ordenação / ordering):
    - Banco de palavras (word bank) embaralhado aleatoriamente
    - O usuário clica nas palavras para movê-las para o slot container
    - Pode remover palavras do slot clicando nelas
    - Botão "Resetar" limpa os slots
    - Comparação: userWords.join(' ') vs correctWords.join(' ')
    - Aceita ordenações alternativas em ex.correctAlts

5.2 ESTRUTURA DE DADOS DE UM EXERCÍCIO

  {
    q:        string,           // Enunciado da pergunta (obrigatório)
    qPt:      string (opc),     // Pergunta em PT para ordenação
    qEn:      string (opc),     // Pergunta em EN para ordenação
    t:        string,           // 'm' | 't' | 'o' (obrigatório)
    a:        number|string,    // Resposta (índice para 'm', string para 't')
    alts:     string[] (opc),   // Respostas alternativas aceitas ('t')
    opts:     string[] (opc),   // Opções ('m')
    h:        string|string[],  // Dica(s) — string ou array
    w:        string[] (opc),   // Banco de palavras ('o')
    correct:  string[] (opc),   // Ordem correta ('o')
    correctAlts: string[] (opc),// Ordens alternativas aceitas ('o')
    meanings: object (opc),     // Significados {word: {pt, en}} ('o')
    explain:  string (opc),     // Explicação rica em HTML
    tried:    number (opc)      // Contador de tentativas (runtime)
  }

5.3 FLUXO DE VERIFICAÇÃO

checkMulti(chId, i, idx):
  1. Obtém exercício de getEx(chId)[i]
  2. Desabilita todos os botões
  3. Marca botão correto (j === ex.a) com classe 'correct'
  4. Marca botão clicado como 'wrong' se errado
  5. Mostra feedback no elemento #fb-{chId}-{i}
  6. Exibe toast (correto/errado)
  7. Chama trackExercise(chId, correct)

checkTranslate(chId, i):
  1. Obtém valor do input #input-{chId}-{i}
  2. Compara com ex.a e ex.alts via isSimilar()
  3. Aplica classe 'correct' ou 'wrong' ao input
  4. Se errou, calcula distância Levenshtein e mostra "Quase lá!"
  5. Mostra feedback com buildExplanation()
  6. Toast e trackExercise

checkOrder(chId, i):
  1. Coleta palavras dos slots no container #slots-{chId}-{i}
  2. Junta com espaço: userWords.join(' ')
  3. Compara com ex.correct.join(' ') e ex.correctAlts (se existir)
  4. Normaliza ambas as strings antes de comparar
  5. Mostra feedback com buildExplanation()
  6. Toast e trackExercise

5.4 SISTEMA DE DICAS (HINTS)

Função showHint(chId, i):
  - Container: #hints-{chId}-{i}
  - As dicas são elementos <p class="ex-hint-item"> inicialmente ocultos (display:none)
  - Cada clique revela a próxima dica (adiciona classe .show)
  - Animação: hintIn (fade + slide da esquerda)
  - As dicas vêm de ex.h, que pode ser string única ou array

5.5 SISTEMA DE FEEDBACK E EXPLICAÇÕES

Ver seção 7 completa abaixo.

5.6 SISTEMA DE RASTREAMENTO (TRACKEXERCISE)

Função trackExercise(chId, correct):
  1. Inicializa state.progress[chId] se necessário
  2. Incrementa p.exerciseTotal
  3. Se correto, incrementa p.exercisesDone
  4. Salva estado (saveState)
  5. Atualiza UI global (updateAll)

===== 6. SISTEMA DE MINI TESTES =====

6.1 ESTRUTURA E PROPÓSITO

Cada capítulo tem um mini teste final que aparece após a revisão.
É necessário passar no mini teste para:
  - Marcar o capítulo como concluído (state.completed[chId] = true)
  - Desbloquear o próximo capítulo (isUnlocked)

6.2 SELEÇÃO DE PERGUNTAS

Função renderMiniTest(chId):
  - Obtém os exercícios do capítulo: getEx(chId)
  - Seleciona os 3 primeiros: testExs = exs.slice(0, 3)
  - Se não houver exercícios, mostra "Nenhum teste disponível"
  - Renderiza cada pergunta com:
    - Múltipla escolha: botões clicáveis com checkMTMulti
    - Texto: input + botão verificar com checkMTTranslate
  - Cada pergunta tem seu próprio feedback (#mt-fb-{chId}-{i})

6.3 FLUXO DE SUBMISSÃO (submitMiniTest)

Função submitMiniTest(chId):
  1. Coleta todos os feedbacks: $$('[id^="mt-fb-{chId}"]')
  2. Verifica se TODOS foram respondidos (fb.dataset.done existe)
     Se não: toast de erro "Responda todas as perguntas!"
  3. Verifica se PELO MENOS UMA está correta (fb.dataset.done === 'ok')
     Se não: toast de erro "Você precisa acertar pelo menos uma!"
  4. Se passou:
     a. state.progress[chId].testPassed = true
     b. state.completed[chId] = true
     c. saveState() — salva em localStorage
     d. updateAll() — atualiza UI
     e. toast de sucesso "Capítulo concluído!"
     f. renderChapters() — re-renderiza (atualiza lock states)

6.4 CONDIÇÕES DE APROVAÇÃO

Para passar no mini teste é necessário:
  1. Responder TODAS as perguntas (não deixar nenhuma em branco)
  2. Acertar PELO MENOS UMA pergunta

Isso significa que o usuário pode errar 2 de 3 e ainda assim passar,
desde que acerte ao menos 1. Esta é uma decisão de design para não
frustrar o aluno e manter o fluxo de progresso.

As respostas do mini teste são independentes dos exercícios regulares
— o dataset.done no elemento de feedback controla o estado.

===== 7. SISTEMA DE FEEDBACK E EXPLICAÇÕES (buildExplanation) =====

7.1 ESTRUTURA GERAL

Função: buildExplanation(ex, correct, userAnswer)
Retorna: string HTML com explicação completa

Parâmetros:
  ex:         objeto do exercício
  correct:    boolean — se o usuário acertou
  userAnswer: any — resposta do usuário (índice, string ou array)

Fluxo geral:
  1. Determina idioma (isEn = state.lang === 'en')
  2. Se ex.explain existe (explicação rica pré-escrita):
     - Renderiza explicação personalizada + dica de melhoria
  3. Senão, gera explicação dinâmica por tipo (m/t/o):
     a. answerHtml: mostra resposta correta e resposta do usuário
     b. explainHtml: explicação detalhada com regras
     c. tipHtml: dica de melhoria (erro) ou reforço (acerto)

7.2 EXPLICAÇÕES PARA MÚLTIPLA ESCOLHA (TIPO 'm')

Componentes:
  1. Título: "Aprenda com isso:" ou "Learn from this:"
  2. Resposta correta destacada em verde
  3. Se errou: mostra opção selecionada em vermelho
  4. Se acertou: mostra "Escolha certa!" em verde
  5. Sistema de profundidade (depth):
     - Calculado pelo nível do capítulo:
       A1 → depth=3 (máxima explicação)
       A2 → depth=2 (explicação média)
       B1 → depth=1 (explicação concisa)
     - Controla quantas dicas são mostradas
     - depth >= 2: adiciona caixa de regra-chave (ruleHtml)
     - depth >= 3 && correct: adiciona curiosidade "Sabia que?"
  6. Regra-chave categorizada por palavras-chave na pergunta:
     - pronúncia → regra de pronúncia
     - artigo → regra de gênero
     - conjug/verbo → regra de conjugação
     - número/number/zahl → regra dos números (unidade antes da dezena)
     - preposição → regra de caso
     - caso/acusativo/dativo → regra de caso
     - ordem/frase/sentence → regra da 2ª posição
     - traduz/significa → dica de construção de resposta
     - fallback: padrões específicos do alemão

7.3 EXPLICAÇÕES PARA TEXTO (TIPO 't')

Detecção de tipo de pergunta:
  - Se a pergunta contém "conjug" (conjugação):
    - Extrai nome do verbo entre aspas
    - Extrai pessoa (1ª, 2ª, 3ª)
    - Mostra tabela de conjugação completa do verbo
    - Tabelas pré-definidas para: sein, haben, werden, modais
    - Para outros verbos: gera padrão regular (stem + terminações)
    - Dicas numeradas (1️⃣, 2️⃣, 3️⃣) passo a passo
  - Se a pergunta é de tradução:
    - Extrai palavra-alvo entre aspas
    - Categoriza por tipo: artigo, plural, preposição, pronome,
      possessivo, separável, passiva, relativa, Konjunktiv
    - Cada categoria tem explicação específica de regra
    - Tabela de referência de artigos (der/die/das/ein/eine/einen/dem/den)
    - Dicas do exercício
    - Alternativas aceitas (ex.alts)
    - Se acertou: "Preste atenção na estrutura"
    - Se errou: "Compare sua resposta com a esperada"

7.4 EXPLICAÇÕES PARA ORDENAÇÃO (TIPO 'o')

Componentes:
  1. Ordem correta destacada em ciano
  2. Se errou: ordem do usuário em vermelho
  3. Análise palavra por palavra:
     - Cada palavra recebe um papel gramatical:
       sujeito/tópico, verbo (posição 2), complemento,
       conjunção subordinativa, prefixo separável (final)
     - Detecta posição do verbo e mostra posição correta
  4. Regras aplicadas (das dicas do exercício)
  5. Significado dos blocos (do campo meanings):
     - Tabela com todas as palavras do banco
     - ✅ nas palavras usadas na ordem correta
     - Tradução PT ou EN conforme idioma
  6. Se acertou: "Verbo na segunda posição — espinha dorsal"
  7. Se errou: dica de posição do verbo com palavra e posição corretas

7.5 SISTEMA DE PROFUNDIDADE ADAPTATIVA (DEPTH)

O depth é calculado com base no nível CEFR do capítulo:
  A1 → depth = 3 (explicação mais rica, com curiosidades)
  A2 → depth = 2 (explicação média)
  B1 → depth = 1 (explicação concisa, foco na regra)

Isso afeta:
  - Quantas dicas são exibidas (depth > 1 || i < 2)
  - Se a regra-chave é mostrada (depth >= 2)
  - Se a curiosidade "Sabia que?" aparece (depth >= 3 && correct)

7.6 CATEGORIZAÇÃO INTELIGENTE DE REGRAS (ruleHtml)

O sistema analisa a pergunta (q.toLowerCase()) com regex para
determinar qual regra-chave exibir:
  /pronunc/i      → Regra de pronúncia
  /artigo|article/i → Regra de gênero (der/die/das)
  /conjug|verbo|verb/i → Regra de conjugação
  /número|number|zahl/i → Regra dos números (unidade antes da dezena)
  /preposição|preposition/i → Regra de caso com preposições
  /caso|case|acusativo|accusative|dativo|dative|nominativo|nominative/i → Regra de caso
  /ordem|ordena|word.order|sentence|frase|satz/i → Regra da 2ª posição
  /traduz|translate|significa|means/i → Dica de construção
  fallback → Padrões específicos do alemão

7.7 DICAS DE MELHORIA PÓS-ERRO (tipHtml)

Se errou:
  - Caixa com borda vermelha: "Como melhorar:"
  - Mensagem: "Leia a explicação. Identifique a regra específica.
    Pratique criando frases similares."

Se acertou:
  - Caixa com borda verde: "Você entendeu!"
  - Mensagem: "Revisar até respostas corretas fortalece conexões neurais."

===== 8. TREINADOR DE CONJUGAÇÃO (CONJUGATION TRAINER) =====

8.1 BANCO DE DADOS VERB_DB

Ver seção 2.10 para estrutura completa. O banco contém 50+ verbos
com todas as 6 formas de conjugação no presente.

8.2 TIPOS DE VERBOS

Cada verbo tem um campo 'type' que determina seu comportamento:

  'regular':
    - Segue o padrão: radical + e, st, t, en, t, en
    - Maior família, mais previsível
    - Variações: t-stem (arbeiten), s-stem (heißen, reisen), d-stem (finden)
    - Ex: lernen, machen, kommen, gehen, wohnen

  'irregular' (forte):
    - Mudança de vogal no radical na 2ª e 3ª pessoa singular
    - Campo vowelChange: {du: novaVogal, er: novaVogal}
    - 3 padrões principais:
      e→i:  sprechen→sprichst, essen→isst, helfen→hilfst, geben→gibst
      a→ä:  fahren→fährst, schlafen→schläfst, tragen→trägst
      e→ie: lesen→liest, sehen→siehst
    - Plural retorna à vogal original

  'modal':
    - 6 verbos: können, müssen, dürfen, sollen, wollen, mögen
    - Singular (ich, er): radical modificado SEM terminação
    - Plural (wir, ihr, sie): radical com trema + terminações
    - Acompanham infinitivo no final da frase

  'separable' (separável):
    - Prefixo + verbo base (ex: auf + stehen)
    - Conjugação: verbo base conjugado + espaço + prefixo no final
    - Campo prefix indica o prefixo
    - Campo baseVerb indica o verbo base
    - No Perfekt: prefixo + ge + radical (aufgestanden)

  'auxiliary':
    - sein, haben
    - Completamente irregulares (formas supletivas)
    - Essenciais para formar Perfekt, futuro, passiva

  'mixed':
    - backen: aceita tanto "backst" (regular) quanto "bäckst" (com trema)

  'inseparable':
    - Prefixo NUNCA se separa (be-, er-, ver-, zer-, ent-, emp-, ge-, miss-)
    - NÃO recebem ge- no Partizip
    - Ex: besuchen → besucht (não "gebesucht")

8.3 SISTEMA DE DICAS POR PRONOME (getConjHint)

Função getConjHint(verb, pronounId, isEn):
  - Gera dicas ESPECÍFICAS para cada pronome, baseadas no tipo do verbo
  - As dicas NÃO revelam a resposta, apenas guiam o raciocínio

Para AUXILIARES:
  - ich: "forma curta de 3 letras começando com b" (bin)
  - du: "adicione -st a uma base curta começando com b" (bist)
  - er: "forma de 3 letras, como 'is' em inglês" (ist)
  - wir/sie: "forma de 4 letras começando com s" (sind)

Para MODAIS:
  - ich: "forma curta (3-4 letras), sem terminação"
  - du: "radical do ich + -st"
  - er: "IDÊNTICO ao ich — sem terminação!"
  - wir: "retorna à forma do infinitivo (com trema)"

Para SEPARÁVEIS:
  - Todas as dicas lembram: "conjugue o verbo base primeiro,
    depois escreva o prefixo SEPARADO no final"
  - Inclui o nome do prefixo na dica

Para IRREGULARES:
  - ich/wir/ihr/sie: "vogal NÃO muda, use radical do infinitivo"
  - du/er: "vogal MUDA! A vogal se torna '{vogal}' antes da terminação"

Para REGULARES:
  - ich: "remova -en, adicione -e"
  - du: "remova -en, adicione -st (cuidado com t, d, s, ß, z → -e- extra)"
  - er: "remova -en, adicione -t"
  - wir/sie: "use a forma do infinitivo"

Dicas específicas por verbo (specificHint):
  - sein: referência ao inglês "is", "am"
  - haben: "b" desaparece no du/er
  - sprechen: "e vira i"
  - lesen: "e vira ie E o s muda"
  - nehmen: "h cai, e→i, m duplica"
  - werden: "e→i E d é removido"
  - wissen: "usa ß no singular, comporta-se como modal"

As dicas aparecem ao lado do input por 8 segundos (setTimeout),
depois desaparecem automaticamente.

8.4 SISTEMA DE FEEDBACK POR CONJUGAÇÃO (buildConjFeedback)

Função buildConjFeedback(verb, pronounId, userAnswer, isCorrect, isEn):
  Retorna HTML completo com feedback por pronome.

Se CORRETO:
  - Título verde com a forma correta
  - Explicação do porquê baseada no tipo do verbo
  - Tabela de conjugação completa com destaque na forma correta
  - Verbos relacionados (se existir)
  - Exemplo em contexto (se existir)
  - Mensagem de reforço: "Cada conjugação correta fortalece seu modelo mental"

Se INCORRETO:
  - Título vermelho
  - Resposta do usuário (tachada) vs. resposta correta
  - ANÁLISE PERSONALIZADA DO ERRO (ver 8.5)
  - Tabela de conjugação completa
  - Exemplo em contexto
  - Dica prática: "Escreva a forma correta 3 vezes à mão"

8.5 ANÁLISE PERSONALIZADA DE ERROS

O sistema identifica o tipo de erro e dá feedback específico:

  Se campo vazio:
    "Você deixou este campo vazio. Tentar (mesmo errando)
     ajuda mais o cérebro do que evitar."

  Se verbo separável sem prefixo:
    "⚠️ Você esqueceu o prefixo separável! O prefixo DEVE
     aparecer no final com espaço."

  Se verbo separável com prefixo no início:
    "⚠️ O prefixo está no começo! Conjugue o verbo base
     primeiro, prefixo no FINAL."

  Se verbo irregular sem mudança vocálica:
    "⚠️ Você perdeu a mudança vocálica! Em '{pronoun}',
     a vogal se torna '{vogal}' antes da terminação."

  Se modal no singular:
    "Modais no singular NÃO têm terminação — apenas radical modificado."

  Se auxiliar:
    "Forma supletiva — sem conexão com o infinitivo. Memorização pura."

  Se regular com radical dental/sibilante:
    "⚠️ Regra de pronúncia! Radical termina em {letra} →
     insira -e- extra antes da terminação."

Esta análise comparativa é um dos diferenciais pedagógicos do sistema.

8.6 SISTEMA DE VERBOS SIMILARES (getSimilarVerbs, getVerbSimilarityScore)

Função getVerbSimilarityScore(verbA, verbB):
  Calcula pontuação de similaridade entre dois verbos:
    +3: mesmo tipo (regular, irregular, etc.)
    +5: mesmo padrão de mudança vocálica (ex: ambos e→i)
    +2: mudança vocálica parcialmente igual
    +3: mesmo padrão de conjugação
    +5: mesmo prefixo separável
    +4: mesmo verbo base (para separáveis)
    +4: ambos modais
    +2: mesmo auxiliar de Perfekt
    +2: mesmo padrão de radical (t-stem, s-stem)
    +2: mesmo caso regido

Função getSimilarVerbs(currentVerb, allVerbs, isEn):
  - Filtra e ordena verbos por similaridade
  - Seleciona top 3 com score >= 3
  - Para cada similar, gera razões textualmente
  - Usado no Deep Dive para mostrar verbos parecidos

8.7 DEEP DIVE EDUCACIONAL (generateVerbDeepDive)

Função generateVerbDeepDive(verb, chId, vIdx, isEn):
  Gera um painel educacional expansível para cada verbo com:

  1. Header: "Explorando o verbo {infinitivo}" com subtítulo

  2. Overview cards (4 cards em grid):
     - Tipo (regular, irregular, modal, etc.)
     - Significado (com exemplo)
     - Frequência (★ a ★★★★★)
     - Perfekt (Partizip II + auxiliar, se disponível)

  3. Uso e Comportamento:
     - Dados do VERB_EDUCATION (uso detalhado)
     - Ou descrição genérica baseada no tipo

  4. Dica de Memorização (memoryTip):
     - Do VERB_EDUCATION, com insights linguísticos

  5. Verbos Parecidos — Análise Comparativa:
     - Para cada verbo similar (top 3):
       - Tabela comparativa lado a lado das 6 conjugações
       - Destaque nas linhas du/er (highlight-row)
       - Razão da similaridade
       - Insight do padrão compartilhado
       - Aviso: "Não misture! Cada verbo tem suas próprias formas."

  6. Em Contexto — Uso Real:
     - Exemplo do banco (verb.example)
     - Exemplo extra hardcoded (extraEx) para verbos selecionados

  7. Expressões Comuns (commonPhrases):
     - Do VERB_EDUCATION, lista de frases

  8. Você Sabia? (funFact):
     - Curiosidade linguística ou cultural

  9. Cuidado! (confusedWith):
     - Verbos com os quais se confunde

  10. Contextos (tags):
      - Tags de contexto (ex: "educação", "cotidiano", "movimento")

  11. Referência Rápida:
      - Todas as 6 formas em cápsulas visuais
      - Destaque nas formas du/er

8.8 BARRA DE MAESTRIA (MASTERY BAR)

8.9 RENDERIZAÇÃO E CICLO DE VIDA

renderConjugationTrainer(chId):
  1. Obtém verbos do capítulo: getChapterVerbs(chId)
  2. Se não há verbos, esconde o container
  3. Ordena verbos por dificuldade: regular(0) → irregular(1) → auxiliary(2) → separable(3) → modal(4)

resetConjugation(chId, vIdx):

10.3 LÓGICA DE DESBLOQUEIO (isUnlocked)

function isUnlocked(id):
  if (id === 1) return true;  // Capítulo 1 sempre desbloqueado
  const prev = getChapter(id - 1);
  return prev && state.progress[prev.id] && state.progress[prev.id].testPassed;
  // Só desbloqueia se o capítulo ANTERIOR teve o mini teste aprovado

10.4 LÓGICA DE CONCLUSÃO (isCompleted, getProgress)

isCompleted(id):
  return state.completed[id] === true;

getProgress(id):
  - Calcula porcentagem de conclusão do capítulo
  - Total = exercícios.length + 1 (mini teste)
  - Done = exercisesDone + (testPassed ? 1 : 0)
  - Retorna Math.round(done / total * 100)

10.5 CÁLCULO DE PROGRESSO GERAL (getOverall)

function getOverall():
  let total = 0, done = 0;
  CHAPTERS.forEach(ch => {
    total += 100;
    done += getProgress(ch.id);
  });
  return total > 0 ? Math.round(done / total * 100) : 0;

getCompleted():
  return CHAPTERS.filter(ch => isCompleted(ch.id)).length;

10.6 ATUALIZAÇÃO GLOBAL DA UI (updateAll)

function updateAll():
  1. Calcula pct = getOverall(), comp = getCompleted()
  2. Atualiza navbar: progress-pct (X%), progress-bar-fill (width)
  3. Atualiza conclusão: final-completed (X/20), final-pct (X%)
  4. Re-renderiza: renderTOC(), renderSidebar()

16.2 normalize(s)

  function normalize(s):
    return s.toLowerCase()
            .trim()
            .replace(/[.,!?;:]/g, '')
            .replace(/\s+/g, ' ');

  Remove pontuação e normaliza espaços para comparação flexível.

16.3 isSimilar(u, a)

  function isSimilar(u, a):
    if (Array.isArray(a))
      return a.some(x => normalize(u) === normalize(x));
    return normalize(u) === normalize(a);

  Compara resposta do usuário com gabarito (string ou array de alternativas).

16.4 levenshtein(a, b)

  Implementação clássica de distância de edição (Levenshtein distance).
  Usada em checkTranslate para detectar "quase lá" (distância <= 2).
  Complexidade O(n*m).

      d.style.transition = 'opacity .3s';

17.5 RECONHECIMENTO DE RAÍZES

  O sistema ensina explicitamente os padrões de alternância vocálica:
    - e → a  (sprechen → Sprache)
    - i → u  (trinken → Trunk, finden → Fund)
    - e → i  (helfen → Hilfe)
    - a → ä  (fahren → fährst, backen → Bäcker)
    - o → u  (kommen → Kunft)
    - h → cht (sehen → Sicht)
    - b → ft (schreiben → Schrift, geben → Gift)

  E os principais prefixos:
    - be-  (direcionar ação: besprechen, bekommen, bezahlen)
    - ver- (intensificar/transformar: verstehen, verkaufen, versuchen)
    - er-  (resultado alcançado: erfinden, erfahren, erzählen)
    - auf- (para cima/abertura: aufmachen, aufstehen, aufessen)
    - aus- (para fora: ausgehen, Aussprache, Aussicht)
    - ein- (para dentro: einkaufen, einschlafen)
    - an-  (em direção a: ankommen, anrufen, Ansicht)
    - mit- (companhia: mitkommen, mitmachen, mitnehmen)
    - zu-  (fechamento/direção: zumachen, Zukunft)
    - vor- (diante de: vorlesen, vorspielen)
    - Ge-  (coletivo: Gespräch, Gesicht, Gefahr, Gewissen)

    - Schau + Spiel = Schauspiel (espetáculo)

===== 18. MODO ENGENHARIA DA FRASE (SENTENCE ENGINEERING SYSTEM) =====
===============================================================================

18.1 DESCRIÇÃO DO SISTEMA

  Nome:        MODO ENGENHARIA DA FRASE (Sentence Engineering System)
  Namespace:   IIFE isolado (função autoexecutável, sem variáveis globais)
  Arquivo:     deutsch-meister.html (inline)
  Objetivo:    Ensinar COMO O ALEMÃO PENSA, desmontando frases completamente
               e revelando a arquitetura estrutural, a lógica de cada posição
               e o raciocínio cognitivo por trás da ordem das palavras.

  O sistema aparece em TODOS os 20 capítulos, entre a Revisão e o Treinador
  de Conjugação Verbal.

  Para cada capítulo, o sistema analisa 2 frases representativas com
  profundidade extrema: NÃO apenas rotula palavras, mas explica:
    - POR QUE cada palavra está naquela posição
    - QUAL regra estrutural está sendo aplicada
    - COMO o alemão organiza a informação na frase
    - O QUE aconteceria se a ordem mudasse
    - QUAIS erros brasileiros são comuns
    - QUAIS variações são possíveis
    - QUAL é o padrão mental do alemão por trás da estrutura

===============================================================================
18.2 OBJETIVO PEDAGÓGICO

  O sistema NÃO se limita a:
    - Traduzir frases
    - Mostrar palavras separadas
    - Ensinar gramática superficialmente

  O verdadeiro objetivo é fazer o usuário:
    - Enxergar a função de cada palavra
    - Entender a lógica estrutural
    - Compreender a ordem das palavras
    - Analisar o comportamento gramatical
    - Identificar o papel sintático de cada elemento
    - Reconhecer relações entre elementos
    - Visualizar a arquitetura da frase alemã

  Meta final: o usuário deve PARAR DE DECORAR FRASES e COMEÇAR A
  ENTENDER A ESTRUTURA REAL DO ALEMÃO. Deve sentir:
  "Agora eu entendo POR QUE essa frase funciona."

===============================================================================
18.3 BANCO DE DADOS: SENTENCE_ENGINEERING_DB

  Localização:  No script inline, após TH[20] e antes de renderTOC()
  Tipo:         const SENTENCE_ENGINEERING_DB (IIFE que retorna objeto)
  Cobertura:    TODOS os 20 capítulos, 2 frases por capítulo (40+ frases)

  Estrutura da IIFE:
    const SENTENCE_ENGINEERING_DB = (() => {
      const en = {};
      const e = (ch, arr) => { en[ch] = arr; return arr; };
      // e(chapterId, [analyses...]) para cada capítulo
      return en;
    })();

  Estrutura de cada análise de frase:
    {
      de:       string,        // Frase original em alemão
      pt:       string,        // Tradução natural em português
      tokens:   [              // Divisão estrutural palavra por palavra
        {
          w:    string,        // Palavra/token
          r:    string,        // Role CSS class (subj, verb, obj, adv, etc.)
          rp:   string,        // Nome do papel em português
          d:    string,        // Explicação detalhada (PT)
          de:   string         // Explicação detalhada (EN) — opcional
        },
        ...
      ],
      ord:      {pt, en},     // 6. Explicação de ordem das palavras
      gram:     {pt, en},     // 7. Explicação gramatical
      pat:      {pt, en},     // 8. Padrão utilizado
      obs:      {pt, en},     // 9. Observações importantes
      err:      {pt, en},     // 10. Erros comuns de brasileiros
      vars:     [{de, pt}],   // 11. Variações possíveis da frase
      cog:      {pt, en},     // 12. Explicação cognitiva
      conn:     [string],     // 13. Conexões com outras estruturas (tags)
      ctx:      {pt, en},     // 14. Contexto real de uso
      ment:     {pt, en}      // Padrão mental do alemão (campo extra)
    }

===============================================================================
18.4 FUNÇÕES DAS PALAVRAS IDENTIFICADAS (TOKEN ROLES)

  O sistema identifica e classifica cada palavra com papéis gramaticais
  específicos, cada um com sua classe CSS correspondente:

    Role      Classe CSS         Significado

    subj      eng-token.subj     Sujeito (quem pratica a ação)

    adv       eng-token.adv      Advérbio (tempo, modo, lugar)
    neg       eng-token.neg      Negação (nicht, kein)
    prep      eng-token.prep     Preposição
    modal     eng-token.modal    Verbo modal conjugado
    conj      eng-token.conj     Conjunção (dass, weil, wenn, etc.)
    prefix    eng-token.prefix   Prefixo separável (no final)
    dat       eng-token.dat      Objeto no caso dativo

18.6 DIFICULDADE PROGRESSIVA

  O sistema respeita a progressão natural dos capítulos:

  A1 (Capítulos 1-8) — Frases simples:
    - SVO básico (Ich lerne Deutsch)
    - Inversão simples (Heute lerne ich Deutsch)
    - W-Fragen (Wo wohnst du?)
    - Apresentação (Ich heiße Maria)
    - Adjetivos predicativos (Das Auto ist rot)
    - Adjetivos atributivos (Sie trägt ein blaues Kleid)
    - Possessivos (Mein Vater arbeitet im Büro)
    - Modais + infinitivo (Seine Schwester kann gut tanzen)

  A2 (Capítulos 9-15) — Estruturas intermediárias:
    - Perfekt com haben (Ich habe gestern viel gearbeitet)
    - Perfekt com sein (Wir sind mit dem Zug gefahren)
    - Acusativo (Ich sehe den Mann)
    - Dativo com verbo específico (Ich helfe dem Freund)
    - Modais (Ich muss jetzt gehen)
    - Wechselpräpositionen + Dativ (Das Buch liegt auf dem Tisch)
    - Verbos separáveis (Ich stehe um 7 Uhr auf)
    - Direções (Der Bahnhof ist geradeaus)

  B1 (Capítulos 16-20) — Estruturas avançadas:
    - Voz passiva (Der Brief wird geschrieben)
    - Konjunktiv II com würde (Ich würde gern reisen)
    - Condicional com wenn (Wenn ich Zeit hätte, würde ich verreisen)
    - Orações relativas (Der Mann, der hier wohnt, ist Arzt)
    - Vocabulário avançado + precisão gramatical (Er arbeitet in einer Firma)
    - Subordinada com dass (Ich glaube, dass er morgen kommt)

18.7 EXPLICAÇÃO COGNITIVA

  Cada análise inclui uma seção de "Explicação Cognitiva" que revela
  COMO o alemão organiza a informação mentalmente. Exemplos:

    - "O alemão prioriza a informação estrutural (verbo) cedo na frase.
       O cérebro alemão processa PRIMEIRO a ação, DEPOIS os detalhes."

    - "O alemão expressa 'gostar de fazer' como um MODO de fazer
       (gern = com prazer), não como um sentimento separado."

    - "O alemão organiza a informação em camadas: TÓPICO → AÇÃO → AGENTE.
       O português organiza como AGENTE → AÇÃO → TÓPICO."

===============================================================================
18.8 PADRÃO MENTAL DO ALEMÃO

  Cada análise inclui uma seção revelando o "padrão mental" subjacente:

    - "O alemão pensa: 'primeiro te digo QUEM, depois te digo A AÇÃO,
       depois te digo SOBRE O QUÊ'. Esta hierarquia é fixa."

    - "O alemão vê a profissão como uma CATEGORIA à qual você pertence,
       não como 'um exemplar' dela. Por isso, sem artigo."

===============================================================================
18.9 ERROS COMUNS DE BRASILEIROS

  Cada análise antecipa erros típicos de falantes de português:

    - Colocar verbo no lugar errado (ex: "Heute ich lerne" em vez de
      "Heute lerne ich")
    - Usar acusativo com verbos que regem dativo (ex: "helfen")
    - Adicionar artigo antes de profissões com "sein"
    - Usar "haben" com verbos de movimento no Perfekt
    - Não enviar verbo para o final em subordinadas
    - Confundir Dativ com Akkusativ em Wechselpräpositionen

18.10 INTEGRAÇÃO COM O SISTEMA DE EVOLUÇÃO

  O MODO ENGENHARIA DA FRASE alimenta conceitualmente:
    - Domínio estrutural (entendimento da arquitetura da frase)
    - Domínio gramatical (regras aplicadas em contexto real)
    - Domínio de ordem verbal (V2, inversão, Satzklammer)
    - Domínio de padrões (reconhecimento de estruturas recorrentes)

  O progresso do usuário pode ser observado através de:
    - Capacidade de prever estruturas
    - Reconhecimento de padrões em frases novas

===== 19. DNA DO VERBO (VERB PERSONALITY SYSTEM) =====
===============================================================================

19.1 DESCRIÇÃO DO SISTEMA

  Nome:        DNA DO VERBO (Verb DNA / Verb Personality System)
  Namespace:   const VERB_DNA = (() => { ... })() — IIFE isolado
  Arquivo:     deutsch-meister.html (inline)
  Objetivo:    Criar um PERFIL LINGUÍSTICO COMPLETO para cada verbo,
               como uma "ficha técnica de personalidade", revelando
               frequência, dificuldade, irregularidade, regência,
               comportamento estrutural e padrões relacionados.

  O sistema é integrado DIRETAMENTE nos cards do Treinador de Conjugação
  Verbal, aparecendo abaixo do Deep Dive educacional em todos os verbos
  de todos os 20 capítulos.

  Cada verbo recebe um painel "DNA" completo contendo:
   - Frequência real (5 níveis, com estrelas)
   - Dificuldade (com explicação do PORQUÊ)
   - Irregularidade (descrição detalhada)
   - Separável? (com explicação de comportamento)
   - Exigência de Akkusativ/Dativ (com contexto)
   - Mudança de radical (quando, como, por quê)
   - Formalidade (contexto social)
   - Uso no cotidiano / escrita / fala
   - Contextos frequentes (tags)
   - Importância pedagógica + velocidade de aprendizado
   - Padrões relacionados (verbos similares)
   - Família verbal (raiz etimológica)
   - Comportamento estrutural (posição na frase)
   - Exemplos reais (3 por verbo)
   - Observações linguísticas (insights)

===============================================================================
19.2 OBJETIVO PEDAGÓGICO

  O sistema NÃO se limita a:
    - Mostrar conjugação
    - Mostrar tabela verbal
    - Ensinar tradução

  O verdadeiro objetivo é fazer o usuário:
    - Entender a PERSONALIDADE completa de cada verbo
    - Enxergar o verbo como ENTIDADE LINGUÍSTICA viva
    - Reconhecer padrões entre verbos semelhantes
    - Desenvolver intuição sobre comportamento verbal
    - Saber PRIORIZAR quais verbos dominar primeiro
    - Compreender COMO e ONDE cada verbo é usado

  Meta final: o usuário deve sentir:
  "Eu realmente conheço esse verbo — não apenas sua conjugação,
   mas sua personalidade, seu comportamento, sua vida no idioma."

===============================================================================
19.3 BANCO DE DADOS: VERB_DNA.dna

  Localização:  Antes de renderConjugationTrainer(), no script inline
  Tipo:         IIFE que retorna { dna: {...}, renderDNA: fn }
  Cobertura:    ~25 verbos com perfil completo, expansível

  Estrutura de cada entrada:
    {
      freq:            string,     // very_high | high | medium | low | rare
      diff:            string,     // easy | medium | hard
      freqLabel:       string,     // Rótulo descritivo da frequência
      diffLabel:       string,     // Rótulo descritivo da dificuldade
      diffWhy:         string,     // Explicação do PORQUÊ da dificuldade
      irregularity:    string,     // Descrição da irregularidade (ou "Nenhuma")
      separable:       boolean,    // É verbo separável?
      needsAcc:        string|bool,// Exige acusativo? (com explicação)
      needsDat:        string|bool,// Exige dativo? (com explicação)
      stemChange:      string,     // Descrição da mudança de radical
      formality:       string,     // Formal / Informal / Neutro
      dailyUse:        string,     // Frequência no cotidiano
      writtenUse:      string,     // Frequência na escrita
      spokenUse:       string,     // Frequência na fala
      contexts:        string[],   // Lista de contextos de uso (tags)
      importance:      string,     // Descrição da importância pedagógica
      priority:        number,     // Nível de prioridade (1-5)
      learningSpeed:   string,     // Velocidade estimada de aprendizado
      relatedPatterns: string[],   // Verbos com padrões similares
      verbFamily:      string,     // Família verbal / raiz etimológica
      structuralBehavior: string,  // Comportamento na estrutura da frase
      realExamples:    [{de,pt}],  // 3 exemplos reais de uso
      linguisticNotes: string      // Observações e insights linguísticos
    }

===============================================================================
19.4 RENDERIZAÇÃO: VERB_DNA.renderDNA(verb, isEn)

  Função:      VERB_DNA.renderDNA(verb, isEn)
  Chamada:     Em renderConjugationTrainer(), dentro do loop de verbos
  Localização: Após generateVerbDeepDive(), dentro da conj-verb-card

  Fluxo de renderização:
    1. Consulta VERB_DNA.dna[verb.infinitive]
    2. Se não existir perfil, retorna string vazia (sem erro)
    3. Renderiza o painel DNA com:
       a. Header: "DNA DO VERBO — [nome]" com ícone 🧬
       b. Grid de indicadores (8 cards):
          - 📊 Frequência (com estrelas de prioridade)
          - 🧠 Dificuldade (com explicação do porquê)
          - 🧬 Irregularidade (descrição)
          - 🔀 Separável? (✓/✗ com explicação)
          - 🎯 Exige Akkusativ? (✓/✗/◐)
          - 📦 Exige Dativ? (✓/✗/◐)
          - 🔄 Mudança de Radical (descrição)
          - 🗣 Formal/Informal (contexto social)
       c. Seção de Uso no Idioma (3 cards):
          - 🏠 Cotidiano
          - 📖 Escrita
          - 💬 Fala
       d. Importância pedagógica + velocidade de aprendizado
       e. Comportamento estrutural (descrição detalhada)
       f. Tags de contextos frequentes
       g. Tags de padrões relacionados
       h. Família verbal
       i. Exemplos reais (3 frases autênticas)
       j. Observações linguísticas (insights e curiosidades)

  Todo conteúdo é em português (os dados de DNA são em PT,
  com estrutura preparada para futura internacionalização).

===============================================================================
19.5 SISTEMA DE FREQUÊNCIA

  Níveis de frequência (campo freq):
    very_high    Extremamente comum — aparece em quase toda conversa
                 (sein, haben, werden, machen, sprechen, gehen, kommen,
                  lernen, spielen, arbeiten, heißen, geben, nehmen,
                  essen, können, müssen, wollen, mögen, sehen, fahren)
    high         Muito comum — aparece frequentemente
                 (wohnen, lesen, schreiben, trinken, schlafen, helfen,
                  wissen, dürfen, sollen, aufstehen, einkaufen, anrufen)
    medium       Comum — aparece regularmente
    low          Ocasional — aparece em contextos específicos
    rare         Raro — uso limitado

  Prioridade pedagógica (campo priority, 1-5):
    5 = Crítico / Prioridade máxima
    4 = Muito importante
    3 = Importante
    2 = Relevante
    1 = Complementar

===============================================================================
19.6 SISTEMA DE DIFICULDADE

  Níveis de dificuldade (campo diff):
    easy      Fácil — regular, sem armadilhas, aprendizado rápido
    medium    Médio — tem particularidades (mudança vocálica, separação,
              regência especial) mas segue padrões consistentes
    hard      Difícil — múltiplas irregularidades, formas supletivas,
              funções gramaticais múltiplas

  Cada nível inclui diffWhy: explicação do PORQUÊ da dificuldade.
  Exemplos:
    - lernen: "Regular, sem mudanças de radical, padrão previsível."
    - nehmen: "Múltiplas alterações: e→i + perda do h + duplicação do m."
    - sein: "O verbo mais irregular do alemão. Formas supletivas de
             3 raízes proto-indo-europeias diferentes."

===============================================================================
19.7 IRREGULARIDADES E PADRÕES

  O sistema identifica e explica:
    - Verbos regulares (sem irregularidades)
    - Verbos com e→i (sprechen, helfen, essen, geben, nehmen, treffen)
    - Verbos com e→ie (lesen, sehen)
    - Verbos com a→ä (fahren, schlafen, tragen, waschen)
    - Verbos modais (padrão singular sem terminação + plural com trema)
    - Verbos separáveis (prefixo no final da frase)
    - Verbos auxiliares (sein, haben, werden — completamente irregulares)
    - Verbos com padrão misto (wissen — modal no singular, regular no plural)
    - Verbos com Partizip II irregular (gehen→gegangen, kommen→gekommen,
      trinken→getrunken, schreiben→geschrieben)

  Cada irregularidade é explicada com:
    - O QUE muda (vogal, consoante, posição do prefixo)
    - QUANDO muda (apenas 2ª/3ª pessoa? apenas no Partizip?)
    - POR QUE muda (explicação etimológica ou fonológica)
    - QUAIS outros verbos seguem o mesmo padrão (campo relatedPatterns)

===============================================================================
19.8 REGÊNCIA VERBAL (AKKUSATIV / DATIV)

  O sistema identifica para cada verbo:
    - Se exige Akkusativ (objeto direto)
    - Se exige Dativ (objeto indireto)
    - Se exige AMBOS (Dativ + Akkusativ, como "geben")
    - Se é opcional (depende do contexto)

  Verbos notáveis com regência especial documentados:
    helfen      → Dativ (Ich helfe DEM Freund)
    geben       → Dativ + Akkusativ (Ich gebe DEM Kind EINEN Apfel)
    wohnen      → in + Dativ (Ich wohne in EINER Wohnung)
    fahren      → mit + Dativ (Ich fahre mit DEM Bus)

===============================================================================
19.9 COMPORTAMENTO ESTRUTURAL

  Cada verbo tem descrição de seu comportamento na frase:
    - Posição do verbo conjugado (V2 em frases principais)
    - Posição do prefixo (final, para separáveis)
    - Posição do Partizip II (final, no Perfekt)
    - Posição do infinitivo (final, com modais)
    - Construções especiais (impessoal, reflexivo, etc.)

===============================================================================
19.10 EXEMPLOS REAIS

  Cada verbo possui 3 exemplos autênticos de uso:
    - Frase em alemão
    - Tradução em português
    - Contextos variados (cotidiano, trabalho, escola, etc.)

  Os exemplos são escolhidos para demonstrar:
    - A conjugação alvo (especialmente formas irregulares)
    - A regência do verbo (acusativo, dativo)
    - O uso em contexto natural

===============================================================================
19.11 OBSERVAÇÕES LINGUÍSTICAS

  Cada verbo possui uma seção de insights linguísticos:
    - Etimologia (origem da palavra)
    - Curiosidades históricas
    - Conexões com outras línguas
    - Nuances de uso que dicionários não ensinam
    - Armadilhas comuns e como evitá-las

  Exemplos:
    - sein: "3 raízes PIE fundidas em 1 verbo ao longo de milênios"
    - nehmen: "O verbo mais transformado do alemão — 4 formas diferentes"
    - mögen: "möchte é a palavra mágica da cortesia alemã"

===============================================================================
19.12 CONEXÃO COM FAMÍLIAS DE PALAVRAS

    - Palavras derivadas (ex: Sprache, Gespräch, Spruch)
    - Compostos comuns (ex: besprechen, versprechen, aussprechen)

===============================================================================
19.13 CONEXÃO COM ENGENHARIA DA FRASE

  O DNA do Verbo complementa o sistema de Engenharia da Frase:
    - A Engenharia mostra COMO a frase funciona
    - O DNA mostra COMO o verbo funciona DENTRO da frase
    - Juntos, oferecem visão completa da arquitetura do alemão

20.6 FLUXO DE RENDERIZAÇÃO

  1. render(chId) é chamada para cada capítulo desbloqueado
  2. getChapterVerbs(chId) busca verbos do capítulo no VERB_DB
  3. Para cada verbo, consulta WFS_DB[verb.infinitive]
  4. Se existir entrada: renderiza família completa
     - WFS Card Header (nome, verbo raiz, significado)
     - Explicação base da raiz
     - Árvore visual (1º nível com botões [+])
     - Grid de Member Cards
     - Padrões, Prefixos, Sufixos, Compostos
     - Curiosidade/Observações
     - Tags
  5. Se NÃO existir entrada: placeholder "em preparação"
  6. Se capítulo sem verbos: mensagem sutil

Cache: _renderCache evita reconstruir HTML (key = chId + lang).
Invalidação: ocorre quando registerFamily() adiciona novos dados.

20.7 SISTEMA DE EXPANSÃO INCREMENTAL

  - Árvore mostra APENAS profundidade 1 inicialmente
  - Nós com filhos mostram botão [+] azul circular
  - Clique em [+] aciona expandNode()
  - Expansão renderiza filhos SOB DEMANDA (DOM incremental)
  - Botão alterna para [−] quando expandido
  - Recolher recoloca o botão como [+] e esconde filhos

Prevenção de loops:
  - Set() de IDs visitados (window._wfsVisited)
  - Limite de profundidade: MAX_DEPTH = 4
  - Nós já visitados mostram "(já exibido)" sem expandir
  - Toast informa "Conexão circular detectada"

20.12 SISTEMA DE GRAFO — WFS_GRAPH

  Implementado um sistema completo de navegação em grafo:

  WFS_GRAPH._buildIndexes():
    Constrói 4 índices:
    - _nodeIndex:  mapeia memberId → {member, familyKey, familyData}
    - _edgeIndex:  mapeia edgeId → edge
    - _chapterIndex: mapeia chId → [familyKeys]
    - _typeIndex:  mapeia type → [memberIds]

  WFS_GRAPH.findFamiliesByChapter(chId):
    Retorna array de familyKeys para um capítulo.

  WFS_GRAPH.findMemberAcrossFamilies(memberId):
    Busca um membro em TODAS as famílias (não apenas na sua).

  WFS_GRAPH.findMembersByType(type):
    Filtra membros por tipo (VERB, NOUN, ADJ, COMPOUND, etc.).

  WFS_GRAPH.getAllNeighbors(nodeId):
    Retorna TODOS os vizinhos de um nó no grafo:
    - Conexões outgoing (arestas do próprio membro)
    - Conexões incoming (arestas de outros membros apontando para ele)
    - Conexões cross-family (crossConnections bidirecionais)
    Ordenado: intra-family primeiro, cross-family depois.

  WFS_GRAPH.findCrossReferences(nodeId):
    Retorna todas as conexões entre famílias envolvendo este nó.
    Detecta direção: outgoing (da família atual para outra) e incoming.

  WFS_GRAPH.findConnectionPath(fromId, toId, maxDepth=5):
    BFS (Breadth-First Search) para encontrar caminho entre dois nós.
    Anti-loop: Set() de visitados. Profundidade máxima configurável.
    Retorna array de IDs ou null.

  WFS_GRAPH.getStrongestConnections(nodeId, limit=5):
    Retorna as conexões mais fortes (maior weight) de um nó.

  WFS_GRAPH.getStats():
    Retorna métricas completas do grafo:
    - nodeCount, edgeCount, familyCount
    - families: array de chaves
    - typeDistribution: contagem por tipo

  WFS_GRAPH.getTypeDistribution():
    Distribuição de tipos de membros no grafo inteiro.

20.13 BOOTSTRAP DE NÓS RAIZ

  Após a definição do WFS_DB, uma função de bootstrap auto-executa:
    
    1. Para cada família, verifica se existe um membro com id == familyKey
    2. Se não existir, cria um nó raiz virtual com:
       - id = familyKey (ex: "sprechen", "gehen")
       - word = rootVerb
       - type = VERB
       - connections = array gerado a partir das arestas dos membros 
         existentes que apontam de volta para a raiz
    3. Insere o nó raiz no início do array members[]
    4. Reconstrói os índices do grafo (WFS_GRAPH._buildIndexes)

  Isso garante que:
    - Toda aresta "to":"sprechen" tenha um nó de destino válido
    - O grafo seja completo (sem dangling edges)
    - A renderização da árvore funcione corretamente

20.14 PREVENÇÃO DE ESTRUTURAS CIRCULARES PERIGOSAS

  O sistema previne ciclos perigosos em 3 níveis:
    
    1. Dados: as arestas são definidas manualmente. Nenhum ciclo é
       criado nos dados — as conexões vão SEMPRE do derivado para
       a raiz ou entre níveis de derivação (nunca raiz→raiz).
    
    2. Renderização: expandNode() usa window._wfsVisited (Set).
       Nós já visitados mostram "(já exibido)" sem expandir.
       MAX_DEPTH = 4 impede expansão infinita.
    
    3. Grafo: findConnectionPath() usa BFS com visited Set() e
       maxDepth configurável. Não entra em loop infinito.
