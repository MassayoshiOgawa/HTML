1. IDENTIDADE VISUAL — DESCRIÇÃO GERAL
================================================================================

Estilo: Liminal Horror / Tecnológico-decadente / Sci-Fi abandonado / Atmosfera de arquivo perdido.

A apresentação deve simular um "arquivo digital encontrado" — como se fosse um terminal de dados corrompido de uma organização secreta (como a ASYNC Research), tentando documentar os níveis das Backrooms. A identidade visual mescla elementos de interface de sistemas antigos (CRT, scanlines, dados, coordenadas) com a atmosfera úmida, amarelada e opressiva dos espaços liminares.

A sensação geral é de desconforto, solidão e vastidão infinita. Como estar perdido em um corredor sem fim, sob uma luz fluorescente que nunca se apaga.

Material principal: Concreto envelhecido, carpete desgastado, metal oxidado, névoa, vidro sujo e papel amarelado.

4. ESTILO VISUAL
================================================================================

O estilo é "Found Footage Meets Dystopian Terminal Interface":

- Fundo escuro com textura de ruído (grain) constante
- Elementos de interface simulando sistemas antigos de monitoramento
- Efeito CRT sutil (scanlines quase imperceptíveis, leve chromatic aberration nas bordas)
- HUD decorativo com coordenadas, timestamps, indicadores de sinal
- Vignette escurecendo as bordas da tela
- Glassmorphism apenas em elementos específicos (painéis de dados, telas de monitoramento)
- Névoa volumétrica animada
- Partículas de poeira suspensas, flutuando lentamente
- Efeito de luz fluorescente pulsando (flicker muito sutil)
- Bordas duplas estilo terminal/retrô em alguns elementos
- Chromatic aberration e distortion em momentos de transição (como se a realidade estivesse "no-clipando")

NÃO use: cyberpunk colorido, neon excessivo, estilo futurista limpo, minimalismo corporativo, ou qualquer estética que pareça "limpa" ou "nova". Tudo deve parecer degradado, envelhecido, abandonado.

5. CONCEITO ARTÍSTICO
================================================================================

A apresentação deve simular que o próprio sistema no qual ela roda está "corrompido" ou "instável" — como se fosse um terminal encontrado dentro das Backrooms. Cada slide é como se fosse um fragmento de um banco de dados tentando se reconstruir.

A sensação a transmitir é:
- Solidão (espaços vazios, silêncio visual, composição com muito espaço negativo)
- Desconforto (cores amareladas doentias, ruído, flicker)
- Vastidão (profundidade com névoa, elementos distantes, sensação de infinito)
- Mistério (informações fragmentadas, dados parciais, glitch ocasional)
- Decadência (texturas sujas, cores apagadas, imperfeições)

A atmosfera deve ser opressiva mas hipnotizante. O espectador deve sentir que está em um lugar que não deveria existir.

7. NAVEGAÇÃO GLOBAL
================================================================================

COMPONENTES DE NAVEGAÇÃO:

1. Setas laterais:
   - Seta esquerda (anterior): aparece no centro vertical, lado esquerdo. Opacidade 0.3, hover 0.8.
   - Seta direita (próximo): aparece no centro vertical, lado direito. Opacidade 0.3, hover 0.8.
   - Formato: seta simples estilo terminal ( >  e  < )
   - Tamanho: 28px
   - Cor: #F5D742
   - Transição: 300ms ease
   - Desaparecem quando não há slide anterior/próximo (primeiro e último slide)

2. Barra de progresso inferior:
   - Barra fina (2px) na parte inferior da tela
   - Cor: gradiente horizontal de #F5D742 a #B87333
   - Largura = (slideAtual / totalSlides) * 100%
   - Transição: 500ms ease-out
   - Abaixo da barra: contador "SLIDE XX/20" em courier, 0.65rem, #8A8A8A

3. Navegação por teclado:
   - Seta direita (→) ou Seta para baixo (↓): próximo slide
   - Seta esquerda (←) ou Seta para cima (↑): slide anterior
   - Home: primeiro slide (slide 1)
   - End: último slide (slide 20)
   - Número 1-0 (e combinações para 10-20): pular para slide específico (ex: tecla '1' + '5' vai para slide 15). Alternativamente, usar Ctrl+[nº] para slides 10-20.
   - ESC: sai do modo tela cheia se ativado

4. Navegação por touch/swipe:
   - Swipe para esquerda: próximo slide
   - Swipe para direita: slide anterior
   - Detecção: mínimo 50px de deslocamento horizontal

5. Navegação por mouse:
   - NÃO troca slides no clique
   - Roda do mouse: NÃO troca slides (desabilitada para navegação)

6. Mini-índice (acessível por botão):
   - Botão no canto superior direito: ícone de grid/grelha (4 quadrados pequenos)
   - Ao clicar: abre um overlay semi-transparente com uma grade de miniaturas numeradas
   - Cada miniatura: pequena prévia do slide (ou apenas o número em estilo terminal)
   - Ao clicar em uma miniatura: fecha o overlay e navega para o slide
   - Fechar: clique fora ou ESC

7. Botão fullscreen:
   - Canto inferior direito
   - Ícone de expandir telas
   - Ao clicar: ativa/desativa fullscreen

8. ANIMAÇÕES GLOBAIS
================================================================================

TRANSIÇÃO ENTRE SLIDES:

- Tipo: Dissolve com ruído (efeito de estática/scanlines)
- Duração: 600ms
- Easing: ease-in-out
- Como funciona:
  1. Usuário solicita troca
  2. Slide atual inicia dissolve: opacidade vai a 0, ruído de estática aumenta
  3. Ao atingir opacidade 0 (e ruído máximo), o slide atual é ocultado
  4. Pequeno delay de 50ms
  5. Novo slide aparece com opacidade 0, ruído no máximo
  6. Ruído diminui, opacidade do novo slide aumenta até 1
  7. Duração total da transição: ~600ms
  8. Após a transição, aguardar 100ms para iniciar animações de entrada do novo slide

ANIMAÇÕES DE ENTRADA (GLOBAIS):

- Timing: Iniciam 100ms após o slide estar totalmente visível
- Stagger: Cada grupo de elementos com delay incremental de 80ms
- Ordem geral: Background → Elementos decorativos/HUD → Título → Subtítulo → Conteúdo → Cards/Listas → Botões/Interações → Efeitos finais
- Easing padrão: cubic-bezier(0.25, 0.46, 0.45, 0.94) — "ease-out suave"
- Duração padrão: 700ms a 1000ms

MICROANIMAÇÕES CONTÍNUAS:

- Partículas: movimento browniano contínuo (sempre ativo)
- Névoa: deslocamento horizontal contínuo (60-120s por ciclo)
- Luz fluorescente: pulsação extremamente sutil (opacidade variando 2-3% a cada 3-5s, aleatório)
- Glow dos títulos: leve pulsação (opacidade do text-shadow variando 5% a cada 4s)
- Elementos decorativos (HUD): leve flutuação vertical (1-2px, 6-8s, sine wave)
- Ruído/grain: sempre ativo, frame atualizado a cada 50ms (via canvas ou CSS)

4. Reflexão — a mais demorada e impactante (fade + blur 15px→0 + escala 95%→100%, 2000ms, delay 1800ms)
5. Nome do apresentador e rodapé (fade, 600ms, delay 2500ms)

INTERAÇÕES:
- Apenas navegação global
- Ao chegar neste slide, a apresentação não termina abruptamente — o usuário pode ficar o tempo que quiser

TRANSIÇÃO: Não há próximo slide. Se o usuário tentar avançar, não acontece nada (ou volta ao início se preferir).

OBSERVAÇÕES:
- Este slide é o mais lento propositalmente. Tudo deve ser mais lento, mais silencioso, mais vazio.
- A reflexão deve aparecer com a animação mais cinematográfica de toda a apresentação.
- O slide final deve deixar o usuário em silêncio por alguns segundos, processando a experiência.

REGRAS ADICIONAIS PARA A IMPLEMENTAÇÃO

1. NÃO USE IMAGENS EXTERNAS. Toda "imagem" deve ser criada com CSS, gradientes, formas, canvas ou SVG.

2. ÁUDIO: O zumbido do Level 0 deve ser gerado via Web Audio API (OscillatorNode, 60Hz + 120Hz + 180Hz com ganho baixo). Não use arquivos de áudio externos.

3. TODOS OS TEXTOS devem estar em português (PT-BR), exceto nomes próprios e títulos em inglês quando fizer sentido.

4. ORGANIZAÇÃO DO CÓDIGO: Mesmo sendo um único HTML, organize com comentários claros:
   <!-- SLIDE 1 — CAPA -->
   <!-- SLIDE 2 — O QUE SÃO AS BACKROOMS -->
   etc.

5. PERFORMANCE: use transform e opacity para animações (GPU accelerated). Evite animar width, height, top, left, margin, padding.

6. O slide ativo DEVE ter display:flex (ou a forma de exibição correta), os demais slides DEVEM ter display:none (ou visibility:hidden + pointer-events:none quando estiverem em transição). NUNCA deixe múltiplos slides visíveis simultaneamente.

7. A apresentação DEVE ocupar toda a viewport (100vw x 100vh). NENHUM slide pode ter overflow.

8. BARRA DE PROGRESSO INFERIOR: fina, 2px, cor gradiente de #F5D742 a #B87333, com transição suave de 500ms ease-out. Abaixo, o contador "SLIDE XX/20" em Courier New, 0.65rem, #8A8A8A.

9. SETAS DE NAVEGAÇÃO: laterais (esquerda/direita), centro vertical, opacidade 0.3 (hover 0.8), cor #F5D742, tamanho 28px, fonte Courier New.

10. A NÃO SER QUE especificado em contrário, TODAS as animações usam cubic-bezier(0.25, 0.46, 0.45, 0.94) como easing padrão.

11. ORGANIZAÇÃO DOS SLIDES: o container de slides deve usar position:fixed, 100vw x 100vh, cada slide com position:absolute, 100vw x 100vh.

12. RESPONSIVIDADE: A apresentação deve usar unidades relativas (vw, vh, %, rem, em) e clamp() para fontes. Testar em 1920x1080, 1366x768, 1024x768, e mobile (375x667). Em mobile, reorganizar grids para 1-2 colunas se necessário.

13. MARGEM DE SEGURANÇA: Manter 5-8% de padding nas quatro bordas da tela em todos os slides. Nenhum conteúdo pode encostar na borda.

14. CHECKLIST DE CODIFICAÇÃO: Antes de finalizar, percorra TODO o HTML e verifique que nenhum caractere acentuado está corrompido. Verifique strings em português, comentários, CSS content, JavaScript. Use <meta charset="UTF-8">. NENHUM caractere pode aparecer como "�".

15. Não use framework, CDN, ou biblioteca externa. Apenas HTML, CSS e JavaScript puros em um único arquivo.

16. NÃO INCLUA pergunta "Alguma dúvida?" ou variações no último slide. O slide final é uma reflexão, não uma pergunta.

17. O scroll do mouse NÃO pode trocar slides. Desabilitar o evento wheel para navegação.

18. O clique do mouse NÃO pode trocar slides. Desabilitar o evento click na área geral para navegação.

19. APENAS as teclas de seta (←/→/↑/↓) navegam. Home = primeiro slide. End = último slide.

20. O botão de mini-índice (grid) deve estar no canto superior direito. Ao clicar, abre overlay com miniaturas numeradas.

21. O botão de fullscreen deve estar no canto inferior direito.

22. ORGANIZAÇÃO: Os slides devem estar dentro de uma div#slides-container, cada slide dentro de uma div.slide.

23. Na transição entre slides, use um overlay de ruído que aparece e desaparece, para camuflar a troca e criar o efeito de "estática".

24. O ruído de fundo (grain) deve ser gerado com Canvas 2D (desenhar pixels aleatórios a cada ~50ms) ou CSS com pseudo-elemento e background-image com noise SVG.

25. O título do slide 1 DEVE usar o efeito 3D extrudado com text-shadow conforme especificado: 35 camadas de text-shadow com loop JavaScript, texto horizontal (sem rotate, skew, ou transform 3d), mais ::before com filter:blur para sombra ambiente.
