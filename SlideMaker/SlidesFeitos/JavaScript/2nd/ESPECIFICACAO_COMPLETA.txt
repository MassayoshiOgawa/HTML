INSTRUÇÕES PARA A IA QUE IRÁ IMPLEMENTAR O HTML
================================================================================

1. Você deve criar UM ÚNICO arquivo HTML completo, auto-contido, sem dependências externas.
2. NÃO acesse nenhum outro documento dentro da pasta de trabalho. Use apenas este documento de especificação.
3. Todo o conteúdo deve estar em UTF-8. Declare <meta charset="UTF-8"> no head.
4. Antes de finalizar, execute uma auditoria completa de codificação: verifique cada caractere acentuado, cada título, cada parágrafo, cada string JS, cada comentário CSS. NENHUM caractere corrompido é aceitável (sem "�", "Ã", "Ã©", etc.).
5. Responsividade obrigatória: todos os slides devem caber integralmente no viewport (1920×1080, 1600×900, 1440×900, 1366×768, 1280×720, 1024×768, tablets e celulares). NENHUM scroll vertical ou horizontal. Se o conteúdo exceder, reorganize o layout, reduza espaçamentos ou utilize componentes interativos (toggles, accordions, abas). NUNCA use overflow:auto/scroll para slides inteiros.
6. Scroll do mouse NÃO troca slides. Apenas setas do teclado e swipe em touch.
7. Clique em cantos da tela NÃO troca slides.
8. Navegação obrigatória: setas direita/esquerda do teclado, botões na tela, navigation dots, swipe em touch.
9. Não crie tela de loading. A apresentação inicia imediatamente com o slide 1 visível e ativo, disparando sua animação de entrada automaticamente ao carregar a página.
10. O z-index do título no slide 1 deve ser 0.
11. Nenhum elemento pode aparecer antes de sua animação — proibido "flash" de conteúdo.
12. Ao sair de um slide, todos os elementos devem resetar para o estado inicial. Ao retornar, as animações devem rodar novamente.
13. Siga a ordem de animações especificada para cada slide. Use stagger para múltiplos elementos similares. Use curvas de easing naturais (ease-out-cubic, ease-in-out, spring). Evite animações lineares.
14. Cada slide é uma tela cheia. Trate como frame de apresentação profissional (PowerPoint/Keynote/Figma). Nada ultrapassa os limites do viewport.
15. O conteúdo NUNCA pode aparecer "pronto" antes das animações começarem.
16. navigation dots são obrigatórios.
17. Use o sistema de blocos inclinados em perspectiva (skew-panel) como componente visual recorrente.
18. O título da capa (slide 1) deve usar extrusão 3D com text-shadow (múltiplas camadas) conforme especificado. O texto deve permanecer HORIZONTAL, sem rotate, skew ou transform 3D. A extrusão usa dezenas de text-shadow deslocados 1px cada. Use também ::before com blur para sombra ambiente. z-index: 0.
19. O primeiro slide ao abrir o HTML deve já aparecer renderizado e visível, com animação de entrada disparada automaticamente no carregamento.

ANIMAÇÕES GLOBAIS
================================================================================

EASING PADRÃO: cubic-bezier(0.25, 0.46, 0.45, 0.94) — ease-out suave
DURAÇÃO PADRÃO DE ENTRADA: 600ms a 1000ms
DELAY PADRÃO ENTRE ELEMENTOS (STAGGER): 120ms a 200ms

SEQUÊNCIA PADRÃO DE ENTRADA (cada slide):
  1. Background já está visível (contínuo)
  2. Elementos decorativos distantes (500ms após ativação)
  3. Título principal (700ms) — fade + move up 30px + blur 6px→0
  4. Subtítulo (900ms)
  5. Cards / blocos de conteúdo (1100ms + stagger 150ms entre cards)
  6. Listas / ícones (1300ms + stagger 100ms)
  7. Botões / CTA (1600ms)
  8. Efeitos finais / glow (1800ms)

ANIMAÇÕES DE SAÍDA (troca de slide):
  - Slide atual: fade out + scale 0.95 + blur 4px (400ms ease-in)
  - Pequeno intervalo (100ms)
  - Novo slide aparece com animação de entrada completa

MICROANIMAÇÕES CONTÍNUAS:
  - Partículas: movimento perpétuo lento
  - Títulos: leve glow pulsando (opacidade varia 0.6-0.9 a cada 3s)
  - Cards flutuantes: deslocamento vertical de 2-3px a cada 4s
  - Botões: glow que respira
  - Décor: rotação de 0.5° a 1° em elementos geométricos
  - Gradientes: animação sutil de posição (20s loop)

RESPONSIVIDADE DAS ANIMAÇÕES:
  - Em dispositivos mais lentos ou telas menores, reduzir complexidade (partículas, blur, glow)
  - Usar prefers-reduced-motion: reduzir ou desabilitar animações

COMPONENTE RECORRENTE: BLOCO INCLINADO EM PERSPECTIVA (SKEW-PANEL)
================================================================================

DEFINIÇÃO: Container visual com formato de quadrilátero inclinado em perspectiva, usando clip-path: polygon(). Este é um componente de identidade visual obrigatório que deve aparecer recorrentemente.

GEOMETRIA BASE:
  - clip-path: polygon(0% 0%, 100% 10%, 100% 90%, 0% 100%)
  - Lado esquerdo inclinado, lado direito reto
  - Topo e base levemente inclinados (perspectiva)

IMPLEMENTAÇÃO:
  - Criar classe CSS reutilizável .skew-panel
  - Aceitar conteúdo interno (títulos, números, ícones, textos)
  - Conteúdo interno deve acompanhar a perspectiva do container
  - Aplicar ao conteúdo interno: transform: skewY(-0.5deg) ou similar SUTIL para integração
  - Padding interno generoso (especialmente nos cantos inclinados)
  - Profundidade: box-shadow múltipla + gradiente interno + glow sutil

VARIAÇÕES DE TAMANHO:
  - Large: 400px × 200px (para títulos de seção)
  - Medium: 250px × 120px (para badges, destaques)
  - Small: 150px × 60px (para tags, labels)

FUNÇÕES NA APRESENTAÇÃO:
  - Badge de número de slide atual
  - Label de categoria (ex: "História", "Características")
  - Container de destaque para porcentagens
  - Faixa de título sobre background decorativo
  - Indicador de timeline
  - Card de KPI/estatística
  - Botão premium em formato inclinado

ANIMAÇÃO DOS BLOCOS:
  - Entrada: deslizar da esquerda acompanhando inclinação + fade + blur 8px→0
  - Conteúdo interno aparece 200ms após o bloco estabilizar
  - Contínuo: leve glow pulsante na borda superior

IMPLEMENTAÇÃO DE REFERÊNCIA:
  .skew-panel {
    clip-path: polygon(0% 0%, 100% 10%, 100% 90%, 0% 100%);
    background: linear-gradient(135deg, #f7df1e, #f0a500);
    padding: 24px 32px;
    box-shadow:
