Erros comuns no documento HTML que acontecem e como resolve-los e evitar que aconteçam:

---

1. SyntaxError: Unexpected token '.' (ou outro caractere) no meio do JavaScript

   Exemplo: barony-presentation.html:682 Uncaught SyntaxError: Unexpected token '.'

   Causa: Uma regra CSS foi inserida acidentalmente dentro de um bloco <script>, no meio do
   código JavaScript. O interpretador JS encontra um caractere inesperado (como um ponto de
   classe CSS, ou chaves de @keyframes) e lança erro de sintaxe.

   Como resolver:
   - Leia o número da linha indicada no erro (ex: linha 682).
   - Verifique o que está naquela linha. Se for CSS (.classe { ... }, @keyframes, etc.)
     dentro do <script>, mova essa regra para o bloco <style> no <head>.
   - Se necessário, mova o bloco CSS inteiro para o local correto e re-teste.

    Como evitar:
    - Nunca escreva CSS dentro de <script>. Todo CSS deve ficar dentro de <style>.
    - Ao fazer edições no HTML, sempre verifique se não há "vazamento" de CSS para o JS.
    - Use um validador de HTML/JS ou o console do navegador para detectar esses erros
      precocemente.

---

2. Conteúdo dos slides não aparece (todos os elementos ficam invisíveis com opacity: 0)

   Exemplo: Todos os .anim permanecem opacity:0, slide de capa mostra apenas o fundo.

   Causa: Na função triggerAnims, o código montava a string de animation concatenando
   o valor de type.anim (que JÁ continha o shorthand completo: nome + duração + easing +
   fill-mode) com duração e easing novamente. Resultado:
   "animTitle 900ms var(--ease-enter) forwards 900ms var(--ease-enter) forwards"
   O navegador rejeita a sintaxe inválida, a animação nunca roda, e o elemento fica
   preso com opacity: 0 (definido pela classe .anim).

   Correção:
   // ANTES (inválido — duração e easing duplicados):
   a.style.animation = type.anim + ' ' + dur + 'ms var(--ease-enter) forwards';

   // DEPOIS (correto — type.anim já contém o shorthand completo):
   a.style.animation = type.anim;

   Como resolver:
    - Verifique no console do navegador se há erros de CSS/JS.
    - Ao programar animações via JavaScript, nunca duplique partes do shorthand de animation.
    - O shorthand CSS de animation segue a ordem: name duration timing-function delay
      iteration-count direction fill-mode play-state. Se já está completo, não adicione nada.

    Como evitar:
    - Quando uma função retorna um shorthand de animation completo, não concatene
      duração e easing novamente no momento da aplicação.
    - Prefira retornar apenas os dados necessários (nome, duração, stagger) e montar
      o shorthand uma única vez.
     - Sempre teste as animações no navegador após criar funções de animação programática.
     - Use o painel de Computado do DevTools (na aba Elements) para verificar se o
       property "animation" está com valor válido no elemento.

---

3. Elementos dos slides ficam borrados (filter: blur permanece após animação)

   Exemplo: Cards, grids e blocos com a classe .anim-fade-scale aparecem com texto
   embaçado mesmo após a animação de entrada ter terminado.

   Causa: A classe .anim-fade-scale define filter:blur(5px) no estado inicial para
   criar o efeito de entrada suave. Porém, as regras .slide.active .anim-X só
   resetavam opacity e transform com !important — esqueceram de incluir
   filter:none!important. Resultado: o filter:blur(5px) da classe base continuava
   ativo mesmo depois do slide ficar visível, mantendo o elemento borrado.

   Correção:
   /* ANTES (faltava resetar filter):
   .slide.active .anim-3{opacity:1!important;transform:none!important;transition-delay:500ms!important}

   /* DEPOIS (filter tambem e resetado):
   .slide.active .anim-3{opacity:1!important;transform:none!important;filter:none!important;transition-delay:500ms!important}

   Como resolver:
   - Abra as regras .slide.active .anim-N (N de 1 a 12) no bloco <style>.
   - Adicione filter:none!important em cada uma delas.
   - Salve e recarregue a página — os elementos devem aparecer nítidos.

   Como evitar:
   - Sempre que uma classe de animação inicial usar filter (blur, brightness, etc.),
     inclua filter:none!important na regra .slide.active .anim-N correspondente.
   - Regra geral: se a classe base tem filter, a regra de ativação DEVE resetar filter.
     - Ao criar novas classes de animação, verifique se há propriedades além de
       opacity e transform que precisam ser revertidas no estado final.

---

4. Failed to load resource: /favicon.ico 404 (Not Found)

   Exemplo: :5500/favicon.ico:1 Failed to load resource: the server responded with a status of 404 (Not Found)

   Causa: O navegador solicita automaticamente /favicon.ico em todo site/página local.
   Se o arquivo não existe no diretório raiz do servidor, o servidor responde com 404.
   Isso aparece no console do navegador como erro, embora não afete o funcionamento
   da página — apenas gera ruído no console.

   Correção:
   Adicione um favicon inline no <head> do HTML, evitando que o navegador busque o
   arquivo externamente. Uma forma simples é usar um favicon SVG data URI:

   <link rel="icon" href="data:image/svg+xml,<svg xmlns='http://www.w3.org/2000/svg' viewBox='0 0 100 100'><text y='.9em' font-size='90'>⚡</text></svg>">

   Ou, se preferir uma imagem real, crie um arquivo favicon.ico ou favicon.png na pasta
   do projeto e referencie:
   <link rel="icon" href="favicon.ico">

   Como resolver:
   - Abra o <head> do HTML e adicione o <link rel="icon"> antes do </head>.
   - Recarregue a página — o erro 404 do favicon deve desaparecer do console.

   Como evitar:
   - Sempre inclua um <link rel="icon"> no <head> de todo documento HTML.
   - Use o favicon SVG data URI para evitar dependência de arquivo externo.
   - Se usar arquivo externo (favicon.ico), certifique-se de que ele existe no diretório
     correto antes de iniciar o servidor local.
