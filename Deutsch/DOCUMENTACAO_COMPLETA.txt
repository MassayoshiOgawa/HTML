================================================================================
  1. VISÃO GERAL E ARQUITETURA
================================================================================

  DeutschMeister é uma SPA offline que ensina alemão do nível A1 ao B1.
  Todo o código está em UM único arquivo HTML contendo HTML+CSS+JS inline.
  Sem frameworks, sem bibliotecas externas, sem arquivos separados.

  Sistemas principais (6 subsistemas pedagógicos):
    1. DNA do Verbo         — perfil linguístico de cada verbo
    2. Conexões Verbais     — rede de verbos derivados por prefixos
    3. Engenharia da Palavra — decomposição morfológica
    4. Famílias de Palavras  — árvore de raízes e derivações (WFS)
    5. Engenharia da Frase   — análise estrutural de frases
    6. GPS / Evolução        — tracking de domínio real do usuário

  Fluxo de carregamento:
    DOMContentLoaded → setup()
    ├── loadState()          — carrega de localStorage
    ├── initGPS()            — inicializa evolução (migra se necessário)
    ├── applyLang()          — aplica idioma + renderiza tudo
    │   ├── renderChapters() — 20 capítulos
    │   │   ├── renderExercises()
    │   │   ├── renderSentenceEngineering()
    │   │   ├── renderConjugationTrainer()
    │   │   │   ├── generateVerbDeepDive()
    │   │   │   ├── VERB_DNA.renderDNA()
    │   │   │   ├── GermanVerbConnectionsSystem.render()
    │   │   │   └── GermanWordEngineeringSystem.render()
    │   │   ├── DeutschMeisterWordFamilies.render()
    │   │   └── renderMiniTest()
    │   ├── renderTOC()
    │   ├── renderSidebar()
    │   ├── renderGlossCats() + renderGlossary()
    │   └── updateAll() → renderEvoDashboard()
    ├── Configura listeners (menu, sidebar, settings, teclado)
    ├── IntersectionObserver para animações de scroll
    └── Esconde loader após 1.5s

================================================================================
  4. SISTEMA DE SAVE / PERSISTÊNCIA
================================================================================

  loadState():
    - Lê localStorage['deutschmeister_state']
    - Merge com state padrão: state = {...state, ...parsed}
    - try/catch para segurança

  saveState():
    - localStorage.setItem('deutschmeister_state', JSON.stringify(state))
    - Chamado após: cada exercício, mini teste, troca idioma/tema, import, reset, anotações

  initGPS():
    - 1. Tenta state.evo (formato novo centralizado)
    - 2. Fallback: deutschmeister_evo (formato antigo) → migra e remove
    - 3. Se nada, usa defaults
    - 4. Aplica decay de memória
    - 5. Salva snapshot em state.evo via saveState()

  saveGPS():
    - GPS.lastSave = Date.now()
    - state.evo = getEvoSnapshot()
    - saveState()

  resetGPS():
    - Zera COMPLETAMENTE: skills, memory, history, rank, profile, weaknesses, strengths
    - state.evo = null

  syncGPSFromState():
    - Restaura GPS de state.evo após import
    - Valida cada campo com fallback para defaults

  Reset (handler do #reset-btn):
    1. localStorage.removeItem('deutschmeister_state')
    2. localStorage.removeItem('deutschmeister_evo') — limpeza
    3. state = default completo (evo: null)
    4. resetGPS() — zera TODA evolução
    5. applyLang() + toast

  Import (handler do #import-file):
    1. Lê JSON via FileReader
    2. Valida: data.state && data.state.progress
    3. state = data.state (substituição completa)
    4. Garante campos ausentes (wfsExplored, wfsPatterns, evo)
    5. syncGPSFromState() — restaura evolução
    6. saveState() + applyLang() + updateAll()

  Export (exportProgress):
    - Cria { exportedAt, version: 1, state }
    - Download via Blob + <a> click

  5. SISTEMA DE PROGRESSO
================================================================================

  isUnlocked(id):
    - Capítulo 1 sempre desbloqueado
    - Demais: capítulo anterior teve testPassed = true

  isCompleted(id):
    - state.completed[id] === true

  getProgress(id):
    - Calcula %: exercisesDone / (exercises.length + 1 para mini teste) * 100

  getOverall():
    - Média das porcentagens dos 20 capítulos

  getCompleted():
    - Contagem de state.completed[id] === true

  trackExercise(chId, correct):
    - Incrementa exerciseTotal; se correto, incrementa exercisesDone
    - saveState() + updateAll()

  updateAll():
    - Atualiza barra de progresso, TOC, sidebar, conclusão, evo dashboard

================================================================================
  6. SISTEMA GPS — EVOLUÇÃO
================================================================================

  Objeto GPS (const, global):
    {
      skills: {
        verbs: { regular, irregular, modal, separable, auxiliary },
        grammar: { wordOrder, conjugation, articles, cases:{nom,acc,dat}, tenses, sentenceStructure },
        vocabulary: { total, categories:{} },
        patterns: { vowelChange, separablePrefix, modalStructure, v2Rule, subordinateClause, caseSystem, articleGender },
        overall: 0
      },
      memory: {},    // { [itemId]: { strength, stability, reviews, lastCorrect, lastSeen, category } }
      history: [],   // últimos 50 { ts, chId, exIndex, correct, overall }
      rank: { level:1, title:'Iniciante', xp:0, nextXP:100 },
      weaknesses: [],
      strengths: [],
      profile: { vocabRate:0, grammarRate:0, patternRate:0, consistency:0 },
      lastSave: 0
    }

  Fluxo após cada exercício:
    trackEvo(ex, chId, correct, exIndex)
    ├── classifyExercise(ex, chId)  — classifica em grammar/vocab/pattern
    ├── updateMemory() × N          — atualiza força/estabilidade de cada item
    ├── recalcSkills()              — recalcula TODAS as habilidades
    ├── analyzeProfile()            — detecta fraquezas (≤25%) e forças (≥65%)
    ├── updateRank()                — atualiza nível/título/XP
    ├── GPS.history.push()          — mantém últimos 50 registros
    ├── saveGPS()                   — persiste em state.evo
    └── renderEvoDashboard()        — atualiza UI

  classifyExercise(ex, chId):
    - Regex no texto da pergunta (q + qPt)
    - Categoriza em: grammar (conjugation, articles, wordOrder, cases, tenses, sentenceStructure)
                     vocab (general, numbers, colors, family, greetings, directions)
                     pattern (vowelChange, separablePrefix, modalStructure, v2Rule, subordinateClause, caseSystem, articleGender)

  updateMemory(itemId, category, correct, chId):
    - Se acerto: strength += (15 - strength*0.1), stability += (10 - stability*0.05)
    - Se erro:   strength -= (8 + strength*0.05), stability -= (12 + stability*0.08)
    - Clamp: 0-100

  recalcSkills():
    - Para cada item na memória, acumula strength por categoria
    - Calcula média por skill (sum/count)
    - vocabulary.total = % de itens vocab com strength > 50
    - overall = média de todas as skills

  analyzeProfile():
    - Fraquezas: skills ≤ 25%
    - Forças: skills ≥ 65%
    - profile.grammarRate = média das 6 skills de gramática
    - profile.patternRate = média das 7 skills de padrão
    - profile.consistency = % de itens com stability > 50 (mínimo 2 reviews)

  updateRank():
    - Níveis: 1(Iniciante Curioso/100XP) → 7(Poliglota em Formação/1500XP)
    - Baseado em GPS.skills.overall

  applyMemoryDecay(days):
    - Decay factor = 1 - (days * 0.02) por dia
    - strength *= decayFactor
    - stability *= decayFactor * 0.7
    - Aplicado se inativo > 0.5 dias

  renderEvoDashboard():
    - Se overall=0 e history vazio: mostra placeholder
    - Header: rank badge (nível, título, XP)
    - Cards: Gramática (6 barras), Padrões (7 barras)
    - Radar SVG (8 eixos)
    - Memória: ring chart + tags (consolidados/instáveis/enferrujados/novos)
    - Insights: fraquezas e forças
    - Summary strip: geral, gramática, padrões, vocabulário, consistência

================================================================================
  7. SISTEMA DE EXERCÍCIOS
================================================================================

  Tipos de exercício:
    'm' — múltipla escolha (botões clicáveis)
    't' — texto (input + verificar)
    'o' — ordenação (word bank + slots)

  Estrutura de dados:
    {
      q:        string,         // enunciado
      qPt:      string (opc),   // enunciado em PT (ordenação)
      qEn:      string (opc),   // enunciado em EN (ordenação)
      t:        'm'|'t'|'o',   // tipo
      a:        number|string,  // resposta
      alts:     string[] (opc), // alternativas aceitas (tipo t)
      opts:     string[] (opc), // opções (tipo m)
      h:        string|string[],// dicas
      w:        string[] (opc), // banco de palavras (tipo o)
      correct:  string[] (opc), // ordem correta (tipo o)
      correctAlts: string[] (opc), // ordens alternativas aceitas
      meanings: object (opc),  // significados das palavras (tipo o)
      explain:  string (opc)   // explicação rica em HTML
    }

  Bases de dados:
    EX[chapterId]    — exercícios em português (20 capítulos, 362 exercícios)
    EX_EN[chapterId] — exercícios em inglês (20 capítulos, 300 exercícios)

  Seleção por idioma:
    getEx(chId) → state.lang==='en' && EX_EN[chId] ? EX_EN[chId] : EX[chId]

  Verificação — checkMulti(chId, i, idx):
    1. Desabilita todos os botões
    2. Marca correto (verde) e errado (vermelho)
    3. Mostra feedback com buildExplanation()
    4. trackExercise() + trackEvo()

  Verificação — checkTranslate(chId, i):
    1. Compara input com ex.a via isSimilar() (normalização + alternativas)
    2. Se distância Levenshtein ≤ 2: "Quase lá!"
    3. buildExplanation() + trackExercise() + trackEvo()

  Verificação — checkOrder(chId, i):
    1. Coleta palavras dos slots
    2. Compara com ex.correct.join(' ') e ex.correctAlts
    3. buildExplanation() + trackExercise() + trackEvo()

  buildExplanation(ex, correct, userAnswer):
    - Gera explicação multi-seccional em HTML:
      a. answerHtml: resposta correta vs usuário
      b. explainHtml: explicação detalhada com regras
      c. tipHtml: dica de melhoria ou reforço
    - Sistema de profundidade adaptativa (depth):
      A1 → depth=3 (máxima explicação, curiosidades)
      A2 → depth=2 (média)
      B1 → depth=1 (concisa)
    - Categorização inteligente por palavra-chave na pergunta

  Dicas — showHint(chId, i):
    - Cada clique revela a próxima dica oculta
    - Animação: fade + slide da esquerda

================================================================================
  9. TREINADOR DE CONJUGAÇÃO VERBAL
================================================================================

  renderConjugationTrainer(chId):
    - Obtém verbos do capítulo via getChapterVerbs(chId)
    - Ordena por dificuldade: regular → irregular → auxiliary → separable → modal
    - Renderiza para cada verbo:
      - Card com nome, significado, tipo, progresso
      - 6 linhas de conjugação (PRONOUNS)
      - Input + botão dica + status (✅/❌)
      - Botões "Verificar Todos" e "Reset"
      - Deep Dive educacional (generateVerbDeepDive)
      - DNA do verbo (VERB_DNA.renderDNA)
      - Conexões verbais (GermanVerbConnectionsSystem.render)
      - Engenharia da palavra (GermanWordEngineeringSystem.render)
    - Barra de maestria do capítulo

  getChapterVerbs(chId):
    - Filtra VERB_DB pelos verbos com chapter.includes(chId)
    - Ordena por tipo (dificuldade)

  checkConjugation(chId, vIdx):
    - Compara 6 inputs com verb.conj[pIdx]
    - Feedback individual por pronome (buildConjFeedback)
    - Atualiza progresso e maestria

  getConjHint(verb, pronounId, isEn):
    - Dicas específicas por tipo de verbo e pronome
    - Auxiliares, modais, separáveis, irregulares, regulares

  buildConjFeedback(verb, pronounId, userAnswer, isCorrect, isEn):
    - Análise personalizada do erro (campo vazio, prefixo esquecido, etc.)
    - Tabela de conjugação completa com destaque
    - Verbos relacionados + exemplo em contexto

  10. DNA DO VERBO (VERB_DNA)

  Namespace: window.VERB_DNA (IIFE)

    stemChange               — mudança de radical
    formality                — contexto social
    dailyUse, writtenUse, spokenUse — uso
    contexts                 — tags de contexto
    importance, priority     — importância pedagógica (1-5)
    learningSpeed            — velocidade de aprendizado
    relatedPatterns          — verbos com mesmo padrão
    verbFamily               — família etimológica
    structuralBehavior       — comportamento sintático
    realExamples             — 3 exemplos reais
    linguisticNotes          — observações linguísticas

  Renderização: VERB_DNA.renderDNA(verb, isEn)
    - Grid de indicadores (frequência, dificuldade, irregularidade, etc.)
    - Uso no idioma (cotidiano, escrita, fala)
    - Importância pedagógica + velocidade
    - Comportamento estrutural
    - Contextos frequentes (tags)
    - Padrões relacionados (tags)
    - Família verbal
    - Exemplos reais
    - Observações linguísticas
    - Engenharia da Palavra (se houver dados)

================================================================================
  12. ENGENHARIA DA PALAVRA (GermanWordEngineeringSystem)
================================================================================

  Namespace: window.GermanWordEngineeringSystem (IIFE)
  Dados: engineering — 38 verbos

  Estrutura:
    {
      prefix,               // prefixo (ex: 'auf', 'ver')
      root,                 // raiz (ex: 'stehen', 'sprech')
      suffix,               // sufixo (ex: 'ier')
      rootFamily,           // família da raiz (ex: 'STEH/STAND')
      explanation: {pt, en},// lógica da construção
      parts: {              // explicações individuais
        pt: { prefix, root, suffix },
        en: { prefix, root, suffix }
      },
      related: []           // palavras relacionadas
    }

  Tipos de entrada:
    - Verbos prefixados (7): aufstehen, einkaufen, anrufen, mitkommen,

  29. INCONSISTÊNCIAS DETECTADAS

  1. [BAIXO] state.adaptive existe mas NÃO é usado ativamente nos exercícios.
     O toggle existe na UI e no state, mas a lógica adaptativa não foi implementada.

  2. [BAIXO] Mini teste aprova com apenas 1 acerto de 3. Decisão de design
     para não frustrar o aluno, mas pode gerar progresso sem domínio real.

  3. [MÉDIO] exerciseCounts (let, linha ~3126) é inicializado como {} mas
     parece ser uma variável de cache não utilizada ou parcialmente implementada.

  4. [BAIXO] A função trackExercise incrementa exerciseTotal mesmo em erros,
     o que pode inflar a porcentagem se o usuário tentar muitas vezes.

  5. [BAIXO] color-mix() CSS é usado extensivamente nos novos sistemas
     (CONEXÕES, WFS, WORD-ENG) mas requer Chrome 111+ / Firefox 113+ / Safari 16.2+.
     Navegadores mais antigos não terão os efeitos de cor.

  6. [BAIXO] O WFS_GRAPH (grafo de conexões entre famílias) é construído
     mas as funções de consulta (findCrossReferences, findConnectionPath)
     não parecem ser usadas ativamente na UI atual.

  7. [BAIXO] A função renderTOC() gera cards para todos os 20 capítulos
     mas não verifica isUnlocked antes de torná-los clicáveis —
     a verificação é feita apenas visualmente (classe .locked).

  8. [BAIXO] O IntersectionObserver observa TODOS os .chapter mas
     renderChapters só cria capítulos desbloqueados. Capítulos bloqueados
     não têm a classe .chapter, então não são observados.

    35. MODO MONTAR FRASES — SENTENCE BUILDER
================================================================================

   35.1 VISÃO GERAL
   ----------------------------------------------------------------------------
   O Modo Montar Frases é um sistema pedagógico de construção de frases
   por blocos (drag and drop). O usuário recebe uma frase em português
   (ou alemão) e blocos de palavras embaralhadas, e deve montar a frase
   na ordem correta.

   Objetivo pedagógico: treinar ordem das palavras, estrutura frasal,
   conjugação, tempos verbais, sintaxe, casos e formação de frases reais
   — ensinando COMO o alemão é construído.

   Namespace: GermanSentenceBuilderCore (IIFE)
   API pública: window.GermanSentenceBuilder
   Container: #mode-sentenceBuilder

   35.2 ARQUITETURA INTERNA
   ----------------------------------------------------------------------------
   O GermanSentenceBuilderCore é uma IIFE isolada com:
     - Banco de frases (SB_PHRASES): organizado por contagem de palavras (2-15)
     - Estado interno (_sbState): dificuldade, streak, erros, histórico
     - Sistema de drag and drop: mouse + touch (mobile/tablet)
     - Sistema de verificação: comparação textual palavra por palavra
     - Sistema de explicações: explicação completa por frase com 15 seções
     - Integração com GPS: trackEvo para métricas de sintaxe
     - Persistência: state.sentenceBuilderState via saveState()

   Funções principais:
     - onModeEnter()        — Chamada ao entrar no modo (GermanModeCore)
     - _renderSidebar()     — Popula a sidebar com estatísticas
     - _pickPhrase()        — Seleciona frase aleatória (com anti-repetição)
     - _renderBlocks()      — Renderiza blocos arrastáveis
     - _verify()            — Verifica resposta do usuário
     - _renderExplanation() — Renderiza explicação completa
     - _nextPhrase()        — Avança para próxima frase
     - _advanceDifficulty() — Aumenta dificuldade (streak)
     - _reduceDifficulty()  — Reduz dificuldade (erros consecutivos)
     - resetBuilder()       — Reseta estado interno

   35.3 INTERFACE DO USUÁRIO
   ----------------------------------------------------------------------------
   Componentes da tela:
     1. Cabeçalho do modo (ícone 🧩, título, descrição)
     2. Barra de estatísticas: palavras atuais, streak, erros consecutivos
     3. Slider de configuração: streak necessária para avançar (1-100, padrão 5)
     4. Card da frase: mostra a frase a ser traduzida
     5. Área de resposta (sb-answer-area): zona de drop para blocos
     6. Banco de palavras (sb-word-bank): blocos embaralhados
     7. Botões: Verificar, Resetar, Continuar
     8. Área de explicação: 15 seções de análise da frase

   35.4 FLUXO DE USO
   ----------------------------------------------------------------------------
   1. Usuário vê frase em português (ou alemão — alterna a cada acerto)
   2. Arrasta blocos do banco para a área de resposta (ou clica)
   3. Clica "Verificar"
   4. Sistema mostra explicação completa (acertando ou errando)
   5. Clica "Continuar" para próxima frase

   Alternância de direção:
     - ptToDe: frase em português → montar em alemão
     - deToPt: frase em alemão → montar em português
     - Alterna automaticamente a cada acerto

   35.5 PERSISTÊNCIA
   ----------------------------------------------------------------------------
   Campos em state.sentenceBuilderState:
     - wordCount:       número atual de palavras (2-15, padrão 2)
     - streak:          acertos consecutivos atuais
     - errorsInARow:    erros consecutivos atuais
     - streakNeeded:    streak necessária para avançar (padrão 5)
     - history:         últimas 20 frases usadas (anti-repetição)
     - totalCorrect:    total de acertos no modo
     - totalAttempts:   total de tentativas
     - lastDirection:   'ptToDe' ou 'deToPt'

   Salvamento ocorre em:
     - Cada acerto (_advanceDifficulty)
     - Cada erro (_reduceDifficulty)
     - Cada nova frase (_nextPhrase)
     - Cada mudança de slider
     - Ao entrar no modo (_loadState)

   35.6 INTEGRAÇÃO COM GERMAN MODE CORE
   ----------------------------------------------------------------------------
   Adições ao GermanModeCore:
     1. MODE_DEFS.sentenceBuilder: definição do modo
     2. _onModeActivated: hook para GermanSentenceBuilder.onModeEnter()
     3. _renderModeSidebarContent: case 'sentenceBuilder'
     4. _renderSentenceBuilderSidebar(): delega para GermanSentenceBuilder

   36.1 ESTRUTURA
   ----------------------------------------------------------------------------
   SB_PHRASES é um objeto indexado por contagem de palavras:

   SB_PHRASES = {
     2: [ {de, pt, deWords, ptWords, cat, tense, expl}, ... ],
     3: [ ... ],
     ...
     15: [ ... ]
   }

   Cada entrada possui:
     - de:          frase em alemão
     - pt:          tradução em português
     - deWords:     array de palavras em alemão (ordem correta)
     - ptWords:     array de palavras em português (ordem correta)
     - cat:         categoria/tema (Casa, Escola, Trabalho, etc.)
     - tense:       tempo verbal (Präsens, Perfekt, Konjunktiv II, etc.)
     - expl:        objeto com explicação completa (15 seções)

   36.2 CATEGORIAS/TEMAS COBERTOS
   ----------------------------------------------------------------------------
   Casa, Escola, Trabalho, Restaurante, Compras, Viagem, Tecnologia,
   Rotina, Clima, Lazer, Amigos, Família, Transporte, Saúde, Emergência,
   Conversação cotidiana, Universidade, Hotel, Mercado

   36.3 PROGRESSÃO GRAMATICAL
   ----------------------------------------------------------------------------
   Frases de 2 palavras:  Präsens simples (SV básico)
   Frases de 3 palavras:  Präsens + modais simples
   Frases de 4 palavras:  Akkusativ, verbos separáveis
   Frases de 5 palavras:  Dativ, Perfekt
   Frases de 6-7 palavras: Perfekt avançado, Konjunktiv II, orações subordinadas
   Frases de 8+ palavras: estruturas complexas, múltiplos complementos

    36.4 ANTI-REPETIÇÃO
    ----------------------------------------------------------------------------
    O sistema mantém um histórico (_sbState.history) com as últimas 20
    frases utilizadas (identificadas pelo texto em alemão). Ao selecionar
    nova frase, frases no histórico são filtradas. Se todas as frases do
    grupo estiverem no histórico, o histórico é reutilizado (fallback).

================================================================================
    37. ALGORITMO DE PROGRESSÃO — STREAK E DIFICULDADE
================================================================================

   37.1 PROGRESSÃO DE DIFICULDADE
   ----------------------------------------------------------------------------
   Início: 2 palavras
   Ao atingir streak necessária (padrão 5 acertos consecutivos):
     → +1 palavra (até máximo de 15)
   Streak é resetada a cada avanço de nível.

   Após atingir 15 palavras:
     → continua indefinidamente em frases de 15 palavras
     → streak continua contando, mas não avança mais

   37.2 REDUÇÃO DE DIFICULDADE
   ----------------------------------------------------------------------------
   Se o usuário errar 2 vezes consecutivas:
     → -1 palavra (nunca abaixo de 2)
     → erros consecutivos resetam para 0

   37.3 CONFIGURAÇÃO DE STREAK
   ----------------------------------------------------------------------------
   Slider na interface (1-100, padrão 5):
     - Controla quantos acertos consecutivos são necessários
     - Permite progressão mais rápida (1-2) ou mais lenta (10+)
     - Persistido em state.sentenceBuilderState.streakNeeded

   37.4 INDICADORES
   ----------------------------------------------------------------------------
   Mostrados na barra de estatísticas:
     - Palavras atuais: X (número de palavras na frase atual)
     - Streak: Y/Z (acertos atuais / necessários para avançar)
     - Erros consecutivos: N

================================================================================
    38. SISTEMA DE EXPLICAÇÕES — EXPLICAÇÕES POR FRASE
================================================================================

   38.1 ESTRUTURA DA EXPLICAÇÃO
   ----------------------------------------------------------------------------
   Cada frase possui um objeto `expl` com 15 seções de análise:

   1.  literal:       Tradução literal palavra por palavra
   2.  natural:       Tradução natural idiomática
   3.  words:         Array de {w (palavra), g (classe gramatical), f (função)}
   4.  order:         Explicação da ordem das palavras
   5.  conj:          Conjugação completa do verbo
   6.  verb:          Infinitivo original e tipo do verbo
   7.  tenseLab:      Tempo verbal com explicação
   8.  cases:         Casos gramaticais utilizados
   9.  decl:          Declinações de artigos/substantivos
   10. reason:        Motivo da construção frasal
   11. nuance:        Nuances de uso e significado
   12. pron:          Pronúncia relevante (IPA aproximado)
   13. commonErr:     Erros comuns de brasileiros
   14. extra:         Observações extras e curiosidades
   (15. implícito:    Tudo integrado ao fluxo de resposta)

   38.2 RENDERIZAÇÃO
   ----------------------------------------------------------------------------
   As explicações são renderizadas em seções coloridas:
     - translation:    roxo claro (borda primária) — traduções
     - grammar:        ciano claro (borda accent) — classes gramaticais
     - word-order:     verde claro (borda success) — ordem das palavras
     - cases:          amarelo claro (borda warn) — casos e declinações
     - common-errors:  vermelho claro (borda error) — erros comuns
     - pronunciation:  lilás claro (borda #8b5cf6) — pronúncia
     - conjugation:    ciano (borda accent2) — conjugação e tempos

   Cada seção possui um label em maiúsculas com ícone para rápida
   identificação visual.

   38.3 EXIBIÇÃO
   ----------------------------------------------------------------------------
   A explicação é mostrada:
     - Ao acertar (ícone ✅ "Correto!")
     - Ao errar (ícone ❌ "Incorreto — veja a resposta")
   Sempre. Nunca é pulada. O botão "Continuar" aparece junto.

   ----------------------------------------------------------------------------
   1. Usuário inicia com 2 palavras — frases simples no presente
   2. A cada 5 acertos consecutivos, +1 palavra
   3. Progressão gramatical: presente → modais → acusativo → dativo →

   5. Máximo de 15 palavras — continua infinitamente
   6. Alternância automática PT→DE e DE→PT a cada acerto
   7. Explicações completas em cada resposta (acerto ou erro)
   8. Anti-repetição: últimas 20 frases não se repetem
   9. Integração com GPS: métricas alimentam o dashboard de evolução
   10. Persistência completa: estado salvo automaticamente

   42.2 ESTRUTURA TRILÍNGUE
   ----------------------------------------------------------------------------
   Cada frase no banco SB_PHRASES possui três idiomas:

     pt:      Tradução em português
     de:      Frase original em alemão
     en:      Tradução em inglês

   Blocos de palavras (word blocks):
     deWords:  Palavras alemãs (ordem correta)
     ptWords:  Palavras em português
     enWords:  Palavras em inglês

   Explicações:
     expl:     Explicação completa em português (15 seções)
     explEn:   Explicação completa em inglês (15 seções)

   42.3 DICIONÁRIO SB_I18N
   ----------------------------------------------------------------------------
   O dicionário SB_I18N contém todas as strings de UI visíveis ao

   SB_I18N.pt = {
     title, subtitle, wordsLabel, streakLabel, errorsLabel,

     emptyHint, verify, reset, continue, correct, incorrect,
     correctAnswer, translation, literal, natural, wordAnalysis,

     sidebarWords, sidebarStreak, sidebarCorrect, sidebarAttempts,
     sidebarDirection, diffBadge, modalName, modalSidebarTitle
   }

   SB_I18N.en = { ... mesmo conjunto em inglês ... }

   A helper function _sbT(key) seleciona a tradução correta
   baseada em state.lang ('pt' ou 'en').

   42.4 RENDERIZAÇÃO DINÂMICA
   ----------------------------------------------------------------------------
   Ao entrar no modo (onModeEnter), _refreshAllUIText() atualiza todos
   os elementos estáticos da interface:

     - Título e subtítulo do modo
     - Labels de estatísticas (Palavras/Streak/Erros)
     - Label de configuração do slider
     - Textos dos botões (Verificar/Resetar/Continuar)
     - Hint da área vazia (arraste os blocos)
     - Botão do modo na sidebar
     - Badge de dificuldade

   A função _renderPhraseCard() seleciona a frase a ser exibida
   baseada no idioma atual: quando o usuário está em inglês e a
   direção é ptToDe, mostra-se phrase.en em vez de phrase.pt.

   A função _getWords() seleciona os blocos de palavras corretos:
   quando o idioma é inglês e a direção é deToPt, retorna enWords
   em vez de ptWords.

   A função _renderExplanation() seleciona o objeto de explicação:
   quando o idioma é inglês, usa _currentPhrase.explEn.

   42.5 ADAPTAÇÃO CULTURAL
   ----------------------------------------------------------------------------
   As explicações em inglês (explEn) foram escritas especificamente
   para falantes de inglês:

     - Erros comuns: "English speakers often..." (não "Brasileiros")
     - Terminologia gramatical: usa termos da gramática inglesa
       (present continuous, past participle, dative case, etc.)
     - Contexto cultural: referências relevantes para anglófonos
     - Comparações: alemão vs. inglês (não vs. português)

   Exemplo de diferença:
     PT: "Brasileiros frequentemente dizem 'Ich bin wohne'..."
     EN: "English speakers often say 'Ich bin wohne'..."

   42.6 ALTERNÂNCIA AUTOMÁTICA
   ----------------------------------------------------------------------------
   A alternância de direção (ptToDe ↔ deToPt) é independente
   do idioma da interface:

     Usuário em PT:
       Rodada 1: "Eu moro" → montar "Ich wohne" (PT→DE)
       Rodada 2: "Ich wohne" → montar "Eu moro" (DE→PT)

     Usuário em EN:
       Rodada 1: "I live" → montar "Ich wohne" (EN→DE)
       Rodada 2: "Ich wohne" → montar "I live" (DE→EN)

   O alemão (DE) é sempre o elemento constante. A língua nativa
   do usuário alterna como origem/destino a cada acerto.

   42.7 INTEGRAÇÃO COM O SISTEMA I18N GLOBAL
   ----------------------------------------------------------------------------
   O sistema SB_I18N é independente mas complementar ao sistema
   i18n global (LANG / _t / applyLang). A separação existe porque
   o modo Montar Frases possui terminologia específica que não se
   aplica a outros modos.

   Quando o usuário troca o idioma nas configurações:
     1. state.lang é atualizado
     2. applyLang() é chamada (i18n global)
     3. GermanModeCore.renderModeSidebar() é chamada
     4. Se o modo ativo for sentenceBuilder:
        a. _renderSidebar() chama _refreshAllUIText()
        b. Todos os textos são atualizados via _sbT()
     5. Se o usuário entrar no modo depois: onModeEnter() atualiza tudo

   Não há duplicação de estado: ambos os sistemas leem state.lang.

   42.8 PERSISTÊNCIA
   ----------------------------------------------------------------------------
   O idioma selecionado persiste normalmente via state.lang.
   Não há estado adicional específico de idioma para o modo.
   A seleção de idioma controla a renderização, não o estado interno.

   33. NAVEGAÇÃO DO MODO MÚSICA — SISTEMA DE RETORNO
================================================================================

   33.1 VISÃO GERAL
   ----------------------------------------------------------------------------
   O Modo Música implementa um sistema profissional de navegação entre duas
   sub-views: Lobby e Detail. A navegação é gerenciada por transições CSS
   animadas com preservação completa de estado, sem recarregar a página
   ou destruir o DOM.

   Objetivo: simular a experiência de navegação de um aplicativo real de
   música, onde o usuário navega entre telas com transições suaves.

   33.2 ARQUITETURA DE NAVEGAÇÃO INTERNA
   ----------------------------------------------------------------------------
   O GermanMusicCore gerencia duas sub-views dentro de #mode-music:

   #music-lobby:
     - Grid de cards das músicas
     - Renderizado UMA ÚNICA VEZ (_lobbyRendered = true)
     - Nunca destruído — apenas ocultado/mostrado via CSS

   #music-detail:
     - Página individual da música com capa, tags, letra
     - Conteúdo renderizado sob demanda (render cache via data-song-id)
     - Botão de voltar fixo (HTML estático, listener reatribuído)

   33.3 FLUXO DE NAVEGAÇÃO LOBBy → DETAIL
   ----------------------------------------------------------------------------
   1. Usuário clica em um card de música (onclick → showSong)
   2. _lobbyScrollY = window.scrollY (salva posição do scroll do lobby)
   3. Lobby recebe classe music-lobby-exit → animação de saída (26s)
   4. Conteúdo da detail é renderizado (se data-song-id diferente)
   5. Back button recebe onclick → GermanMusicMode.showLobby()
   6. setTimeout 280ms:
      a. lobby.style.display = 'none' + remove exit class
      b. detail.style.display = 'block' + music-detail-visible → animação de entrada
      c. window.scrollTo(0, 0)

   33.4 FLUXO DE NAVEGAÇÃO DETAIL → LOBBy (BOTÃO VOLTAR)
   ----------------------------------------------------------------------------
   1. Usuário clica no botão "← Voltar ao Lobby"
   2. Detail recebe classe music-detail-exit → animação de saída (28s)
   3. Lobby.style.display = 'block' + music-lobby-enter → animação de entrada
   4. setTimeout 280ms:
      a. detail.style.display = 'none' + remove exit class
      b. lobby remove enter class
      c. window.scrollTo(0, _lobbyScrollY) — restaura posição exata do lobby
   5. Sidebar é re-renderizada (GermanModeCore.renderModeSidebar)

   33.5 BOTÃO DE VOLTAR — DESIGN E FUNCIONAMENTO
   ----------------------------------------------------------------------------
   POSIÇÃO: O botão fica NO FINAL da view da música, ABAIXO da letra,
   dentro de uma seção .music-back-section centralizada.

   HTML (renderizado dinamicamente dentro de #music-detail-content):
     <div class="music-back-section">
       <button id="music-back-btn" class="music-back-btn">
         <span class="back-arrow">←</span> Voltar ao Catálogo
       </button>
     </div>

   CSS:
     .music-back-section: text-align:center, padding 32px 0 48px
     .music-back-btn:
       - display inline-flex com gap 10px, padding 14px 28px
       - border-radius 14px, border 1.5px solid var(--border)
       - background var(--bg2), box-shadow sutil
       - transition: all .25s cubic-bezier(.4,0,.2,1)

   Hover:
     - background var(--primary3), color var(--primary)
     - border-color var(--primary)
     - transform: translateY(-2px) + box-shadow ampliado
     - seta (.back-arrow) desliza 4px para esquerda (translateX)

   Active (click):

   Listener:
     - Reatribuído após cada renderização (showSong / onModeEnter)

   33.6 PRESERVAÇÃO DE ESTADO
   ----------------------------------------------------------------------------
   Variáveis de estado no GermanMusicCore:
     _currentView          — 'lobby' | 'detail'
     _currentSongId        — ID da música atual (ou null)
     _lobbyScrollY         — posição de scroll do lobby (salva ao sair)
     _lobbyRendered        — flag: cards já foram renderizados

   Persistência (state.musicState):
     currentSong            — ID da última música aberta
     currentView            — 'lobby' | 'detail'
     lobbyScrollY           — posição de scroll do lobby

   Salvamento:
     - showSong(id)          → salva _lobbyScrollY (se vindo do lobby)
     - renderLobby()         → salva _currentView='lobby', _currentSongId=null
     - showLobby()           → salva _currentView='lobby', _currentSongId=null
     - _saveState()          → persiste no localStorage via saveState()

   Restauração (onModeEnter):
     - _loadState() restaura _currentView, _currentSongId, _lobbyScrollY
     - Se currentView='detail' + currentSong válido → restaura detail view
     - Senão → mostra lobby

   33.7 ANIMAÇÕES DE TRANSIÇÃO
   ----------------------------------------------------------------------------
   Classes CSS de animação (todas @keyframes):

   Entrada do Lobby:
     .music-lobby-enter → musicLobbyIn (3s)
     from: opacity:0, translateY(8px) → to: opacity:1, translateY(0)

   Saída do Lobby:
     .music-lobby-exit → musicLobbyOut (26s)
     from: opacity:1, translateY(0) → to: opacity:0, translateY(-8px)

   Entrada da Detail:
     .music-detail-visible → musicDetailIn (4s)
     from: opacity:0, translateY(16px) → to: opacity:1, translateY(0)

   Saída da Detail:
     .music-detail-exit → musicDetailOut (28s)
     from: opacity:1, translateY(0) → to: opacity:0, translateY(8px)

   Todas as animações usam animation-fill-mode: forwards para manter
   o estado final após a conclusão.

   33.8 CACHE DE RENDERIZAÇÃO
   ----------------------------------------------------------------------------
   Para evitar renderizações duplicadas ao clicar na mesma música:

   - #music-detail-content possui atributo data-song-id
   - showSong() verifica: contentEl.getAttribute('data-song-id') !== id
   - Se a música já está renderizada → pula innerHTML, apenas mostra detail
   - Se música diferente → renderiza novo conteúdo e atualiza data-song-id

   Benefícios:
     - Evita flicker ao reabrir a mesma música
     - Preserva estado de scroll da letra (se aplicável)
     - Reduz operações de DOM desnecessárias

   33.9 PREVENÇÃO DE CONFLITOS E DUPLICAÇÕES
   ----------------------------------------------------------------------------
   Regras implementadas:

   1. NENHUM addEventListener para o back button — usa onclick (sobrescreve)
   2. _lobbyRendered impede re-renderização do grid de cards
   3. data-song-id impede re-renderização do conteúdo da detail
   4. _initialized impede dupla inicialização do módulo
   5. Variáveis internas no escopo do IIFE (não globais)
   6. window.GermanMusicMode apenas com as funções essenciais

   33.10 COMPATIBILIDADE COM O SISTEMA MULTIMODO
   ----------------------------------------------------------------------------
   A navegação interna (lobby ↔ detail) NÃO interage com o GermanModeCore:
     - GermanModeCore gerencia a troca ENTRE modos (chapters, music, etc.)
     - GermanMusicCore gerencia a troca DENTRO do modo música
     - Transições internas usam display + animation, não afetam outros modos
     - Scroll do modo música é gerenciado separadamente pelo GermanModeCore

   Ao trocar de modo (ex: music → chapters):
     - GermanModeCore.saveScrollPosition('music') salva window.scrollY
     - GermanModeCore.restoreScrollPosition('music') restaura ao voltar
     - GermanMusicCore.onModeEnter() restaura estado interno
     - _lobbyScrollY persiste no state.musicState (cross-mode)

   33.11 PERFORMANCE
   ----------------------------------------------------------------------------
   - Lobby cards renderizados 1x (nunca destruídos)
   - Detail content com cache por song ID
   - Transições via CSS (GPU accelerated: opacity + transform)
   - Sem setInterval, sem requestAnimationFrame desnecessário
   - setTimeout de 280ms apenas para sincronizar animações
   - Nenhum listener duplicado

   33.12 RESPONSIVIDADE
   ----------------------------------------------------------------------------
   O botão de voltar é responsivo:
     - Desktop: tamanho normal, margem 24px superior
     - Tablet (<768px): mesmo comportamento (botão inline-flex)
     - Mobile (<480px): padding adapta-se naturalmente
   Nenhum breakpoint específico necessário para o botão de voltar.

   34.1 VISÃO GERAL
   ----------------------------------------------------------------------------
   O Catálogo Musical é o lobby do Modo Música — a primeira tela que o
   usuário vê ao entrar no modo. Ele exibe cards visuais das músicas
   disponíveis em um grid responsivo.

   Atualmente: 1 música (Ein Schiff wird kommen por Lale Andersen)
   Expansão futura: múltiplas músicas organizadas por nível/tema

   34.2 ESTRUTURA DO CATÁLOGO
   ----------------------------------------------------------------------------
   HTML:
     <div id="music-lobby">
       <div class="music-lobby-header">
         <div class="music-lobby-icon">🎵</div>
         <h2 class="music-lobby-title">Música & Aprendizado</h2>
         <p class="music-lobby-sub">Aprenda alemão através de músicas autênticas</p>
       </div>
       <div id="music-lobby-grid" class="music-lobby-grid">
         <!-- Cards gerados dinamicamente por _buildLobbyCards() -->
       </div>
     </div>

   O grid usa CSS Grid com auto-fill e minmax(280px, 1fr), adaptando-se
   automaticamente ao número de músicas.

   34.3 CARD DE MÚSICA
   ----------------------------------------------------------------------------
   Cada card (.music-card) contém:
     - .music-card-thumb: capa da música (thumbnail YouTube, aspect-ratio 16:9)
     - .music-card-thumb-overlay: gradiente overlay na capa
     - .music-card-play: ícone play circular (surge no hover)
     - .music-card-info: título, artista, badge de nível, duração
     - .music-card-glow: efeito glow no hover

   Interações:
     - Hover: card eleva (translateY -4px), glow, play button aparece
     - Click: chama GermanMusicMode.showSong(id) → navega para detail view
     - onerror na img: fallback para ícone 🎵

   34.4 RENDERIZAÇÃO DO CATÁLOGO
   ----------------------------------------------------------------------------
   _buildLobbyCards():
     - Chamada UMA única vez (_lobbyRendered = true)
     - Gera innerHTML do #music-lobby-grid
     - Nunca destruído — ao voltar da detail view, apenas re-exibido

   renderLobby():
     - Chamada na entrada inicial do modo música
     - Gerencia animação de entrada (music-lobby-enter)

   showLobby():
     - Chamada pelo botão de voltar
     - Gerencia animação de saída da detail + entrada do lobby
     - Restaura scroll position (_lobbyScrollY)

   34.5 EXPANSÃO DO CATÁLOGO
   ----------------------------------------------------------------------------
   Para adicionar uma nova música:
     1. Adicionar entrada ao array SONGS no GermanMusicCore
     2. Fornecer: id, title, artist, youtubeId, thumbnail, duration,
        level, tags, lyrics
     3. NENHUMA outra modificação necessária
