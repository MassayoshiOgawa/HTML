1.1 PURPOSE
This document provides the complete specification for recreating an extremely
faithful version of the game "Don't Starve" (originally developed by Klei
Entertainment, released 2013) as a single self-contained HTML file. The target
version is the original launch version of Don't Starve (circa April 2013),

1.3 GAME OVERVIEW
Don't Starve is a survival action-adventure game with procedural world
generation, permanent death (unless resurrected via specific game mechanics),
roguelike elements, crafting, base building, and exploration. The player
controls Wilson (or other unlockable characters in later versions, but the
target version focuses on Wilson) who has been transported to a mysterious
wilderness world by a shadowy figure named Maxwell.

3.1 GAME LOOP

The game loop MUST use requestAnimationFrame for smooth 60fps rendering.

Structure:
function gameLoop(timestamp) {
    const dt = Math.min((timestamp - lastTimestamp) / 1000, 0.05);
    lastTimestamp = timestamp;
    gameTime += dt;

    // FIXED TIME STEP for physics/simulation (10 updates per second)
    accumulator += dt;
    while (accumulator >= FIXED_DT) {
        fixedUpdate(FIXED_DT);
        accumulator -= FIXED_DT;
    }

    // Variable time step for rendering
    update(dt);
    render(interpolation);
}

FIXED_DT = 0.033 (roughly 30 ticks per second for simulation)

3.2 EVENT SYSTEM (EventBus)

A publish/subscribe event system decouples all game systems.

Interface:
EventBus.on(eventName, callback, context)
EventBus.off(eventName, callback)
EventBus.emit(eventName, data)
EventBus.once(eventName, callback)

Implementation:
const EventBus = (function() {
    const listeners = {};
    return {
        on: function(name, cb, ctx) {
            if (!listeners[name]) listeners[name] = [];
            listeners[name].push({cb: cb, ctx: ctx || null});
        },
        off: function(name, cb) {
            listeners[name] = (listeners[name] || []).filter(l => l.cb !== cb);
        },
        emit: function(name, data) {
            (listeners[name] || []).forEach(l => l.cb.call(l.ctx, data));
        },
        once: function(name, cb) {
            const wrapper = function(data) { cb(data); EventBus.off(name, wrapper); };
            EventBus.on(name, wrapper);
        }
    };
})();

Events that MUST be emitted:
- 'day.start' - when dawn begins
- 'day.dusk' - when dusk begins
- 'day.night' - when night begins
- 'season.change' - when seasons change (data: {season: 'winter'|'autumn'})

3.5 CAMERA SYSTEM

The camera follows the player with smooth interpolation.

Properties:
- x, y: Camera position (top-left corner of view in world coords)
- targetX, targetY: Where camera wants to be (player position - screen/2)
- zoom: Float, default 1.0, range 0.5 to 2.0
- targetZoom: Float, for smooth zooming

Behavior:
- Camera follows player with slight lag (lerp factor 0.08 per frame)
- Camera bounds: cannot go outside world boundaries
- Zoom changes via scroll wheel, stored in save
- World-to-screen: screenX = (worldX - camera.x) * zoom
- Screen-to-world: worldX = screenX / zoom + camera.x

Viewport culling:
- Only render entities within a margin of the visible area
- Margin = 200 pixels in each direction
- checkBounds: return entity.x > camera.x - margin &&
  entity.x < camera.x + canvas.width/zoom + margin &&
  entity.y > camera.y - margin &&
  entity.y < camera.y + canvas.height/zoom + margin

3.8 SEEDED RANDOM NUMBER GENERATOR

All procedural generation must use a seeded PRNG to ensure reproducibility.

Implementation (Mulberry32 or similar simple PRNG):

function SeededRandom(seed) {
    this.seed = seed;
    this.next = function() {
        let t = this.seed += 0x6D2B79F5;
        t = Math.imul(t ^ t >>> 15, t | 1);
        t ^= t + Math.imul(t ^ t >>> 7, t | 61);
        return ((t ^ t >>> 14) >>> 0) / 4294967296;
    };
    this.nextInt = function(min, max) {
        return Math.floor(this.next() * (max - min + 1)) + min;
    };
    this.nextFloat = function(min, max) {
        return this.next() * (max - min) + min;
    };
    this.pick = function(array) {
        return array[Math.floor(this.next() * array.length)];
    };
    this.shuffle = function(array) {
        for (let i = array.length - 1; i > 0; i--) {
            const j = Math.floor(this.next() * (i + 1));
            [array[i], array[j]] = [array[j], array[i]];
        }
        return array;
    };
}

The world seed is generated randomly on new game. Display the seed on the
screen so players can share/recreate worlds. Allow entering a specific seed
for reproducible worlds.

Seed range: 0 to 2147483647 (32-bit integer).

5.4 WORLD GENERATION PROCESS

Step 1: Generate height map using layered Perlin simplex noise
    - Use 3 octaves with decreasing amplitude
    - Octave 1: amplitude 1.0, frequency 0.005
    - Octave 2: amplitude 0.5, frequency 0.01
    - Octave 3: amplitude 0.25, frequency 0.02
    - Normalize to 0-1 range

Step 2: Assign biomes based on height and additional noise map
    - Below 0.3: swamp/marsh areas (if moisture noise high)
    - 0.3-0.5: grassland
    - 0.5-0.6: savanna
    - 0.6-0.7: forest
    - 0.7-0.8: deciduous forest
    - Above 0.8: rocky
    - Use a second "moisture" noise map to differentiate:
        - High moisture + mid height = swamp
        - Low moisture + mid height = savanna

Step 3: Place biome-specific decorations
    - For each biome, randomly scatter decorations (grass tufts, saplings,
      berry bushes, etc.)
    - Density varies by biome: e.g., forest has many trees but few grass tufts

Step 4: Place set pieces
    - Maxwell's Light (ring of fire with items)
    - Checkerboard floor with chess pieces
    - Pig King surrounded by torches
    - Graveyard with headstones and ghosts at night
    - Touching stone (resurrection structure)
    - Wormholes (pairs of connected teleportation points)

Step 5: Place resources
    - Scatter flint, rocks, gold nuggets, etc.
    - Ensure minimum resources near spawn point

Step 6: Place roads
    - Pathfinding-based road generation connecting set pieces
    - Some cobblestone paths in chess biome areas

Step 7: Spawn initial entities
    - Place starting resources (near spawn)
    - Place passive mobs (beefalo, butterflies, rabbits, birds)
    - Place hostile mobs (spiders, hounds) away from spawn
    - Create initial player at spawn point

5.5 NOISE IMPLEMENTATION

Implement 2D Perlin Noise or Simplex Noise from scratch (no libraries).

Implementation steps:
1. Create permutation table (shuffle 0-255 based on seed)
2. Implement fade function: t * t * t * (t * (t * 6 - 15) + 10)
3. Implement lerp: a + t * (b - a)
4. Implement gradient dot product
5. Combine into 2D noise(x, y) function returning -1 to 1
6. Implement octave noise (fractal Brownian motion)

5.6 BIOME GENERATION ALGORITHM

function generateBiomes(world, rng) {
    // 1. Generate base noise map (terrain height)
    const heightMap = generateNoiseMap(world.width, world.height, 0.005, rng);

    // 2. Generate moisture noise map
    const moistureMap = generateNoiseMap(world.width, world.height, 0.008, rng);

    // 3. Generate temperature noise map
    const tempMap = generateNoiseMap(world.width, world.height, 0.004, rng);

    // 4. Assign biomes using rules
    for (let y = 0; y < world.height; y++) {
        for (let x = 0; x < world.width; x++) {
            const h = heightMap[y][x];
            const m = moistureMap[y][x];
            const t = tempMap[y][x];

            if (h < 0.25) {
                if (m < 0.3) biome = 'marsh';
                else biome = 'swamp';
            } else if (h < 0.4) {
                biome = 'grassland';
            } else if (h < 0.55) {
                if (m > 0.6) biome = 'savanna';
                else biome = 'grassland';
            } else if (h < 0.7) {
                if (t > 0.5) biome = 'deciduous';
                else biome = 'forest';
            } else if (h < 0.85) {
                biome = 'forest';
            } else {
                biome = 'rocky';
            }

            // Force specific biomes near boundaries or set pieces
            // Apply biome to world tile
        }
    }

    // 5. Apply smoothing: if 5+ of 8 neighbors share a biome, change this tile too
    smoothingPass(world, 2); // 2 passes
}

CHAPTER 11: COMBAT SYSTEM
================================================================================

11.1 BASICS
Kiting combat: attack then retreat during enemy wind-up.
Most enemies have a visible wind-up animation before attacking.

11.2 DAMAGE CALCULATION
Player damage = weapon damage * character multiplier (Wilson=1.0)
Damage taken = rawDamage * (1-armor1) * (1-armor2)
Example: Log Suit (80%) + Football Helmet (80%):
  damage = 20 * 0.2 * 0.2 = 0.8
  armor1 durability loss = 20 * 0.8 = 16
  armor2 durability loss = 20 * 0.8 = 16
Unarmed: 10 damage

11.3 ATTACK CYCLE
Player: wind-up (0.2s) -> hit -> recovery (0.3s) -> cooldown (0.5s)
Enemy: wind-up (0.3-1.0s) -> attack -> recovery (0.3-1.0s)

11.4 HITSTUN & KNOCKBACK
0.2-0.5s freeze, pushed 8-16px away from attacker

11.5 WEAPON STATS

11.6 TARGETING

Move to cancel

11.7 AGGRO

Triggers: player in detection range, attack on same-type, aggro items, low sanity
Detection: Spider=40px, Hound=100px, Tentacle=120px, Pig=neutral
Chase range: 80-160px from spawn (hounds chase endlessly)

CHAPTER 24: SOUND SYSTEM

24.1 AUDIO MANAGER
All sounds generated procedurally via Web Audio API.
AudioContext created on first user interaction.

AudioManager interface:
- generate(name, generatorFn): creates and caches AudioBuffer
- play(name, volume=1.0, loop=false, rate=1.0): plays sound
- stop(name): stops looping sounds
- setMasterVolume(level): 0.0-1.0
- createSoundSprite(name, start, duration): for sound variations

24.2 SOUND LIST

FOOTSTEPS:
  Grass: filtered white noise, 50ms, LP 800Hz
  Wood: click + low thump, 60Hz, 60ms
  Stone: higher click, 150Hz, 40ms

WEAPON/COMBAT:
  Spear hit: 400Hz->150Hz sweep, 100ms, saw wave
  Fist hit: 200Hz->100Hz sweep, 80ms, square
  Player hurt: 500Hz->200Hz, 200ms, distortion
  Mob hurt: varies by creature
  Death: 200Hz->30Hz, 1000ms, high distortion

ITEM:
  Pickup: 300Hz->600Hz, 100ms, sine
  Drop: 200Hz->100Hz, 80ms, sine
  Equip: 300Hz click, 30ms, square
  Unequip: 250Hz click, 30ms, square
  Eat: 80Hz rumble, 200ms, filter noise
  Chew: 3 short 60Hz clicks, 50ms each

CRAFT/BUILD:
  Craft: 3 short beeps (200,300,400Hz), 50ms each, square, 10ms gap
  Build: low thud, 100Hz, 150ms, sine+noise
  Prototype: ascending 4 beeps (300,400,500,600Hz)

FIRE:
  Crackle: random noise bursts 80-120Hz, random timing (100-300ms interval)
  Roar: filtered noise 200Hz, bandpass, continuous

NATURE:
  Wind: filtered noise + LFO, low volume
  Rain: white noise filtered at 4kHz, continuous (visual only)
  Thunder: noise explosion 100-500Hz, 1-2s
  Bird chirp: 2-4kHz rapid sine sweep, 50ms
  Cricket: 4kHz pulse, 100ms, every 1-2s (night)
  Frog croak: 150Hz sine, 300ms (swamp)
  Bee buzz: 220+330Hz sine, tremolo, quiet
  Spider chitter: 2kHz rapid clicks, 8-12 over 200ms
  Pig grunt: 150Hz sine, 300ms
  Beefalo moo: 100Hz sine, 500ms
  Hound bark: saw wave 200->400->200Hz, 200ms

AMBIENT:
  Night: low drone 55Hz (A1), very quiet, occasional chirps
  Day: gentle pad (C3,E3,G3), very quiet, bird chirps
  Winter: wind noise, low rumble
  Swamp: frog croaks, buzzing
  Forest: bird chirps, rustling leaves
  Cave: dripping water, echoey drone
  Insanity: whispers (filtered noise + vocal formants, very quiet)

UI:
  Menu click: 500Hz beep, 30ms, square
  Menu hover: 600Hz beep, 20ms, sine
  Inventory open: 400Hz, 100ms, sine
  Inventory close: 300Hz, 100ms, sine
  Map open: 500Hz->600Hz, 150ms
  Map close: 600Hz->500Hz, 150ms
  Warning: 800Hz pulse, 100ms, repeating
  Alarm: 500-800Hz alternating, 200ms each

CHARLIE:
  Growl: 80Hz rumble + distortion, 500ms
  Attack: 200Hz->50Hz, 300ms, high distortion

24.3 AMBIENT LAYERS
3 ambient layers controlled by day/night and biome:
1. Base layer: biome-specific (wind, bugs, etc.)
2. Time layer: day (birds) / dusk (crickets) / night (owls)
3. Event layer: hound wave (howling), insanity (whispers)
Each layer is a looping AudioBufferSourceNode with volume control.

24.4 VOLUME SETTINGS

Category volumes: SFX, Music, Ambient (relative to master)
Individual sounds: randomized pitch (+/- 20%) to reduce repetition

25.1 STORAGE
Uses browser localStorage. One save slot (the current world).

Save key: 'dontstarve_save'
Save format: JSON string

25.2 SAVE DATA STRUCTURE
{
    version: number,           // Save format version (incremental)
    seed: number,              // World generation seed
    created: number,           // Timestamp of world creation
    lastSaved: number,         // Timestamp of last save
    totalDays: number,         // Days survived
    season: string,
    dayTime: number,           // Current time within day cycle
    
    player: {
        x: number,
        y: number,
        health: number,
        hunger: number,
        sanity: number,
        temperature: number,
        beardStage: number,
        inventory: [{ type, count, data }], // Serialized ItemStacks
        equipment: { weapon, head, body },  // Serialized ItemStacks
        prototyped: string[],  // List of prototyped recipe names
        stats: { maxHealth, maxHunger, maxSanity }
    },
    
    world: {
        tiles: Array,          // Only modified tiles (compact format)
        entities: [{
            id, type, subtype, x, y,
            components: { health, burnable, growable, etc. }
        }],
        structures: [{
            id, type, x, y, health, fuel, data
        }]
    },
    
    stats: {
        daysSurvived: number,
        mobsKilled: { [mobType]: number },
        itemsCrafted: { [itemType]: number },
        distanceWalked: number,
        deaths: number
    },
    
    settings: {
        zoom: number,
        masterVolume: number,
        sfxVolume: number,
        musicVolume: number
    }
}

25.3 SERIALIZATION
Custom serialize/deserialize functions for game state:
- Entities: convert to plain objects, strip methods
- ItemStacks: { type, count, data: { ...perishable info, durability } }
- Tiles: only store tiles that have been modified (harvested, burned, etc.)
  Format: { x, y, type, decoration, hasTree, burnt, ... }

25.4 SAVE FREQUENCY
- Auto-save every 60 seconds of real time
- Save on quit (pause menu -> Save & Quit)
- Save on season change
- Save on important events (crafting prototype, structure build)
- DO NOT save on death (save is cleared on death)

25.5 LOAD PROCESS
1. Check if save exists in localStorage
2. Validate version number
3. Reconstruct world from seed + saved modifications
4. Reconstruct entities from saved data
5. Place player at saved position with saved stats/inventory
6. Restore game state (day count, season, time of day, settings)

25.6 VALIDATION
- Check version field matches current version
- Check for corrupt data (negative health, NaN positions)
- If invalid: show "Save corrupted" message, return to main menu
- Minimum validation: every field must exist and be the right type

25.7 DELETE SAVE
- On death: save is deleted
- On "New Game": save is deleted
- On manual "Delete Save" in options

CHAPTER 26: PERFORMANCE & OPTIMIZATION
================================================================================

26.1 PERFORMANCE TARGETS
- 60 FPS on modern browsers (Chrome, Firefox, Edge)
- 30 FPS minimum on older machines
- Memory: < 200 MB RAM usage
- Load time: < 5 seconds (procedural generation time)

26.2 RENDERING OPTIMIZATION

Viewport Culling:
- Only render entities within visible area + 200px margin
- Only render tiles within visible area + 1 tile margin
- Check visibility per entity in EntityManager.renderAll

Tile Rendering:
- Pre-tile: render all visible tiles to an offscreen canvas ONCE
- Only re-render when tiles change (harvest, burn, etc.)
- Draw pre-rendered tile canvas as single image to main canvas

Light Mask Optimization:
- Cache light mask between frames (only redraw when lights change)
- Use offscreen canvas for light mask
- Combine all light sources into single mask draw call
- For many lights: only include lights within visible area

Sprite Batching:
- Group nearby sprites and draw them from cached sprite sheets
- Use nearest-neighbor scaling (ctx.imageSmoothingEnabled = false)

26.3 ENTITY OPTIMIZATION

Object Pooling:
- Particles: recycle particle objects when they die
- Dropped items: pool item entities
- Damage numbers: reuse text objects
- Projectiles: pool projectile entities

Entity Limits:
- Max active mobs: 200
- Max particles: 500
- Max dropped items: 100
- When exceeding limits, remove oldest/dead entities first

Spatial Indexing:
- Divide world into 2D grid of chunks (e.g., 8x8 tiles per chunk)
- Only update/check collisions for entities in chunks near player
- Useful for AI detection: only check enemies in nearby chunks

26.4 AI OPTIMIZATION
- Only update AI for mobs within 200px of player
- Mob update frequency: every 5 ticks for distant mobs, every tick for nearby
- Pathfinding: limit A* range to 50 tiles, cache paths when possible
- Limit simultaneous pathfinding calls to 3 per frame

26.5 MEMORY OPTIMIZATION

Memory Management:
- Clear references to destroyed entities immediately
- Use WeakRef or manual cleanup for event listener references
- Limit sound buffer cache to 50 sounds (discard least recently used)
- Procedural textures stored as canvas elements (not ImageData)
- Clear particle arrays when transitioning between areas (not applicable for top-down)

Garbage Collection Prevention:
- Reuse objects instead of creating new ones each frame
- Object pooling for frequently created/destroyed objects
- Avoid string concatenation in tight loops (use array join)
- Avoid creating closures in update loops

26.6 LOAD TIME OPTIMIZATION
- Loading screen with progress bar during startup
- Generate assets in order of priority:
  1. First: tile textures (needed for world rendering)
  2. Second: player sprites
  3. Third: common mob sprites (spider, pig, beefalo)
  4. Fourth: item sprites
  5. Fifth: structure sprites
  6. Last: rare mob sprites
- Display percentage complete on loading screen
- Use setTimeout/setInterval to yield to UI thread during generation
- Generate audio buffers lazily (on first play)

26.7 NETWORK (not needed - single player, offline)

26.8 FRAME SKIP
If frame takes too long to render, skip some particle updates
and reduce AI update frequency. Dynamic quality adjustment:
- If FPS < 30: reduce particle count by 50%
- If FPS < 20: reduce AI update frequency by 50%
- If FPS < 10: show "Low Performance" warning
