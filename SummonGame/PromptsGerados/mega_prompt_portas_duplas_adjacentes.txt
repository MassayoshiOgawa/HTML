================================================================================
1. DESCRICAO DA IDEIA
================================================================================

No jogo SummonGame, portas sao entidades individuais representadas pelo tile 'd'
no mapa ASCII. Cada porta funciona de forma independente: abrir uma porta nao
afeta as outras.

A IDEA: Quando duas (ou mais) portas estiverem uma ao lado da outra
ortogonalmente (cima, baixo, esquerda, direita), elas devem se fundir em um
grupo de "portas duplas". Ao interagir com QUALQUER porta do grupo, TODAS as
portas do grupo abrem/fecham simultaneamente. Visualmente, o grupo deve ser
renderizado como uma unica porta MAIOR que ocupa o espaco combinado dos tiles.

DIAGONAL NAO CONTA: Duas portas na diagonal (ex: (x,y) e (x+1,y+1)) NAO formam
um grupo. Somente vizinhanca ortogonal direta (4 direcoes) e considerada.

O QUE ISSO SIGNIFICA NA PRACTICA:
- Se houver 2 portas lado a lado na horizontal |d d|, elas formam 1 grupo de 2.
- Se houver 2 portas lado a lado na vertical (uma em cima da outra), formam
  1 grupo de 2.
- Se houver 3 portas em linha |d d d|, TODAS as 3 formam 1 grupo (grupo com
  mais de 2 portas).
  MIDDLE door tem vizinha dos dois lados, entao faz parte do mesmo grupo.
- Se houver 4 portas em quadrado 2x2, TODAS formam 1 grupo (todas sao vizinhas
  ortogonais de pelo menos uma outra).
- Se houver 2 portas separadas por parede, NAO formam grupo.

3.1 - MODIFICACOES NA CLASSE DoorEntity

Adicionar ao CONSTRUCTOR:
  this.group = null;     // referencia ao grupo (ou array de portas do grupo)
  this.groupId = -1;     // id do grupo (-1 = sem grupo)

OU alternativamente:
  this.groupMembers = null;  // array de DoorEntity do mesmo grupo, ou null

OBSERVACAO: A escolha entre usar um array estatico global de grupos vs
propriedades individuais em DoorEntity fica a criterio da implementacao,
desde que seja possivel, dado um DoorEntity qualquer, obter todas as outras
DoorEntity do mesmo grupo.

Novo metodo:
  hasGroup() { return this.groupMembers !== null && this.groupMembers.length > 0; }
  (ou similar)

Metodo toggle() MODIFICADO:
  Ao invocar toggle() em uma porta que pertence a um grupo, DEVE chamar
  toggle() em TODAS as portas do grupo (incluindo ela mesma).
  CUIDADO: Deve evitar loop infinito! Sugestao:
    - Adicionar um parametro opcional `skipGroup = false` ao toggle()
    - toggle() chama toggle(true) nas outras portas do grupo
    - toggle() com skipGroup=true so executa a logica padrao sem propagar

  Exemplo de logica:
    toggle(skipPropagation = false) {
      if (this.animating || this.debounceTimer > 0) return;
      if (!skipPropagation && this.groupMembers) {
        for (const member of this.groupMembers) {
          if (member !== this) member.toggle(true);
        }
      }
      this.open = !this.open;
      this.animating = true;
      this.animTimer = 0;
    }

Metodo forceOpen() MODIFICADO:
  Deve propagar para todas as portas do grupo tambem.
  Sugestao: forceOpen() verifica se ha grupo, e chama forceOpen() nos membros.

NOTA: O getter solid() deve refletir o estado individual de cada porta no grupo.
Cada porta mantem seu proprio estado open/animating independente. O toggle()
apenas garante que todas comecam a abrir/fechar juntas, mas o estado real de
cada uma e individual (elas podem estar em momentos ligeiramente diferentes
da animacao se o codigo for chamado no mesmo frame, o que e aceitavel).

3.2 - LOGICA DE AGRUPAMENTO (GROUP DETECTION)

LOCAL: Dentro de Game.loadMap(), IMEDIATAMENTE apos a linha:
  this.doorEntities = mapData.doors.map(d => new DoorEntity(d.x, d.y));

Adicionar o codigo de agrupamento:

PASSO 1: Construir mapa de indices
  Criar uma matriz 2D (mapWidth x mapHeight) inicializada com -1.
  Para cada DoorEntity em this.doorEntities, armazenar seu indice na matriz
  na posicao (tileX, tileY).

PASSO 2: Flood-fill / BFS para encontrar grupos ortogonais
  Para cada door nao visitada, fazer BFS nas 4 direcoes (cima, baixo,
  esquerda, direita) para encontrar todas as portas ortogonalmente conectadas.
  Cada componente conexo forma 1 grupo.

PASSO 3: Atribuir grupo
  Para cada grupo encontrado (componente com 2+ portas):
    - Atribuir um groupId unico
    - Para cada porta no grupo, armazenar a lista de todas as outras portas
      do grupo (groupMembers)
  Portas isoladas (sem vizinhas ortogonais) nao recebem grupo.

ALGORITMO SUGERIDO (flood-fill simples):
  visited = {} (conjunto de "x,y")
  groups = []
  for each door in doorEntities:
    key = door.tileX + ',' + door.tileY
    if key in visited: continue
    // BFS para encontrar todas portas conectadas ortogonalmente
    queue = [door]
    component = []
    while queue not empty:
      current = queue.shift()
      cKey = current.tileX + ',' + current.tileY
      if cKey in visited: continue
      visited[cKey] = true
      component.push(current)
      // Checa 4 vizinhos
      for each [dx, dy] in [[0,-1],[0,1],[-1,0],[1,0]]:
        nx = current.tileX + dx
        ny = current.tileY + dy
        neighborDoor = doorEntities.find(d => d.tileX === nx && d.tileY === ny)
        if neighborDoor:
          nKey = nx + ',' + ny
          if nKey not in visited:
            queue.push(neighborDoor)
    // Se component tem 2+ portas, e um grupo
    if component.length >= 2:
      for each door in component:
        door.groupMembers = component.filter(d => d !== door)
        // (ou armazenar o array completo em cada porta)

OBS: Usar um Map ou objeto para acesso O(1) ao vizinho baseado em "x,y".

3.3 - MODIFICACOES NA RENDERIZACAO (renderDoors)

O metodo Game.renderDoors() (linha ~2558) precisa ser modificado para
renderizar portas agrupadas como uma UNICA porta GRANDE.

LOGICA:
  Para cada porta em doorEntities:
    SE porta pertence a um grupo E e a porta "primaria" do grupo
    (ex: a primeira do grupo no array, ou a de menor tileX + tileY):
      - Pular (nao renderizar individualmente)
    SE porta pertence a um grupo E e a porta "primaria":
      - Calcular bounding box do grupo:
        minX = min(tileX do grupo), maxX = max(tileX do grupo)
        minY = min(tileY do grupo), maxY = max(tileY do grupo)
      - Largura em tiles: (maxX - minX + 1)
      - Altura em tiles: (maxY - minY + 1)
      - Renderizar UMA unica porta GRANDE que ocupa todo o espaco do grupo:
        sx = minX * TILE_SIZE - camX
        sy = minY * TILE_SIZE - camY
        sw = (maxX - minX + 1) * TILE_SIZE
        sh = (maxY - minY + 1) * TILE_SIZE
      - Fundo: INTERIOR_COLOR preenchendo todo o bounding box
      - Porta fechada: DOOR_CLOSED_COLOR com margem proporcional:
        Se grupo horizontal (width > height):
          portaWidth = sw * 0.85
          portaHeight = sh * 0.7
        Se grupo vertical (height > width):
          portaWidth = sw * 0.7
          portaHeight = sh * 0.85
        Senao (quadrado 2x2 etc):
          portaWidth = sw * 0.8
          portaHeight = sh * 0.8
        Centralizar a porta dentro do bounding box
      - Animacao:
        Se animating, usar animProgress medio do grupo (media dos progressos)
        OU usar o progresso da porta primaria para determinar a abertura.
        A barra de abertura deve crescer da borda inferior para cima (porta
        de correr/deslizar pra cima) OU do centro para as laterais.

    SE porta NAO pertence a grupo:
      - Renderizar normalmente (codigo existente)

DETALHES VISUAIS:
  - Porta dupla horizontal (2 tiles lado a lado):
    Uma larga porta de 64px de largura, 32px de altura.
    Moldura mais larga, Unique closed color, puxador centralizado.
  - Porta dupla vertical (2 tiles empilhados):
    Uma alta porta de 32px de largura, 64px de altura.
  - Grupo 2x2 (4 portas em quadrado):
    Uma grande porta de 64px x 64px.

  ANIMACAO DA PORTA GRANDE:
    Em vez de animar encolhendo horizontalmente (como a porta individual),
    a porta grande deve animar de forma diferente:
    - Abrindo: a porta "sobe" (encurta verticalmente de baixo para cima)
      ou "desliza" para o lado.
    - O efeito visual mais dramatico: as duas folhas da porta abrem para
      fora (cada metade vai para seu lado), mas isso requereria mais
      complexidade. Para simplificar, usar:
      - Abrir horizontalmente: do centro para as bordas (as duas metades
        encolhem para as laterais), ou
      - Abrir verticalmente: de baixo para cima (a porta sobe)
    SUGESTAO SIMPLES: Usar o mesmo sistema de animProgress, onde a porta
    grande encolhe de altura (vertical) OU de largura (horizontal),
    dependendo da orientacao.
    - Grupo horizontal (lado a lado): animProgress controla a ALTURA da porta
      (porta "sobe" como uma porta de garagem)
    - Grupo vertical (empilhado): animProgress controla a LARGURA da porta
      (porta desliza para o lado)
    - Isso da uma sensacao visual diferente e claramente distinguivel de
      uma porta normal.

  renderDoors(ctx) {
    const ts = TILE_SIZE;
    const doorRange = 160;
    for (const door of this.doorEntities) {
      const sx = door.tileX * ts - this.camX;
      const sy = door.tileY * ts - this.camY;
      if (sx + ts < -50 || sx > this.canvas.width + 50 || sy + ts < -50 || sy > this.canvas.height + 50) continue;
      const dx = door.tileX * ts + ts / 2;
      const dy = door.tileY * ts + ts / 2;
      let near = false;
      for (const pl of this.players) {
        if (!pl.alive) continue;
        const pdx = pl.px - dx;
        const pdy = pl.py - dy;
        if (Math.sqrt(pdx * pdx + pdy * pdy) < doorRange) { near = true; break; }
      }
      if (!near) continue;
      ctx.fillStyle = INTERIOR_COLOR;
      ctx.fillRect(sx, sy, ts, ts);
      if (door.animating) {
        ctx.fillStyle = DOOR_CLOSED_COLOR;
        ctx.fillRect(sx + ts * 0.1, sy + ts * 0.1, ts * 0.8 * door.animProgress, ts * 0.8);
      } else if (!door.open) {
        ctx.fillStyle = DOOR_CLOSED_COLOR;
        ctx.fillRect(sx + ts * 0.1, sy + ts * 0.1, ts * 0.8, ts * 0.8);
      }
    }
  }
