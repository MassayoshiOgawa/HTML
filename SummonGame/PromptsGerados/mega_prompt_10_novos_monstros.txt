VISAO GERAL DA ARQUITETURA DO SISTEMA DE MONSTROS (para consulta rapida)
================================================================================

- MonsterTypes: objeto com definicoes dos tipos de monstro.
  Campos: name, desc, weight (peso para selecao aleatoria), chaseLoseTime,
  searchDuration, spawnCount, color, strokeColor, speedMod, randomSpawn.
  Atualmente: normal, blueman, twins, glitch (4 tipos).

- MonsterEntity: classe do monstro. Construtor recebe tileX, tileY, game,
  monsterType. Propriedades principais:
  * px, py, speed (70 base), alive, state (patrol/chase/search/taunted)
  * currentWaypoint, waypointOrder, facingAngle
  * chaseTimer, searchTimer, lastKnownPlayerPos
  * attackCooldown, game, path, pathTarget, pathRecalc
  * type (string), chaseLoseTime, searchDuration, bodyColor, bodyStroke, name
  * stunTimer, tauntTimer, tauntTarget, preTauntState
  * Metodos: spawn(), die(), update(dt), render(ctx, game),
    findNearestPlayer(), canSeePlayer(), canDetectBehind(),
    hasLineOfSight(), canMoveTo(), checkNearbyDoors(), followPath(dt),
    updatePatrol(dt), updateChase(dt), updateSearch(dt), updateTaunted(dt)

- FSM (Finite State Machine):
  * patrol: segue waypoints aleatorios usando BFS pathfinding.
  * chase: persegue o jogador mais proximo via BFS. Se perder de vista
    por chaseLoseTime segundos, transita para search.
  * search: vai ate lastKnownPlayerPos. Se chegar ou searchDuration
    expirar, volta para patrol.
  * taunted: vai ate o tauntTarget (trap de noise maker). Ao expirar
    tauntTimer, volta ao estado anterior.

- Velocidade: speed = getMonsterSpeed() * speedMod no spawn.
  Durante chase/taunted: speed * 1.4 no followPath().

- Spawn: Game.spawnMonster() usa weightedRandom(MonsterTypes) para
  escolher o tipo. Cria MonsterEntity, define speed, chama spawn().
  Se randomSpawn=true, spawna em ponto aleatorio do mapa.

- Render: MonsterEntity.render() desenha corpo circular (raio = TILE_SIZE*0.38),
  chapeu amarelo, olhos brancos com pupilas vermelhas, indicador de direcao.
  Se taunted: mostra "!!!" pulsando. Se oracleReveal ativo: overlay amarelo.
  Fog of war: so renderiza se isPointVisible() ou debugMode ou oracleReveal.

- Ataque: distancia < TILE_SIZE * 0.8 causa takeDamage(20) com 1s cooldown.

- Stun: stunTimer > 0 bloqueia update (monstro nao se move, nao ataca).

- Pathfinding BFS: Game.findPath(startTileX, startTileY, endTileX, endTileY).
  Considera tiles 'O' e 'W' como obstaculos, portas solidas bloqueiam.

- Traps: game.traps[] com { x, y, item, active, stun, trapColor, trapRadius,
  tauntDuration, tauntTimer, tauntedMonster }. O loop de traps verifica
  distancia do monstro e aplica stun.

- Artifacts: game.artifactEntities[] com ArtifactEntity { tileX, tileY,
  collected, glowPhase }. Coleta via hold E (interacao), chama collectArtifact().

- ActivateAbility: game.activateAbility() e chamada quando player pressiona F.
  Definida como funcao global activateAbility(game, player).

COMPORTAMENTO:
- A Ballerina SO se move quando NENHUM jogador esta "olhando" para ela.
- "Olhando" = a direcao de movimento do jogador (facing) esta apontando
  para a Ballerina, dentro de um cone de visao.
- Como determinar se um jogador esta olhando:
  1. Calcular o angulo do jogador para a Ballerina:
     angleToBallerina = Math.atan2(ballerina.py - player.py, ballerina.px - player.px)
  2. Calcular o angulo de facing do jogador (direcao de movimento):
     playerFacing = Math.atan2(player.lastDy, player.lastDx)
     NOTA: se player.lastDx === 0 && player.lastDy === 0 (jogador nunca
     se moveu), considerar que NAO esta olhando (player parado = nao olha).
  3. Calcular a diferenca angular:
     let diff = angleToBallerina - playerFacing;
     while (diff > Math.PI) diff -= Math.PI * 2;
     while (diff < -Math.PI) diff += Math.PI * 2;
  4. Se Math.abs(diff) < Math.PI / 3 (60 graus = cone de 120 graus):
     o jogador ESTA olhando para a Ballerina.
  5. A distancia NAO importa para o "olhar" - se o jogador esta olhando
     na direcao, congela a Ballerina independente da distancia.
     (O jogador pode estar do outro lado do mapa; se estiver olhando
     na direcao, a Ballerina para.)

- Se PELO MENOS 1 jogador (vivo) esta olhando: a Ballerina CONGELA.
  * Nao se move (skip do movimento no update).
  * AINDA pode atacar se um jogador estiver muito perto (distancia < TILE_SIZE*0.8).
  * O FSM (patrol/chase/search) continua rodando, mas o movimento e bloqueado.
- Se NENHUM jogador esta olhando: a Ballerina se move normalmente.

- A verificacao de "olhando" deve ser feita a CADA FRAME.
