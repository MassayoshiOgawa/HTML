FIX 3: Jester - sempre andando, so parar quando pego por trap
================================================================================

PROBLEMA: O Jester (MonsterType 'jester') vai ate uma trap e para ao lado dela sem pisar, porque o threshold de contato (nearestDist < TILE_SIZE * 0.2, ~6.4px) e muito rigoroso. O pathfinding leva o Jester ate o centro do tile, mas a coordenada exata da trap pode estar numa posicao que nao satisfaz esse threshold.

LOCAL: Funcao updateJester(), linhas ~2403-2431.

CODIGO ATUAL:
  updateJester(dt) {
    if (this.stunTimer > 0) { this.stunTimer -= dt; if (this.stunTimer <= 0) this.stunTimer = 0; return; }
    let nearest = null; let nearestDist = Infinity;
    for (const t of this.game.traps) {
      const dx = t.x - this.px; const dy = t.y - this.py;
      const dist = Math.sqrt(dx * dx + dy * dy);
      if (dist < nearestDist) { nearestDist = dist; nearest = t; }
    }
    if (!nearest) { this.trapSeeking = false; return; }
    if (nearestDist < TILE_SIZE * 0.2) {
      this.stunTimer = nearest.stun || 0;
      const idx = this.game.traps.indexOf(nearest);
      if (idx >= 0) this.game.traps.splice(idx, 1);
      this.path = null;
      return;
    }
    this.jesterPathRecalc -= dt;
    const stx = Math.floor(this.px / TILE_SIZE);
    const sty = Math.floor(this.py / TILE_SIZE);
    const gtx = Math.floor(nearest.x / TILE_SIZE);
    const gty = Math.floor(nearest.y / TILE_SIZE);
    if (!this.path || this.jesterPathRecalc <= 0) {
      this.path = this.game.findPath(stx, sty, gtx, gty);
      this.jesterPathRecalc = 0.5;
    }
    if (this.path && this.path.length > 0) {
      this.followPath(dt);
    }
  }

ANALISE DO PROBLEMA:
- O Jester encontra a trap mais proxima
- Se nearestDist < TILE_SIZE * 0.2 (6.4px) → pisa na trap (stun e remove)
- Senao: recalcula path periodica e segura e segue o path
- O path leva ao centro do tile (gtx, gty), nao a coordenada exata da trap (nearest.x, nearest.y)
- Quando chega no centro do tile ao lado da trap, o Jester pode parar porque this.path se esgota (path.length === 0) e nao ha logica para continuar andando
- O Jester so recalcula o path quando this.path e null OU jesterPathRecalc <= 0, mas se o path existe e tem length 0, ele nunca recalcula

ALTERACAO:

1. Alterar a condicao de pisar na trap de nearestDist < TILE_SIZE * 0.2 para nearestDist < TILE_SIZE * 0.6 (~19.2px). Isso garante que o Jester pise na trap assim que chegar no tile adjacente.

2. Garantir que o Jester SEMPRE tenha um path valido para andar enquanto houver traps no mapa, so parando quando stunTimer > 0. Modificar a logica para:
   - Se stunTimer > 0: decrementar e retornar (parado)
   - Encontrar nearest trap
   - Se nearestDist < TILE_SIZE * 0.6: pisar na trap (stun, remover, path = null, retornar)
   - Senao: recalcular path para o tile da nearest trap a cada frame (sem depender de jesterPathRecalc == 0 ou path existente). Usar uma logica mais simples: sempre recalcular o path se ele for null ou tiver comprimento 0, com taxa de recalc maxima de 0.1s para evitar CPU excessiva.
   - Se o path existe e tem length > 0: seguir o path

3. Remover a condicao if (!nearest) { this.trapSeeking = false; return; } — em vez disso, se nao houver traps, o Jester deve se mover aleatoriamente ou patrulhar waypoints (comportamento padrao de patrulha). IMPORTANTE: o Jester nao deve ficar parado mesmo sem traps.

4. Verificar se a propriedade this.trapSeeking e usada em outro lugar; se nao for, pode ser removida ou mantida como inercial.

CODIGO NOVO (esboco):
  updateJester(dt) {
    if (this.stunTimer > 0) { this.stunTimer -= dt; if (this.stunTimer <= 0) this.stunTimer = 0; return; }
    let nearest = null; let nearestDist = Infinity;
    for (const t of this.game.traps) {
      const dx = t.x - this.px; const dy = t.y - this.py;
      const dist = Math.sqrt(dx * dx + dy * dy);
      if (dist < nearestDist) { nearestDist = dist; nearest = t; }
    }
    if (nearest && nearestDist < TILE_SIZE * 0.6) {
      this.stunTimer = nearest.stun || 0;
      const idx = this.game.traps.indexOf(nearest);
      if (idx >= 0) this.game.traps.splice(idx, 1);
      this.path = null;
      return;
    }
    if (nearest) {
      const gtx = Math.floor(nearest.x / TILE_SIZE);
      const gty = Math.floor(nearest.y / TILE_SIZE);
      if (!this.path || this.path.length === 0) {
        const stx = Math.floor(this.px / TILE_SIZE);
        const sty = Math.floor(this.py / TILE_SIZE);
        this.path = this.game.findPath(stx, sty, gtx, gty);
        this.jesterPathRecalc = 0.5;
      }
      if (this.path && this.path.length > 0) {
        this.followPath(dt);
      } else {
        // Path falhou ou esta bloqueado, anda em direcao a trap diretamente
        this.moveToward(nearest.x, nearest.y, dt);
      }
    } else {
      // Sem traps: patrulha ou move aleatoriamente (NAO parar)
      this.patrolBehavior(dt);
    }
  }

NOTA: O metodo moveToward() pode ser implementado como movimento linear em direcao a (targetX, targetY) usando a velocidade do monstro. O metodo patrolBehavior() pode reutilizar a logica existente de patrulha de waypoints (updatePatrol, etc.).
