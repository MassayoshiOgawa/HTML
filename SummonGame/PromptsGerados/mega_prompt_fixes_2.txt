FIX 2B: Primeiro jogador selecionado = USUARIO (o proprio priest)
================================================================================

PROBLEMA: Quando o menu abre (keysJustPressed[kb.ability]), o codigo
atual define menuOpen = true mas NAO define menuSelectedIndex. O indice
atual (vindo do construtor = 0 ou do ultimo ciclo) e usado. No primeiro
ciclo de tap (quando a tecla e solta), o menuSelectedIndex avanca para
o proximo jogador, pulando o usuario.

CAUSA RAIZ: O tapPending e processado no MESMO evento de abertura.
Quando o jogador pressiona F:
  1. keysJustPressed: menuOpen = true, menuUseTapPending = true
  2. No mesmo frame (ou frame seguinte), ao soltar: processa o tap
     e CICLA para o proximo jogador (pois menuUseTapPending = true).
O menu abre E imediatamente cicla, pulando o usuario.

SOLUCAO: Separar "abrir menu" de "ciclar selecao". No primeiro pressionar
de F (quando o menu estava fechado), apenas ABRIR o menu com o usuario
selecionado. NAO ativar tapPending. Apenas em pressionamentos SUBSEQUENTES
(menu ja aberto), ativar tapPending para ciclar.

LOCAL: Player.update(), bloco do helpfulpriest.

CODIGO ATUAL (aproximado):
  if (keysJustPressed[kb.ability]) {
    this.menuOpen = true;
    this.menuUseTapPending = true;
    this.menuUseTimer = 0;
    keysJustPressed[kb.ability] = false;
  }

CODIGO NOVO:
  if (keysJustPressed[kb.ability]) {
    keysJustPressed[kb.ability] = false;
    if (!this.menuOpen) {
      // MENU ESTAVA FECHADO -> ABRIR com usuario selecionado
      this.menuOpen = true;
      this.menuSelectedIndex = this.playerIndex;  // USA O PROPRIO INDICE
      this.menuUseTapPending = false;  // NAO processa tap neste ciclo
      this.menuUseTimer = 0;
    } else {
      // MENU JA ESTAVA ABERTO -> preparar para ciclar
      this.menuUseTapPending = true;
      this.menuUseTimer = 0;
    }
  }

EXPLICACAO DETALHADA:
- Se o menu estava FECHADO (!this.menuOpen):
  * Abre o menu.
  * Define menuSelectedIndex = this.playerIndex (o indice do proprio
    Helpful Priest no array game.players). Ex: se o priest e o jogador 2
    (indice 1), comeca selecionado nele mesmo.
  * NAO ativa tapPending (false). Quando a tecla for solta, nao cicla.
    O menu fica aberto com o usuario selecionado.

- Se o menu JA ESTAVA ABERTO:
  * Ativa tapPending (true). Quando a tecla for solta (tap), cicla para
    o proximo jogador.
  * O comportamento de ciclagem e fechamento no ultimo jogador deve estar
    implementado (do fix anterior).

COMPORTAMENTO FINAL (playerCount > 1):
  1. Pressiona F: menu abre, usuario (indice = playerIndex) selecionado.
  2. Solta F: nada acontece (tapPending estava false).
  3. Pressiona F de novo: tapPending = true.
  4. Solta F: cicla para playerIndex + 1.
  5. Continua pressionando/soltando: cicla ate o ultimo jogador.
  6. No ultimo jogador, ao soltar: menu fecha.

COMPORTAMENTO FINAL (playerCount === 1 - SOLO):
  1. Pressiona F: menu abre, usuario (indice 0) selecionado.
  2. Solta F: nada acontece (sem outros jogadores para ciclar).
  3. Pressiona F de novo (menu ja aberto): tapPending = true.
  4. Solta F: processa tap.
     Com a logica de "fechar no ultimo": menuSelectedIndex (0) >= playerCount-1 (0)
     -> fecha o menu. OU: como so ha 1 jogador, o tap simplesmente fecha.

FIX 2E: Tratamento do hold (segurar F) com a nova logica
================================================================================

Com a nova logica, o hold (segurar F por >= 1s) funciona assim:

1. Pressiona F: menu abre com usuario selecionado. tapPending = false.
2. Segura F: o codigo de hold (menuUseTimer += dt) entra em acao.
   - Como tapPending === false, o codigo do hold executa normalmente.
   - Apos 1s: applyPriestEffect e chamado (se helpfulpriestUsed === false).
3. Solta F: como tapPending era false, nada acontece.

IMPORTANTE: O codigo de hold NAO deve ser afetado pela nova logica.
Verificar se a condicao do hold esta correta:

  if (keys[kb.ability]) {
    if (this.menuUseTapPending) {
      // Modo tap: timer < 0.3s -> se passar, cancela tap e entra em hold
      this.menuUseTimer += dt;
      if (this.menuUseTimer >= 0.3) {
        this.menuUseTapPending = false;
        this.menuUseTimer = 0;
      }
    } else {
      // Modo hold: timer acumula ate 1.0s
      this.menuUseTimer += dt;
      if (this.menuUseTimer >= 1.0 && !this.helpfulpriestUsed) {
        applyPriestEffect(game, this);
        this.helpfulpriestUsed = true;
        this.menuOpen = false;
        this.menuUseTimer = 0;
      }
    }
  }

Com a nova logica:
- Primeiro pressionar F: menuOpen = true, tapPending = false.
  O codigo de hold (else) roda imediatamente, acumulando timer.
  Se o jogador segurar por 1s, a habilidade e usada. PERFEITO.
- Segundo pressionar F (menu ja aberto): tapPending = true.
  Timer acumula. Se < 0.3s e soltar: tap -> cicla.
  Se >= 0.3s: cancela tap (tapPending = false), entra em hold.
  Se continuar ate 1s: usa habilidade. PERFEITO.

A nova logica funciona corretamente com o hold!
