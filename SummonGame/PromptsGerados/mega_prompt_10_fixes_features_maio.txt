ITEM 7: FIX BALLERINA - SO CONGELA NO CAMPO DE VISAO RAYCAST
================================================================================

CONCEITO: A Ballerina atualmente congela quando QUALQUER jogador esta
virado em direcao a ela (isPlayerLooking). A correcao e: ela so deve
congelar se o jogador que esta olhando para ela TAMBEM a tem dentro do
campo de visao iluminado (isPointVisible). Se o jogador esta virado para
ela mas NAO a ve (atras de uma parede, fora do alcance de visao), ela
continua andando.

LOCAL: MonsterEntity.isBeingWatched() - metodo que verifica se PELO MENOS
UM jogador vivo esta olhando para a Ballerina.

CODIGO ATUAL:
  isBeingWatched() {
    for (const p of this.game.players) {
      if (p.alive && this.isPlayerLooking(p)) return true;
    }
    return false;
  }

CODIGO NOVO:
  isBeingWatched() {
    for (const p of this.game.players) {
      if (!p.alive) continue;
      if (!this.isPlayerLooking(p)) continue;
      // Verificar se a Ballerina esta dentro do campo de visao do jogador
      if (this.game.isPointVisible(this.px, this.py)) return true;
    }
    return false;
  }

EXPLICACAO: isPointVisible(px, py) verifica se o ponto (monstro) esta
dentro de algum poligono de visibilidade de qualquer jogador. Como
isPointVisible ja verifica TODOS os poligonos de TODOS os jogadores
vivos (uniao de visoes), o resultado e: a Ballerina so congela se
ALGUM jogador pode ve-la (esta no campo de visao iluminado).

IMPORTANTE: Isso significa que em modo multiplayer, se um jogador P1
esta olhando para a Ballerina mas NAO a tem no campo de visao, e P2
tambem nao a ve, a Ballerina continua andando. Se P2 tem a Ballerina
no campo de visao (mesmo sem olhar para ela), isPointVisible retorna
true para o ponto dela (porque isPointVisible verifica se QUALQUER
jogador ilumina o ponto). Neste caso, a Ballerina congelaria se P1
esta olhando e P2 ilumina o ponto. Este comportamento esta CORRETO -
a logica e: "Alguem pode me ver?" (isPointVisible) + "Alguem esta
olhando para mim?" (isPlayerLooking). Se ambas as condicoes sao
verdadeiras para o MESMO jogador ou jogadores diferentes, ela congela.

ITEM 10: ICONES DA HOTBAR IGUAIS AOS DA LOJA (UNIFICAR RENDERIZACAO)
================================================================================

CONCEITO: Atualmente os icones da loja usam funcoes Canvas 2D
(ItemIcons[it.icon]) enquanto os icones da hotbar usam classes CSS
(.item-icon.icon-beartrap). E necessario unificar: a hotbar deve
usar os MESMOS icones Canvas 2D que a loja usa, garantindo aparencia
identica. Deve-se lidar com o problema de escala (os slots da hotbar
tem tamanhos variaveis dependendo de hotbarSize e layout).

================================================================================
ESTRATEGIA DE IMPLEMENTACAO
================================================================================

A hotbar e renderizada via innerHTML (DOM). Para usar icones Canvas 2D,
cada slot ocupado da hotbar deve conter um elemento <canvas> em vez de
<span class="item-icon icon-...">. Apos definir o innerHTML, os canvases
devem ser desenhados com a respectiva funcao ItemIcons.

PASSO 1: Na funcao updateHotbarHUD(), alterar a geracao de HTML dos slots.

CODIGO ATUAL (para slot com item, dentro do loop de slots):
  if (it) {
    html += '<span class="item-icon icon-' + it.icon + '"></span>';
  }

CODIGO NOVO:
  if (it) {
    html += '<canvas class="item-canvas" data-item="' + item +
      '" width="' + slotSize + '" height="' + slotSize +
      '" style="width:' + slotSize + 'px;height:' + slotSize + 'px;"></canvas>';
  }

IMPORTANTE: O atributo data-item deve conter a CHAVE do item (ex: 'beartrap',
'landmine', etc.), nao o objeto item. Use a variavel 'item' que ja e a
string da chave.

PASSO 2: Apos definir container.innerHTML, desenhar os icones nos canvases.

Adicionar o seguinte bloco APOS a linha 'container.innerHTML = html;'
no final de updateHotbarHUD():

  // Render ItemIcons on hotbar canvases
  var canvases = container.querySelectorAll('.item-canvas');
  for (var ci = 0; ci < canvases.length; ci++) {
    var cvs = canvases[ci];
    var itemKey = cvs.getAttribute('data-item');
    if (!itemKey) continue;
    var iconFn = ItemIcons[itemKey];
    if (!iconFn) continue;
    var ctx2 = cvs.getContext('2d');
    var cw = cvs.width;
    var ch = cvs.height;
    ctx2.clearRect(0, 0, cw, ch);
    // Centralizar o icone no canvas, com margem de 15% para padding
    var iconSize = Math.min(cw, ch) * 0.7;
    iconFn(ctx2, cw / 2, ch / 2, iconSize);
  }

EXPLICACAO:
  - Cada canvas tem width/height = slotSize (definido pelo sistema de hotbar).
  - O canvas e criado com o tamanho exato do slot.
  - ItemIcons[itemKey] e a funcao que desenha o icone (ex: ItemIcons.beartrap).
  - iconSize = 70% do tamanho do slot para dar padding (mesmo comportamento
    visual da loja que usa size=22 em slots maiores).
  - ctx2.clearRect limpa o canvas antes de desenhar (evita acumulo).
  - O centro do canvas e (cw/2, ch/2).

PASSO 3 (OPCIONAL): Remover as classes CSS de icones antigos (.icon-beartrap,
.icon-landmine, etc.) se nao forem mais usadas em nenhum outro lugar.
VERIFIQUE se as classes CSS de icones sao usadas em outros lugares alem
da hotbar (ex: tela de selecao de classes). Se forem usadas apenas na
hotbar, podem ser removidas do CSS.

ATENCAO: As classes CSS de icones de ITENS (.icon-beartrap, .icon-landmine,
etc.) sao DIFERENTES das classes CSS de icones de CLASSES (.class-icon-oracle,
.class-icon-scout, etc.). NAO remova as classes de icones de classes.
