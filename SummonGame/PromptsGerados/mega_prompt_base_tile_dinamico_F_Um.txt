================================================================================
1. DESCRICAO DA IDEIA
================================================================================

No jogo SummonGame, existem tiles especiais que atualmente sao SEMPRE tratados
como piso interno (floor / INTERIOR_COLOR / 'C'):

  - F = Artifact Spawn
  - U = Waypoint
  - m = Random Monster Spawn
  - (e tambem P, M, S, T, mas estes NAO estao no escopo desta alteracao)

O PROBLEMA: Os tiles F, U, m podem estar localizados em areas externas
rodeadas por grama (G). Porem, atualmente eles sao SEMPRE renderizados com
cor e textura de chao interno (INTERIOR_COLOR), e o player ao pisar neles
e considerado "dentro de casa" (roof desaparece, visao total). Isso e
inconsistente quando, por exemplo, um artefato (F) esta no meio do jardim.

A SOLUCAO: Implementar um sistema de resolucao DINAMICA de base para os
tiles F, U, m. A cada loadMap(), analisar os 8 vizinhos (Moore neighborhood)
de cada tile F/U/m para determinar se visualmente e funcionalmente ele deve
ser tratado como chao (C/floor) ou como grama (G/grass).

REGRAS DE RESOLUCAO:

  1. Olhar os 8 tiles vizinhos ao redor de F/U/m (dx = -1..1, dy = -1..1,
     excluindo o proprio tile).

  2. CONTAR apenas tiles 'C' (floor) e tiles 'G' (grass).
     - Tiles 'd' (porta) contam como 'C' (ambiente interno).
     - Qualquer outro tile (O, W, A, P, M, S, T, m, F, U) e IGNORADO
       na contagem (nao conta como C nem G).

  3. Se floorCount >= grassCount:
       Resolver como 'C' (floor) — tile tratado como interno.
     Se grassCount > floorCount:
       Resolver como 'G' (grass) — tile tratado como externo.

  4. Para tiles NORMAIS (C, G, O, d, W, A, P, M, S, T), a resolucao e
     simplesmente o proprio tile (sem alteracao de comportamento).

IMPACTO EM TODO O SISTEMA:
  - Visual: F/U/m renderizados com cor e autotiling de grass ou floor
    dependendo da vizinhanca.
  - Roof: player sobre F/U/m resolvido como grass fica "fora" (roof ativo).
  - Visao (visionRange): player sobre F/U/m resolvido como grass tem
    visao reduzida (outdoorRange = 160px).
  - Autotile: bordas, variacoes de textura e edge mask usam o tipo resolvido.
  - Tudo deve ser escalavel: adicionar novos tiles especiais no futuro deve
    ser trivial (apenas adicionar ao conjunto de tiles especiais).

3.2 — NOVO METODO: resolveBaseTile(x, y)

Adicionar como metodo da classe Game (apos loadMap ou antes de buildAutotileCache):

  resolveBaseTile(x, y) {
    const tile = this.tiles[y][x];
    // Apenas tiles F, U, m precisam de resolucao dinamica
    if (tile !== 'F' && tile !== 'U' && tile !== 'm') return tile;
    let floorCount = 0;
    let grassCount = 0;
    for (let dy = -1; dy <= 1; dy++) {
      for (let dx = -1; dx <= 1; dx++) {
        if (dx === 0 && dy === 0) continue;
        const nx = x + dx, ny = y + dy;
        if (nx < 0 || nx >= this.mapWidth || ny < 0 || ny >= this.mapHeight) continue;
        const neighborTile = this.tiles[ny][nx];
        if (neighborTile === 'C') floorCount++;
        else if (neighborTile === 'G') grassCount++;
        else if (neighborTile === 'd') floorCount++; // door = ambiente interno
        // Outros tiles (O, W, A, P, M, S, T, F, U, m) sao ignorados
      }
    }
    return floorCount >= grassCount ? 'C' : 'G';
  }

5. ESCALABILIDADE E MANUTENCAO
================================================================================

O sistema foi projetado para ser facilmente escalavel:

  Para ADICIONAR um novo tile especial no futuro (ex: 'X'):
    1. Adicionar 'X' ao if em resolveBaseTile():
         if (tile !== 'F' && tile !== 'U' && tile !== 'm' && tile !== 'X') return tile;
    2. Se 'X' precisar de resolucao baseada em vizinhanca, nada mais
       precisa ser modificado — o sistema ja consulta baseTileResolved.

  Para mudar a LOGICA de resolucao:
    Modificar apenas resolveBaseTile(). Tudo o resto consome o resultado.

  Para REMOVER a resolucao de um tile:
    Remover o tile do if em resolveBaseTile().

buildAutotileCache() atual (linha ~1536):
------------------------------------------------
  buildAutotileCache() {
    const h = this.mapHeight, w = this.mapWidth;
    this.tileVariation = new Array(h);
    this.tileEdgeMask = new Array(h);
    const isFloor = t => t === 'C' || t === 'U' || t === 'F' || t === 'P' || t === 'M' || t === 'S' || t === 'T' || t === 'm';
    for (let y = 0; y < h; y++) {
      this.tileVariation[y] = new Float32Array(w);
      this.tileEdgeMask[y] = new Int8Array(w);
      for (let x = 0; x < w; x++) {
        this.tileVariation[y][x] = Game.tileHash(x, y);
        const tile = this.tiles[y][x];
        if (tile !== 'G' && !isFloor(tile)) { this.tileEdgeMask[y][x] = 0; continue; }
        let mask = 0;
        const match = isFloor(tile) ? isFloor : t => t === 'G';
        if (y > 0 && !match(this.tiles[y - 1][x])) mask |= 1;
        if (y < h - 1 && !match(this.tiles[y + 1][x])) mask |= 2;
        if (x > 0 && !match(this.tiles[y][x - 1])) mask |= 4;
        if (x < w - 1 && !match(this.tiles[y][x + 1])) mask |= 8;
        this.tileEdgeMask[y][x] = mask;
      }
    }
  }

ALTERACAO 19 - SISTEMA DE BASE DINAMICA PARA TILES ESPECIAIS (F, U, m):

  PROBLEMA: Tiles F (Artifact Spawn), U (Waypoint) e m (Random Monster
  Spawn) eram sempre tratados como piso interno (C), independente de
  estarem em areas externas de grama. Isso causava inconsistencias
  visuais e de gameplay: o tile era renderizado com cor de chao interno,
  o roof desaparecia e a visao era total mesmo quando o tile estava em
  uma area externa.

  SOLUCAO: Implementado sistema de resolucao dinamica de base para tiles
  especiais. Um novo array baseTileResolved[][] e populado em loadMap()
  com o resultado da analise dos 8 vizinhos de cada tile F/U/m.
  O sistema e usado por 5 subsistemas: renderizacao, autotile, roof,
  visao e cache de bordas.

  MUDANCAS NO CODIGO:
    a) Game — NOVA PROPRIEDADE:
       baseTileResolved[mapHeight][mapWidth]: matriz de chars ('C' ou 'G'
       para tiles F/U/m, ou o proprio tile original para os demais)

    b) Game — NOVO METODO resolveBaseTile(x, y):
       Analisa 8 vizinhos de F/U/m. Conta tiles C (floor) e G (grass).
       Portas (d) contam como C. Outros tiles sao ignorados.
       Retorna 'C' se floorCount >= grassCount, senao 'G'.

    c) Game — NOVO METODO getEffectiveTile(x, y):
       Retorna baseTileResolved[y][x] se existir, senao tiles[y][x].
       Helper central usado por todos os subsistemas.

    d) Game.loadMap() — NOVA SECAO:
       Apos carregar tiles, antes de buildAutotileCache(), popula
       baseTileResolved[][] chamando resolveBaseTile() para cada tile.

    e) Game.buildAutotileCache() — MODIFICADO:
       isFloor() substituido por logica que usa getEffectiveTile().
       Edge mask calculada com base no tile resolvido, nao no bruto.

    f) Game.renderTiles() — MODIFICADO:
       Switch case: F, U, m usam cor baseada em baseTileResolved.
       Autotiling: F, U, m escolhem entre autotiling de floor ou grass
       baseado em baseTileResolved.

    g) Game.computeRoofAlpha() — MODIFICADO:
       Usa getEffectiveTile() para decidir se player esta dentro/fora.

    h) Game.updateVisionRanges() — MODIFICADO:
       Usa getEffectiveTile() para decidir indoor/outdoor range.

    i) Game.renderRoof() — MODIFICADO:
       Usa getEffectiveTile() para decidir se tile recebe roof overlay.
