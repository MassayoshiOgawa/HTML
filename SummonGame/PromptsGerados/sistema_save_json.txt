## CONTEXTO DO PROJETO

### O QUE É O SUMMON GAME
Summon Game é um jogo top-down 2D em tempo real renderizado em HTML5 Canvas, implementado em um ÚNICO arquivo HTML (`SummonGame.html`). Não há dependências externas. Arquitetura: Game Loop com objetos-entidade e sistemas centralizados em uma classe Game orquestradora.

### ESTRUTURA DO ARQUIVO
- `<style>`: Todo o CSS do jogo (HUD, painéis, botões, hotbar, etc.)
- `<body>`: Elementos DOM (canvas#game, #hud, #settings-btn, #settings-panel, #map-editor-panel, #message, #summon-desc, #class-select, #ability-hud, #hotbar-hud, #use-progress, #monster-selector)
- `<script>`: Todo o JavaScript (configurações, classes, game loop, renderização, input, UI handlers)

### SISTEMAS PRINCIPAIS (NÃO ALTERAR)
- **Player**: classe com atributos como playerIndex, name, playerClass, hp, px, py, tileX, tileY, speed, inventory[5], selectedSlot, keybinds, useTimer, abilityCooldown, abilityActive, abilityTimer, interacting, interactTarget, interactType, invisible, invulnTimer, commandYellMult, speedItemTimer, speedItemMult, timeTravelUsed, wiredGirlUsed, rerrolerUsed, helpfulpriestUsed, phasing, menuOpen, etc.
- **MonsterEntity**: classe com atributos como type, px, py, tileX, tileY, speed, alive, state, stunTimer, tauntTimer, etc.
- **DoorEntity**: classe com atributos open, animating, animProgress, groupMembers
- **ArtifactEntity**: classe com atributos collected, isFake
- **Game**: classe orquestradora com todos os sistemas (players[], activeMonsters[], doorEntities[], artifactEntities[], traps[], shopItems[], visibilityPolygons[], currency, roundNumber, summonCount, difficulty, isNight, nightTransition, roofAlpha, hotbarSize, hotbarLayout, hotbarGap, activeClones[], activeWalls[], activeZones[], lockedDoor, ratEntities[], pendingMonsterType, selectedMonsterType, debugSelectedMonster, etc.)
- **Tela inicial** (`#class-select`): contém título "Summon Game", seletor de dificuldade, seletor de quantidade de jogadores, painéis de setup por jogador (nome, classe, hotkeys), e botão "Start Game".

### LOCALIZAÇÃO DOS ELEMENTOS NA TELA INICIAL
A tela inicial (`#class-select`) tem esta estrutura vertical:
1. `<h2>Summon Game</h2>` (título)
2. `#difficulty-selector` (botões Easy/Medium/Hard)
3. `#player-count-selector` (botões -/+, label de contagem)
4. `#player-setup-container` (painéis de setup por jogador)
5. `#player-setup-desc` (descrição da classe)
6. `#btn-start-game` (botão Start Game)

#### 2.5 - COMPORTAMENTO AO CARREGAR SAVE IN-GAME
Ao carregar um save in-game:
1. Restaure `game.paused = true` durante o processo

3. Recrie os arrays de entidades (players, monsters, doors, artifacts, traps, shops, clones, walls, zones, rats) com os dados salvos
4. Restaure as referências cruzadas (índices -> objetos reais)
5. Reconstrua `visibilityPolygons[]` chamando `buildLightmap()` e `updateVisibility()`
6. Aplique as configurações (dificuldade, nomes, classes, keybinds)
7. Reconstrua a UI (HUD, hotbar, ability HUD)
8. Defina `game.paused = false`
9. O jogo continua exatamente de onde parou

## VALIDAÇÕES E SEGURANÇA

### AO SALVAR
- Verifique se `game` e seus arrays existem antes de tentar serializar
- Use `try/catch` ao chamar `JSON.stringify` para evitar crash se algum dado for circular
- Use `JSON.stringify` com um replacer que remove referências circulares e funções

### AO CARREGAR
- Valide que o JSON tem o campo `version` e `type`
- Se `type === "config"`, só carregue configurações (não afeta o jogo em andamento)
- Se `type === "save"`, carregue o jogo completo
- Use `try/catch` ao fazer `JSON.parse`
- Se o JSON for inválido, mostre mensagem de erro "Invalid save file" e NÃO crash o jogo
- Verifique se os índices de referência cruzada são válidos antes de usá-los

### COMPATIBILIDADE FUTURA
- O campo `version` permite detectar saves de versões antigas
- Se `version` for maior que a versão atual do jogo, avise "This save was created in a newer version"
- Se `version` for menor, tente carregar mesmo assim (forward compatibility básica)
