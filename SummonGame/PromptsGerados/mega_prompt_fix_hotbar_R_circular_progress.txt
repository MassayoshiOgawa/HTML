4. TAREFA 1 - CORRIGIR HOTBAR (BUG DA TECLA R)
================================================================================

4.1 - DESCRICAO DO PROBLEMA:
      Atualmente, no metodo Player.update(), o codigo usa keysJustPressed[kb.use]
      para ciclar o slot da hotbar IMEDIATAMENTE ao pressionar R. Como a tecla
      continua pressionada (hold), keys[kb.use] fica true e o timer de uso comeca
      no slot que ACABOU DE SER CICLADO (slot errado).

      COMPORTAMENTO ATUAL (ERRADO):
        Keydown R -> keysJustPressed -> cicla slot -> hold comeca no slot ciclado
        Resultado: em vez de usar o item equipado, cicla pro proximo e usa esse

      COMPORTAMENTO DESEJADO:
        Tap R (pressionar e soltar rapido): cicla para o proximo slot nao vazio
        Hold R (segurar por >= 1 segundo): usa o item ATUALMENTE equipado SEM ciclar

4.2 - IMPLEMENTACAO DA SOLUCAO:

      a) ADICIONAR NOVO ATRIBUTO no construtor do Player (apos this.using = false):
           this.useTapPending = false;
         Mantenha this.useTimer e this.using existentes.

      b) SUBSTITUIR O BLOCO DE CODIGO EM Player.update() (linhas ~749-770):
         BLOCO ANTIGO (a remover):
           // Hotbar: cycle slot on tap, hold to use
           if (keysJustPressed[kb.use]) {
             keysJustPressed[kb.use] = false;
             let next = this.selectedSlot;
             let tries = 0;
             do { next = (next + 1) % 5; tries++; }
             while (tries < 5 && !this.inventory[next]);
             this.selectedSlot = next;
             this.useTimer = 0;
             this.using = false;
           }
           if (keys[kb.use] && this.inventory[this.selectedSlot] && !this.using) {
             this.useTimer += dt;
             if (this.useTimer >= 1) {
               game.useItem(this);
               this.useTimer = 0;
             }
           }
           if (!keys[kb.use]) { this.useTimer = 0; this.using = false; }

         BLOCO NOVO:
           // Hotbar: tap to cycle, hold to use
           if (keysJustPressed[kb.use]) {
             keysJustPressed[kb.use] = false;
             this.useTapPending = true;
             this.useTimer = 0;
           }

           if (keys[kb.use]) {
             if (this.useTapPending) {
               // Ainda em fase de deteccao tap vs hold
               this.useTimer += dt;
               if (this.useTimer >= 0.3) {
                 this.useTapPending = false; // Confirmado: hold
                 this.useTimer = 0; // Reset para usar o timer de item
               }
             } else if (this.inventory[this.selectedSlot]) {
               // Hold confirmado: usar item equipado
               this.useTimer += dt;
               if (this.useTimer >= 1) {
                 game.useItem(this);
                 this.useTimer = 0;
               }
             }
           }

           if (!keys[kb.use]) {
             if (this.useTapPending) {
               // Tap detectado (solteu antes de 0.3s): ciclar slot
               let next = this.selectedSlot;
               let tries = 0;
               do {
                 next = (next + 1) % 5;
                 tries++;
               } while (tries < 5 && !this.inventory[next]);
               this.selectedSlot = next;
             }
             this.useTapPending = false;
             this.useTimer = 0;
             this.using = false;
           }

      c) EXPLICACAO DO FUNCIONAMENTO:
         - Ao pressionar R: marca useTapPending = true, nao cicla ainda
         - Enquanto segura R:
           * Se ainda esta em fase de deteccao (< 0.3s): incrementa useTimer
           * Se passar de 0.3s: confirma hold (useTapPending = false),
             reseta useTimer, comeca a contar para usar o item (1s)
           * Nota: usa VARIAVEL UNICA this.useTimer para ambos os propositos
             (deteccao e uso), pois sao mutuamente exclusivos no tempo
         - Ao soltar R:
           * Se ainda esta pendente (useTapPending true): foi um TAP, cicla slot
           * Senao: foi um HOLD, item ja foi usado (ou nao), nao cicla
         - Vantagem: o slot NUNCA e ciclado durante hold, resolvendo o bug

5.2 - ADICIONAR NOVO METODO renderUseProgressCircle(ctx) NA CLASSE Game:

      ADICIONAR o novo metodo na classe Game, de preferencia logo APOS o metodo
      renderInteractionCircle(ctx) existente (antes do fechamento da classe Game).

      ESPECIFICACOES DO METODO:

      a) ASSINATURA:
           renderUseProgressCircle(ctx)
         NOTA: nao recebe parametros adicionais, usa this.players e this.camX/Y.

      b) LOGICA:
         - Itera sobre todos os jogadores vivos (this.players)
         - Para cada jogador p:
           * Se p.useTimer <= 0: pula (nao esta segurando R)
           * Se p.useTimer > 0: desenha circulo de progresso

      c) POSICAO:
         - 1 tile (TILE_SIZE = 32px) a DIREITA do centro do jogador
         - worldX = p.px + TILE_SIZE (direita)
         - worldY = p.py (mesma altura)
         - screenX = worldX - this.camX
         - screenY = worldY - this.camY
         - Se screenX/screenY estiver fora do canvas (margem 50px), pular

      d) DESENHO DO CIRCULO (MESMO ESTILO DO renderInteractionCircle, MAS BRANCO):
         const circleRadius = TILE_SIZE * 0.4;
         const lineWidth = circleRadius * 2 * 0.15;
         const progress = Math.min(1, Math.max(0, p.useTimer / 1));
         const startAngle = -Math.PI / 2;
         const endAngle = startAngle + Math.PI * 2 * progress;

         // Circulo de fundo (escuro semi-transparente)
         ctx.beginPath();
         ctx.arc(screenX, screenY, circleRadius, 0, Math.PI * 2);
         ctx.strokeStyle = 'rgba(255,255,255,0.2)';
         ctx.lineWidth = lineWidth + 2;
         ctx.stroke();

         // Circulo interno de fundo
         ctx.beginPath();
         ctx.arc(screenX, screenY, circleRadius, 0, Math.PI * 2);
         ctx.strokeStyle = 'rgba(255,255,255,0.3)';
         ctx.lineWidth = lineWidth;
         ctx.stroke();

         // Arco de progresso (BRANCO PURO, sem gradiente)
         if (progress > 0) {
           ctx.beginPath();
           ctx.arc(screenX, screenY, circleRadius, startAngle, endAngle);
           ctx.strokeStyle = '#ffffff';
           ctx.lineWidth = lineWidth;
           ctx.lineCap = 'round';
           ctx.stroke();
           ctx.lineCap = 'butt';
         }

      e) CHAMADA NO RENDER:
         No metodo Game.render(), ADICIONAR a chamada:
           this.renderUseProgressCircle(ctx);
         IMEDIATAMENTE APOS a chamada de:
           this.renderInteractionCircle(ctx);

      f) NOTA IMPORTANTE:
         - NAO reutilizar o metodo renderInteractionCircle para este proposito

           separacao de responsabilidades
         - NAO usar gradiente de cores (Game.progressColor) - usar BRANCO #ffffff
         - Sempre verificar frustum culling (se esta visivel na tela)

         SOLUCAO: Implementado sistema de deteccao tap vs hold.
         - Tap (pressionar e soltar em < 0.3s): cicla para o proximo slot nao vazio
         - Hold (segurar por >= 1s): usa o item atualmente equipado SEM ciclar
         - A deteccao usa uma propriedade useTapPending no Player
         - O ciclo so ocorre no keyup (ao soltar a tecla), nunca no keydown

         MUDANCAS NO CODIGO:
           a) Player — NOVO ATRIBUTO:
              useTapPending (boolean): true enquanto aguarda confirmacao tap/hold
              Inicializado como false no construtor.

              - keysJustPressed[kb.use]: define useTapPending=true, nao cicla
              - keys[kb.use] com useTapPending: incrementa useTimer ate 0.3s
              - Se useTimer >= 0.3: confirma hold (useTapPending=false, useTimer=0)
              - keys[kb.use] SEM useTapPending: useTimer conta ate 1s para usar item
              - !keys[kb.use] com useTapPending: TAP confirmado, cicla slot
              - !keys[kb.use] sem useTapPending: HOLD, apenas reseta timers
