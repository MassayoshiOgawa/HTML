1. VISAO GERAL DO PROJETO
================================================================================

Genero: RPG de texto (roguelike) em console, com exploracao em grid 2D ASCII,
combate por turnos, gerenciamento de recursos e progressao de personagem.

Proposta: "Sombras de Valdoria" e um RPG de fantasia medieval onde o jogador
controla um heroi que explora masmorras/florestas geradas proceduralmente,
enfrenta inimigos, completa missoes, gerencia recursos (fome, stamina, peso),
evolui de nivel, melhora equipamentos e interage com uma loja com economia
dinamica (inflacao noturna, sistema de reputacao/desconto).

Objetivos do Jogo:
- Sobreviver explorando mapas aleatorios cheios de perigos
- Evoluir do nivel 1 ao 50 enfrentando inimigos cada vez mais dificeis
- Gerenciar recursos: HP, Mana, Fome, Stamina, Peso do inventario, Ouro
- Completar quests para ganhar XP e ouro extras
- Refinar arma ate +5 para maximizar dano
- Derrotar bosses para progredir
- Acumular riqueza e reputacao na loja

Fluxo Principal de Gameplay:
1. Jogador inicia digitando nome e selecionando uma das 8 classes
2. Recebe itens iniciais (3 pocoes de vida, 2 de mana, 5 paes)
3. Passa por um combate tutorial (nivel 1)
4. Entra no loop principal: explora mapa -> encontra inimigos/eventos/lojas/saida
5. Em cada passo no mapa, pode consumir fome, mudar o ciclo dia/noite, ativar eventos
6. Ao encontrar saida, novo mapa e gerado
7. Morrer faz perder 20% do ouro e voltar com 50% HP/Mana
8. Jogo continua ate o jogador desistir (nao ha "final" implementado)

Experiencia Esperada: Jogador deve sentir que esta em uma jornada de
sobrevivencia onde cada decisao importa - gastar ouro com comida vs equipamento,
arriscar explorar mais ou voltar, usar habilidades no momento certo, gerenciar
cooldowns e recursos em combates prolongados.

================================================================================
2. RESUMO EXECUTIVO DO FUNCIONAMENTO
================================================================================

O jogador inicia no menu principal onde pode comecar um novo jogo ou carregar
um save. Ao criar personagem, digita seu nome e escolhe entre 8 classes, cada
uma com atributos iniciais diferentes e 5 habilidades unicas desbloqueadas
progressivamente do nivel 1 ao 5.

Apos a selecao, o jogo gera o primeiro mapa procedural (grid 15x30) usando um
algoritmo de caminhada aleatoria que cria corredores. O jogador comeca na
coluna 0, linha aleatoria. O mapa contem: espacos vazios (caminho), areas
intransponiveis (Nada/paredes), inimigos (E), baus (B), lojas (L), arvores (T),
e uma saida (S) no extremo oposto.

O combate e por turnos com as opcoes: Atacar (auto), Habilidades, Itens, Fugir.
Cada classe tem 5 habilidades com cooldowns e custo de mana. O sistema
elemental (Fogo > Gelo > Terra > Fogo, Luz <> Trevas) dobra dano em fraquezas.
Ha stagger (barra de atordoamento) que ao zerar faz o inimigo perder o turno.

A economia funciona com ouro obtido de inimigos e baus. A loja vende
consumiveis (pocoes, comida) e itens especiais. O ferreiro repara e refina
armas (+1 a +5). Ha inflacao noturna (+25% precos de consumo) e desconto por
reputacao (a cada 500g gastos, +5% desconto, max 20%).

O jogador gerencia fome (0-100) que diminui com acoes. Se chegar a 0, fica
exausto (-50% atributos). O ciclo dia/noite alterna a cada 5 acoes. A noite,
inimigos sao +30% fortes mas dao +50% XP e ouro.

Ao derrotar inimigos, ganha XP e ouro, possivelmente loot (armas, armaduras,
acessorios) com raridade determinada por rolagem. Ao acumular XP suficiente,
sobe de nivel (max 50), ganhando +2 em todos atributos base e recuperando HP/Mana.

O save e feito via codigo textual que o jogador anota e pode digitar ao iniciar
o jogo para restaurar progresso (implementacao basica - o parser nao e completo).

----------------------------------------------------------------------
FUNCAO: inicializar_jogo()
----------------------------------------------------------------------
FINALIDADE: Inicializa todos os sistemas antes do jogo comecar
PARAMETROS: Nenhum
VALORES RETORNADOS: Nenhum (procedimento)
VARIÁVEIS UTILIZADAS: Nenhuma (apenas chama outras funcoes)
PASSO A PASSO:
  1. Limpa a tela
  2. Exibe nome do jogo e versao
  3. Aguarda 1 segundo
  4. Chama inicializar_habilidades() para popular o vetor de skills
  5. Chama inicializar_loja() para popular o vetor da loja
  6. Chama inicializar_eventos() para popular os eventos
  7. Chama inicializar_quests() para popular as missoes
INTERACOES: Depende de todas as funcoes de inicializacao chamadas
IMPORTANCIA: Funcao de setup essencial, sem ela nenhum sistema funciona
RISCOS: Se falhar, nenhum sistema tera dados para operar

----------------------------------------------------------------------
FUNCAO: inicializar_habilidades()
----------------------------------------------------------------------
FINALIDADE: Preenche o vetor global de habilidades com 40 skills (8 classes x 5)
PARAMETROS: Nenhum
VALORES RETORNADOS: Nenhum
VARIÁVEIS UTILIZADAS: g_skill_* (todos os vetores), g_skill_count
PASSO A PASSO:
  Define indices 0-4 para Guerreiro, 5-9 para Mago, 10-14 para Ladino,
  15-19 para Paladino, 20-24 para Arqueiro, 25-29 para Druida,
  30-34 para Necromante, 35-39 para Monge.
  Para cada skill define: nome, custo (MP), cooldown (turnos),
  cooldown_atual (0), dano_mult (percentual), tipo (categoria de efeito),
  duracao (turnos de efeito), elemento, disponivel (verdadeiro)
  Finaliza setando g_skill_count = 40
INTERACOES: Usada por menu_habilidades(), usar_habilidade()
IMPORTANCIA: Nuclear - define todas as capacidades das classes
RISCOS: Alterar indices quebra o mapeamento classe -> skills

INTERACOES: Usada por loja_consumiveis()

----------------------------------------------------------------------
FUNCAO: inteiro calcular_hp_max()
----------------------------------------------------------------------
FINALIDADE: Calcula o HP maximo do jogador
PARAMETROS: Nenhum
VALORES RETORNADOS: inteiro - HP maximo calculado
VARIÁVEIS UTILIZADAS: g_vitalidade, g_equip_vitalidade, g_nivel
FORMULA: base = 100 + (vitalidade * 15) + (equip_vitalidade * 15)
         bonus_nivel = nivel * 12
         retorna base + bonus_nivel
EXEMPLO: Nivel 1, Vitalidade 5, equip 0: 100 + 75 + 12 = 187 (mas inicia como 175)
IMPORTANCIA: Usada sempre que HP precisa ser recalculado (level up, equipamento)
RISCOS: Nenhum

----------------------------------------------------------------------
FUNCAO: inteiro calcular_mana_max()
----------------------------------------------------------------------
FINALIDADE: Calcula a mana maxima do jogador
PARAMETROS: Nenhum
VALORES RETORNADOS: inteiro - mana maxima
FORMULA: base = 50 + (inteligencia * 8) + (equip_inteligencia * 8)
         bonus_nivel = nivel * 10
EXEMPLO: Nivel 1, Inteligencia 5, equip 0: 50 + 40 + 10 = 100 (mas inicia como 90)

----------------------------------------------------------------------
FUNCAO: inteiro calcular_ataque_total()
----------------------------------------------------------------------
FINALIDADE: Calcula o ataque total do jogador para uso em combate
PARAMETROS: Nenhum
VALORES RETORNADOS: inteiro - dano de ataque total
FORMULA: base = g_arma_dano + (g_forca * 1.8) + (g_equip_forca * 1.8)
         bonus_nivel = g_nivel * 8
         refino_bonus: +1=10%, +2=25%, +3=40%, +4=60%, +5=100%
         total = base + bonus_nivel + (base * refino_bonus / 100)
IMPORTANCIA: Usada em todo ataque fisico basico e habilidades fisicas
RISCOS: Nenhum

----------------------------------------------------------------------
FUNCAO: inteiro calcular_defesa_total()
----------------------------------------------------------------------
FINALIDADE: Calcula a defesa total do jogador
PARAMETROS: Nenhum
FORMULA: base = g_defesa + g_armadura_defesa + g_equip_defesa
         bonus_nivel = g_nivel * 7
         retorna base + bonus_nivel

----------------------------------------------------------------------
FUNCAO: inteiro calcular_reducao_dano(inteiro defesa)
----------------------------------------------------------------------
FINALIDADE: Converte defesa em % de reducao de dano
PARAMETROS: defesa - valor de defesa
FORMULA: reducao = defesa * 0.35
         se reducao > LIMITE_REDUCAO_DANO (80), cap em 80
         retorna Matematica.arredondar(reducao, 0)
IMPORTANCIA: Toda defesa passa por esta funcao
NOTA: O limite de 80% significa que mesmo com defesa infinita, sempre
leva pelo menos 20% do dano

----------------------------------------------------------------------
FUNCAO: inteiro calcular_critico_total()
----------------------------------------------------------------------
FINALIDADE: Chance critica total do jogador
FORMULA: total = g_critico + g_equip_critico
         se total > LIMITE_CRITICO (80), cap em 80

----------------------------------------------------------------------
FUNCAO: inteiro calcular_esquiva_total()
----------------------------------------------------------------------
FINALIDADE: Chance de esquiva total do jogador
FORMULA: total = g_esquiva + g_equip_esquiva
         se total > LIMITE_ESQUIVA (75), cap em 75

----------------------------------------------------------------------
FUNCAO: real calcular_peso_max()
----------------------------------------------------------------------
FINALIDADE: Peso maximo que o inventario pode carregar
FORMULA: retorna PESO_BASE (30) + (g_forca * 1.5)
EXEMPLO: Forca 8: 30 + 12 = 42

----------------------------------------------------------------------
FUNCAO: inteiro calcular_xp_proximo()
----------------------------------------------------------------------
FINALIDADE: Calcula XP necessario para o proximo nivel
FORMULA: xp = 100.0
         loop i = 0 ate nivel: xp = xp * 1.45
         retorna Matematica.arredondar(xp, 0)
EXEMPLO: Nivel 1: 100 * 1.45 = 145
         Nivel 2: 145 * 1.45 = 210
         Nivel 3: 210 * 1.45 = 304
         Nivel 10: ~2870
         Nivel 50: ~8.5 bilhoes (crescimento exponencial extremo)
NOTA: O loop vai de 0 ate g_nivel, entao quando g_nivel=1, multiplica 1 vez
      Isso significa que g_xp_proximo ja e o valor para o proximo nivel

----------------------------------------------------------------------
FUNCAO: real verificar_fracao_elemental(inteiro atacante_elem, inteiro defensor_elem)
----------------------------------------------------------------------
FINALIDADE: Retorna multiplicador elemental entre atacante e defensor
PARAMETROS: atacante_elem, defensor_elem (inteiros 0-6)
VALORES RETORNADOS: real (0.5, 1.0, ou 2.0)
TABELA DE FRAQUEZAS:
  Fogo (1) -> Gelo (2): 2.0
  Gelo (2) -> Terra (3): 2.0
  Terra (3) -> Fogo (1): 2.0
  Luz (4) -> Trevas (5): 2.0
  Trevas (5) -> Luz (4): 2.0

TABELA DE RESISTENCIAS (inverso):
  Gelo (2) atacando Fogo (1): 0.5
  Terra (3) atacando Gelo (2): 0.5
  Fogo (1) atacando Terra (3): 0.5
  Trevas (5) atacando Luz (4): 0.5
  Luz (4) atacando Trevas (5): 0.5

Raio (6) e Neutro (0): Sempre 1.0 com todos

FUNCAO: inteiro gerar_inimigo(inteiro nivel, logico elite, logico boss)
----------------------------------------------------------------------
FINALIDADE: Gera um inimigo com stats calculados pelo nivel
PARAMETROS: nivel (1-50), elite (boolean), boss (boolean)
RETORNA: indice do inimigo no vetor, ou -1 se cheio
PASSO A PASSO:
  1. Calcula hp_base = 50 + (nivel * 22) + (nivel * nivel * 2)
     atk_base = 8 + (nivel * 3.5)
     def_base = 5 + (nivel * 2.2)
  2. Se boss: hp*=5, atk*=2.2, def*=1.8
     Se elite: hp*=2.2, atk*=1.5, def*=1.4
  3. Gera nome combinando prefixo + tipo
     Prefixos: 8 opcoes (Selvagem, Sombrio, Antigo, Corrompido, etc)
     Tipos: 10 opcoes (Goblin, Orc, Esqueleto, Lobo, Aranha, etc)
  4. Atribui stats: inteligencia=nivel*3, agilidade=nivel*2,
     vitalidade=nivel*4, critico=5+nivel, esquiva=3+nivel
     resistencia=nivel*2, elemento=aleatorio 1-6
  5. xp = nivel * 15 (elite*2.5, boss*5)
     ouro = (nivel*4) + aleatorio(0, nivel*3) (elite*2, boss*5)
  6. stagger_max = hp_base / 4
  7. stagger_atual = stagger_max
  8. stunned = falso

IMPORTANCIA: Toda criacao de inimigo passa por aqui
DETALHE IMPORTANTE: O inimigo e adicionado ao vetor global, nao e temporario.
Isso significa que inimigos derrotados acumulam no vetor (g_inim_count nunca
diminui). Eventualmente MAX_INIMIGOS=30 sera atingido e novos inimigos nao
poderao ser gerados.

----------------------------------------------------------------------
FUNCAO: inteiro aplicar_dano(inteiro atacante_forca, inteiro atacante_precisao,
        inteiro atacante_critico, inteiro atacante_elemento,
        inteiro defensor_defesa, inteiro defensor_resistencia,
        inteiro defensor_elemento, inteiro skill_mult,
        logico forcar_critico)
----------------------------------------------------------------------
FINALIDADE: Funcao universal de calculo de dano
PARAMETROS: 9 parametros cobrindo atacante e defensor
RETORNA: inteiro - dano final causado (0 se errou)
PASSO A PASSO:
  1. Roll de precisao: se aleatorio(1,100) > atacante_precisao, retorna 0 (erro)
  2. dano_base = atacante_forca * (skill_mult / 100.0)
  3. Roll de critico: se forcar_critico OU aleatorio <= atacante_critico:
     dano *= 2.0
  4. Multiplicador elemental: chama verificar_fracao_elemental()
     dano *= elem_mult (0.5, 1.0, ou 2.0)
  5. Aplicar defesa: reducao = calcular_reducao_dano(defensor_defesa)
     dano -= dano * (reducao / 100.0)
  6. Se skill_mult > 150 (habilidade forte): resistencia aplica 25%
     dano -= dano * (defensor_resistencia * 0.25 / 100.0)
  7. Dano minimo = 1
  8. Retorna dano_final arredondado
IMPORTANCIA: Funcao mais critica do combate - todo dano passa por aqui

  3. Exibe tela de inicio de combate
  4. Loop enquanto g_em_combate:
     a. Incrementa turno
     b. Chama turno_jogador()
     c. Verifica se inimigo morreu -> combate_vitoria()
     d. Verifica se jogador morreu -> combate_derrota()
     e. Chama turno_inimigo()
     f. Verifica se jogador morreu -> combate_derrota()
     g. Chama atualizar_efeitos_jogador()
     h. Chama processar_efeitos_turno_jogador()
     i. Chama reduzir_cooldowns()
     j. Reseta g_turno_extra_rodada = falso
     k. Exibe HUD de combate

5. SISTEMA DE GERACAO DE MAPA ALEATORIO
================================================================================

5.1 ESTRUTURA DE ARMAZENAMENTO
O mapa e armazenado em uma matriz bidimensional de strings:
  g_mapa_matriz[25][50] (cadeia)
  Dimensoes efetivamente usadas: g_mapa_tamanho_x = 15, g_mapa_tamanho_y = 30

Cada celula contem uma string representando seu conteudo:
  "Nada" - area intransponivel (parede/fora do caminho)
  "Caminho" - area transitavel vazia
  "O" - marcador temporario de posicao durante geracao
  "E" - inimigo
  "B" - bau
  "L" - loja
  "S" - saida
  "T" - arvore
  "@" - jogador (nao armazenado, renderizado dinamicamente)

5.2 ALGORITMO DE GERACAO (CALCULAR_MAPA)
O algoritmo e um gerador de labirinto por caminhada aleatoria (random walk):

PSEUDOCODIGO:
  Funcao gerar_mapa():
    1. Preencher toda matriz com "Nada"
    2. Escolher startX aleatorio entre 1 e tamanho_x-2
    3. Posicionar jogador em (startX, 0)
    4. Marcar (startX, 0) como "O"
    5. Enquanto nao parar:
         chamar calcular_mapa()
    6. Chamar colocar_elementos_mapa()

  Funcao calcular_mapa():
    1. Encontrar celula com "O" na matriz (busca completa!)
    2. Verificar vizinhos (cima, baixo, esquerda, direita) que sao "Nada"
       e estao dentro dos limites
    3. Se nenhum vizinho disponivel: g_mapa_parar_geracao = true, retorna
    4. Escolher direcao aleatoria entre as disponiveis
    5. Marcar celula atual como "Caminho"
    6. Marcar celula vizinha escolhida como "O"
    7. Retorna (continua loop em gerar_mapa)

5.3 ALOCACAO DE ELEMENTOS (COLOCAR_ELEMENTOS_MAPA)
Apos gerar caminhos, percorre toda matriz:
  Para cada celula "Caminho":
    15% chance -> inimigo "E"
    5% chance -> bau "B"
    3% chance -> loja "L"
    10% chance -> arvore "T"

  Apos percorrer, coloca saida "S" na ultima celula "Caminho"
  encontrada (percorrendo de tras para frente).

5.4 LIMITACOES E BUGS CONHECIDOS
- O algoritmo de busca do "O" e ineficiente: percorre a matriz INTEIRA
  a cada passo para encontrar a posicao atual
- Nao ha garantia de que todos os caminhos sejam conectados
- Nao ha garantia de que a saida seja alcancavel
- MAX_INIMIGOS=30 pode encher, impedindo geracao de novos inimigos no mapa
  (mas o mapa apenas referencia chars, nao indices de inimigos)
- O mapa nao regenera elementos ao visitar - uma vez que o jogador passa
  por uma celula, ela vira "Caminho" permanentemente
- Nao ha variedade de biomas/regioes - tudo e "Floresta Sombria"

5.5 SIMBOLOGIA DO MAPA
  "@" = jogador
  " " = caminho livre
  "." = area inacessivel (Nada)
  "E" = inimigo
  "B" = bau
  "L" = loja
  "S" = saida
  "T" = arvore
  "=" = borda horizontal
  "|" = borda vertical

5.6 RECRIACAO EM JS
Para recriar em JavaScript, usar uma matriz 2D (array de arrays). O algoritmo
de random walk pode ser implementado com loop while e Math.random(). Para
melhorar a qualidade, considerar geracao de cavernas (cellular automata) ou
BSP (Binary Space Partition) para salas conectadas por corredores.

================================================================================
6. SISTEMA DE MOVIMENTACAO
================================================================================

6.1 COMANDOS
  W - mover para cima (x-1, y)
  S - mover para baixo (x+1, y)
  A - mover para esquerda (x, y-1)
  D - mover para direita (x, y+1)

6.2 LOGICA DE MOVIMENTO (mover_jogador)
  1. Calcula nova posicao baseada na direcao
  2. Verifica limites (0 <= x < tamanho_x, 0 <= y < tamanho_y)
  3. Le o conteudo da celula destino
  4. Se for "Nada": movimento negado (retorna)
  5. Se for "E": inicia combate, inimigo nivel entre nivel-1 e nivel+2,
     20% chance de elite. Apos combate (vitoria ou fuga), celula vira "Caminho"
  6. Se for "B": abre bau, celula vira "Caminho"
  7. Se for "L": entra na loja, celula vira "Caminho"
  8. Se for "S": saida! Gera novo mapa, posiciona jogador no inicio
  9. Se for "T": 30% chance de encontrar ouro (5-15g), celula vira "Caminho"
  10. Se for "Caminho": 25% chance de evento aleatorio
  11. Atualiza posicao do jogador
  12. Incrementa acoes_totais, verifica ciclo tempo, atualiza fome

6.3 EVENTOS DISPARADOS PELO MOVIMENTO
- Encontro com inimigo -> combate
- Bau -> loot
- Loja -> compra/venda
- Saida -> novo mapa
- Arvore -> chance de ouro
- Caminho vazio -> chance de evento aleatorio

================================================================================
7. SISTEMA DE COMBATE
================================================================================

7.1 INICIO
Chamado por gerar_combate(nivel_inimigo, elite, boss)
- Gera inimigo via gerar_inimigo()
- Inicia loop enquanto g_em_combate

7.2 TURNO DO JOGADOR
Opcoes:
  [1] Atacar: ataque_basico() - calcula dano, reduz durabilidade, aplica stagger
  [2] Habilidades: menu_habilidades() - lista skills da classe, verifica CD/mana
  [3] Itens: menu_itens_combate() - usa itens do inventario
  [4] Fugir: tentar_fugir() - chance = 50 + agilidade (20 vs boss)

7.3 TURNO DO INIMIGO
  - Se atordoado (stunned): perde turno
  - Se stagger <= 0: perde turno, recupera 50% stagger
  - IA: cura se HP<30% (30% chance), buff se turno>5 (20% chance), ou ataque

7.4 CALCULO DE DANO (aplicar_dano)
  dano_base = forca_atacante * (skill_mult / 100)
  critico: se rolagem <= critico_atacante, dano *= 2
  elemental: multiplicador 0.5, 1.0, ou 2.0
  defesa: reducao = defesa * 0.35 (cap 80%)
  resistencia: se skill_mult > 150, reduz adicionalmente
  dano_minimo = 1

7.5 DEFESA DO JOGADOR (ia_inimigo)
  ataque_inimigo - reducao(defesa_jogador) = dano
  Noite: dano *= 1.3
  Postura Defensiva (buff tipo 3): dano *= 0.6
  Esquiva: chance de evitar ataque completamente
  Desviar Projeteis (buff tipo 13): bloqueio total
  Pele de Arvore (buff tipo 10): reflete 20% dano

7.6 SISTEMA DE STAGGER
  A cada ataque, reduz stagger (15 para ataque basico, variaveis para skills)
  Bosses sofrem apenas 25% do stagger (valor/4)
  Quando stagger = 0: inimigo perde 1 turno, recupera 50% stagger
  Exibido na HUD como % da barra

7.7 SISTEMA DE STUN
  Habilidades como Bomba de Luz, Armadilha podem atordoar
  Bosses tem 50% de resistencia a stun (Armadilha)

7.8 CONDICOES DE VITORIA
  Inimigo HP <= 0: chama combate_vitoria()
  Recompensas: XP + Ouro + Loot + Progresso Quest

7.9 CONDICOES DE DERROTA
  Jogador HP <= 0: chama combate_derrota()
  Consequencias:
    - Se tiver Coracao de Fenix: revive com 20% HP, consome item
    - Se for Paladino com Ressurreicao: revive com 100% HP, CD = 999
    - Senao: perde 20% ouro, recupera 50% HP/Mana

7.10 DURABILIDADE
  Ataque basico: -1 durabilidade
  Habilidade fisica: -2 durabilidade
  Se durabilidade = 0: dano reduzido a 10% (mult = 10)
  Reparo no Ferreiro: custa durabilidade_perdida / 2

================================================================================
9. SISTEMA DE BALANCEAMENTO
================================================================================

9.1 CURVA DE DIFICULDADE
  Inimigos: HP cresce quadraticamente (nivel^2 * 2), ataque e defesa linearmente
  Jogador: atributos crescem +2 por nivel, linearmente
  XP necessario: cresce exponencialmente (1.45^nivel)

  Isso significa que nos niveis altos, o XP necessario cresce muito mais
  rapido que o XP obtido (nivel*15), criando uma "parede" de progressao.

9.2 FORMULAS COMPLETAS DE CRESCIMENTO

Jogador (por level up):
  HP_max = 100 + vitalidade*15 + nivel*12
  Mana_max = 50 + inteligencia*8 + nivel*10
  Ataque_total = arma_dano + forca*1.8 + equip_forca*1.8 + nivel*8 + refino%
  Defesa_total = defesa + armadura_defesa + equip_defesa + nivel*7

Inimigo (por nivel):
  HP = 50 + nivel*22 + nivel^2 * 2
  ATK = 8 + nivel*3.5
  DEF = 5 + nivel*2.2

  Elite: HP*2.2, ATK*1.5, DEF*1.4, XP*2.5, Ouro*2
  Boss: HP*5, ATK*2.2, DEF*1.8, XP*5, Ouro*5

9.3 DISTRIBUICAO DE RECOMPENSAS
  XP inimigo = nivel * 15 (elite * 2.5, boss * 5)
  Ouro inimigo = nivel*4 + aleatorio(0, nivel*3)

9.4 PONTOS DE ATENCAO
  - O multiplicador de XP exponencial faz com que nivel 50 exija
    aproximadamente 8.5 bilhoes de XP, praticamente inalcancavel
  - Jogador ganha +2 em TODOS atributos por nivel, sem escolha do jogador
  - Level cap de 50 com atributos iniciais ~8 significa nivel 50 tera ~106 em cada stat
  - Stagger de boss e reduzido a 25%, mas stun (Armadilha) tem 50% chance
  - O sistema de equipamento (equipar_item) ACUMULA bonus em vez de substituir

14. FLUXO COMPLETO DO JOGO

1. INICIO
   a. Inicializacao dos sistemas (habilidades, loja, eventos, quests)
   b. Tela de titulo
   c. Opcao: Novo Jogo ou Carregar
   d. Entrada do nome do jogador
   e. Selecao de classe (1-8)
   f. Atribuicao de atributos iniciais conforme classe
   g. Calculo de HP/Mana maximo
   h. Itens iniciais no inventario
   i. Geracao do primeiro mapa
   j. Tutorial e combate tutorial (inimigo nivel 1)
   k. Entrada no menu principal

2. LOOP PRINCIPAL (menu_principal)
   Enquanto jogando:
     a. Exibe HUD de exploracao (stats resumidas)
     b. Exibe mapa (grid 15x30 com @, espacos, inimigos, etc.)
     c. Opcoes:
        [1] Explorar: entra no menu de movimento (WASD)
        [2] Inventario: ver/ usar/ equipar/ descartar itens
        [3] Status: ver todas as stats detalhadas
        [4] Quests: ver progresso das missoes
        [5] Loja: comprar/vender itens
        [6] Salvar: gerar codigo de save
        [7] Sair: pergunta se quer salvar, depois encerra loop

   a. Move jogador (WASD) no grid
   b. Ao mover:
      - Se inimigo: combate por turnos
      - Se bau: loot aleatorio
      - Se loja: abre loja
      - Se saida: gera novo mapa
      - Se arvore: chance de ouro
      - Se caminho vazio: chance de evento aleatorio
   c. A cada movimento: reduz fome, conta acao, alterna dia/noite a cada 5

4. COMBATE
   Loop ate vitoria ou derrota:
     a. Turno jogador: atacar / habilidade / item / fugir
     b. Verifica se inimigo morreu
     c. Turno inimigo (IA)
     d. Verifica se jogador morreu
     e. Processa efeitos (buffs/debuffs)
     f. Reduz cooldowns

5. PROGRESSAO
   a. Acumular XP derrotando inimigos
   b. Check_lvl(): quando XP suficiente, sobe nivel
   c. A cada nivel: +2 todos atributos, recalcula HP/Mana, restaura ao max
   d. Niveis 1-5: desbloqueia nova habilidade
   e. Level maximo: 50 (praticamente inalcancavel)

6. MORTE
   a. Se Coracao de Fenix: revive com 20% HP
   b. Se Paladino com Ressurreicao: revive 100% HP
   c. Senao: perde 20% ouro, retorna com 50% HP/Mana

16.1 ARQUITETURA OBSERVADA
O codigo usa uma abordagem "estruturada global" tipica do Portugol Studio:

- Loop de jogo: menu_principal -> menu_exploracao -> eventos/combate

16.3 INTENCOES DO DESENVOLVEDOR (DO PROMPT ORIGINAL)
O prompt pedia:
- Registros para Jogador, Inimigo, Item, Skill, Quest -> NAO implementado
- Sistema de crafting -> NAO implementado
- Loot procedural com prefixo + tipo + elemento + raridade -> PARCIAL
- Sistema completo de buff/debuff com prioridades -> PARCIAL
- IA de inimigos avancada -> BASICA
- Sistema de troca com precos variaveis -> SIM
- Save/Load completo com parse -> INCOMPLETO
- Slots de equipamento (arma, armadura, capacete, bota, luva, anel, amuleto)

  -> PARCIAL (so mensagem)

16.4 DIFERENCAS ENTRE PROMPT E CODIGO
- Prompt: Tiro Rapido = 2 ataques de 60%. Codigo: 1 ataque de 120%.
- Prompt: Postura Defensiva reduz dano em 40%. Codigo: buff tipo 3

- Prompt: Forca da Natureza invoca raizes. Codigo: apenas dano.

19.1 GERACAO DE MAPA (PSEUDOCODIGO)

funcao gerar_mapa():
    para i = 0 ate tamanho_x:
        para j = 0 ate tamanho_y:
            matriz[i][j] = "Nada"

    startX = aleatorio(1, tamanho_x - 2)
    posX = startX
    posY = 0
    matriz[posX][posY] = "O"

    parar = falso
    enquanto nao parar:
        // encontrar "O"
        pos = encontrar_matriz("O")
        
        // verificar vizinhos validos
        vizinhos = []
        se pos.y-1 >= 0 E matriz[pos.x][pos.y-1] == "Nada":
            vizinhos.adicionar("cima")
        se pos.y+1 < tamanho_y E matriz[pos.x][pos.y+1] == "Nada":
            vizinhos.adicionar("baixo")
        se pos.x+1 < tamanho_x E matriz[pos.x+1][pos.y] == "Nada":
            vizinhos.adicionar("direita")
        se pos.x-1 >= 0 E matriz[pos.x-1][pos.y] == "Nada":
            vizinhos.adicionar("esquerda")
        
        se vizinhos.vazio():
            parar = verdadeiro
            senao:
                direcao = vizinhos[aleatorio(0, vizinhos.tamanho-1)]
                matriz[pos.x][pos.y] = "Caminho"
                mover pos na direcao
                matriz[pos.x][pos.y] = "O"

    // Colocar elementos especiais
    para cada celula "Caminho" na matriz:
        roll = aleatorio(1, 100)
        se roll <= 15: celula = "E"   // inimigo
        senao se roll <= 20: celula = "B"  // bau
        senao se roll <= 23: celula = "L"  // loja
        senao se roll <= 33: celula = "T"  // arvore

    // Colocar saida no ultimo caminho
    percorrer matriz de tras para frente:
        se celula == "Caminho":
            celula = "S"
            retorna

19.4 CALCULO DE DANO (PSEUDOCODIGO)

funcao aplicar_dano(forca_atk, precisao, critico, elem_atk,
                     defesa_def, resistencia_def, elem_def, mult, forcar_crit):
    
    // Precisao
    se aleatorio(1, 100) > precisao:
        escrever("Errou!")
        retorna 0
    
    // Dano base
    dano = forca_atk * (mult / 100.0)
    
    // Critico
    se forcar_crit OU aleatorio(1, 100) <= critico:
        dano *= 2.0
        critico_ativado = verdadeiro
    
    // Elemental
    mult_elem = verificar_fraqueza(elem_atk, elem_def)
    dano *= mult_elem
    
    // Defesa
    reducao = min(defesa_def * 0.35, 80)
    dano -= dano * (reducao / 100.0)
    
    // Resistencia (skills > 150% mult)
    se mult > 150:
        dano -= dano * (resistencia_def * 0.25 / 100.0)
    
    dano = max(dano, 1)
    dano_final = arredondar(dano)
    
    escrever("Dano: ", dano_final)
    se critico_ativado: escrever(" CRITICO!")
    se mult_elem > 1: escrever(" Super eficaz!")
    se mult_elem < 1: escrever(" Resistente!")
    
    retorna dano_final

funcao loja_consumiveis():
    para cada item na loja:
        se item.categoria == CONSUMIVEL OU ESPECIAL:
            preco = item.preco_base
            
            // Inflacao noturna
            se ciclo == "Noite" E item.categoria == CONSUMIVEL:
                preco *= 1.25
            se ciclo == "Noite" E item.eh_mercador_negro:
                preco *= 0.80
            
            // Desconto reputacao
            preco -= preco * (g_desconto / 100)
            
            exibir item.nome + " - " + preco + "g"
    
    ler escolha
    se escolha valida:
        verificar nivel >= item.nivel_requerido
        verificar se item noturno so aparece a noite
        verificar ouro >= preco
        
        se tudo ok:
            ouro -= preco
            reputacao += preco
            se reputacao >= 500:
                desconto += 5
                reputacao = 0
                se desconto > 20: desconto = 20
            adicionar_ao_inventario(item)

funcao check_lvl():
    enquanto xp >= xp_proximo E nivel < LEVEL_MAX:
        nivel++
        xp -= xp_proximo
        xp_proximo = recalcular_xp_proximo()
        
        forca += 2
        defesa += 2
        inteligencia += 2
        agilidade += 2
        vitalidade += 2
        
        hp_max = recalcular_hp_max()
        mana_max = recalcular_mana_max()
        hp_atual = hp_max
        mana_atual = mana_max
        
        exibir_tela_level_up()
        
        se nivel <= 5: // desbloqueou habilidade
            exibir("Nova habilidade!")
